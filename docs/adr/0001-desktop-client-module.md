# 将完整桌面端纳入 Clients 层

已接受并实施的客户端归属设计。完整桌面端归入 `clients/gui`，与 CLI、TUI 及未来的移动端处于同一 Clients 层，共用 Core 的公开能力；会话、历史和执行权威继续归 Core/Runtime。客户端同级不要求各端具有完全相同的功能。

迁移范围包含界面、Electron 宿主、Core 连接、原生能力与构建打包所需的依赖。仅迁移界面源码无法形成可独立运行的桌面应用；继续在外部仓库维护完整桌面端则无法实现统一的客户端源码归属。本次先迁移 GUI，移动端后续迁移。

目标 GUI 不引入旧 DSH GUI 功能与入口。旧仓库相关清理在新 GUI 验收通过后进行；这项决定不删除目标仓库现有的其他 DSH 适配能力。

目标仓库面向开源发布。只迁入审查后的文件快照，不合并来源仓库的 Git 历史，避免将已从当前文件移除的非公开内容带入公开历史。按运行、构建与验证需要选择可公开文件，保留必需的许可证及第三方来源说明。不直接搬运开发采集资料、Skills 或 AGENTS 文档；其中任何确有需要的内容均须单独审查公开适用性，不迁入凭据、私人信息或内部资料。签名、公证使用的证书、私钥、账号、私有配置及操作记录均不迁入；公开构建流程仅保留通用的外部配置接口，不包含实际签名或公证信息。

## 行为与验收边界

现代 GUI 的已有功能与交互是不退化基线，包括桌面侧手机配对能力；移动端源码迁移延后不代表删除桌面侧兼容能力。内部依赖须替换或作为明确阻塞处理，不能以静默删除功能替代迁移。现有运行时界面图标、供应商图标和应用图标沿用源仓库版本，迁移阶段不替换；相关采集档案仍不迁入。

GUI 遵循目标仓的共享 Core 服务生命周期：关闭窗口或退出 GUI 不终止 Core 任务，停止服务必须显式进行。重新打开 GUI 应恢复任务状态；本次不新增完全退出 GUI 后的桌面通知或手机控制能力，GUI 运行时保留已有手机配对功能。

本次先验证全新安装，保留已有安装及数据，不自动接管。旧数据导入、应用替换和自动更新衔接作为后续步骤处理。

验收要求目标仓可独立安装公开依赖、构建、启动，并生成可本地安装验证的桌面包；关键用户流程提供可重复的端到端证据。本次验收平台为 macOS Apple Silicon；保留已有跨平台代码，不推定 Windows、Linux 或 Intel Mac 已验证。签名、公证与公开发布不属于本次执行授权。具体运行与验证入口见 [GUI](../../clients/gui/README.md)。
