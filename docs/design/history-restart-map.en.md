# History Reading, Switching & Restart Recovery Feature Map

This map defines the user-facing product rules and verification bindings for Wave 1 Domain 2 (history reading, thread switching, and disconnect/restart recovery) without duplicating test commands or source paths. Machine selection and execution contracts remain owned by [journey manifest](../../clients/gui/scripts/journey-manifest.json); see [verification system design](verification-system.md) for the overall methodology.

> Rule of thumb: **Expected product rules must be written strictly from the user's perspective, with zero internal error codes, process names, or implementation jargon**; engineering clues belong only in the current-reality column.

| Rule ID & User Goal | Expected Product Rule (PM Intent) | Current Reality & Engineering Clues | Authoritative & Visible Outcomes | Verification Anchor & Coverage Gaps | PM Adjudication |
|---|---|---|---|---|---|
| **`FM-HIST-01`**<br>Refresh the page or reopen the app and revisit an existing thread<br>(Web / Desktop / Mobile) | After refresh or restart, the original project, message history, and latest completed reply remain intact without falling back to an empty page. | Covered by `web-journeys` (W3 reload) and `service-reopen-smoke`; `unknown-receipt-recovery` is not yet wired to `evidenceCheck`. | **Authoritative**: Persistent Core store retains the original Thread and settled Turns.<br>**Visible**: Reopening renders the same history and completed reply. | Linked to `unknown-receipt-recovery` (`service-reopen` / `web-journeys`).<br>Mobile and packaged app not run. | Pending PM sign-off |
| **`FM-HIST-02`**<br>Switch between threads or projects and switch back<br>(Web / Desktop / Mobile) | Returning to a thread never mixes in content from another thread, preserves unsent drafts, and keeps the reading position stable. | Covered on browser fixtures by `history-navigation-ui-smoke` and `conversation-reading-ui-smoke`. | **Authoritative**: Read requests stay bound to the active project/thread identity and ignore stale responses.<br>**Visible**: History, draft, and reading anchor remain intact on return. | Linked to `test:history-navigation-ui` / `test:conversation-reading`. | Pending PM sign-off |
| **`FM-HIST-03`**<br>Scroll upward in a long thread to load older history<br>(Web / Desktop) | Scrolling up smoothly loads earlier turns in order without duplicates or jarring scroll jumps. | `bounded-history-ui-smoke` checks on-demand paging with ≤2px anchor drift; `large-history-smoke` checks 140 operations and restart continuity. | **Authoritative**: Cursor pagination loads complete history without missing or duplicated pages.<br>**Visible**: Older turns prepend cleanly with ≤2px reading-position drift. | Linked to `test:history-recovery` / `test:conversation-reading`. | Pending PM sign-off |
| **`FM-HIST-04`**<br>Lose connection or response right after sending, then reconnect or refresh<br>(Web / Desktop / Mobile) | After recovery, the app only reconciles the original send and **never silently resends a duplicate message**; drafts settle to match reality. | Verified in `web-journeys` (W2b) and `connection-recovery` (`unknownNotReplayed`); not yet unified under `unknown-receipt-recovery` `evidenceCheck`. | **Authoritative**: Only the original receipt is queried; no duplicate Turn is created in Core.<br>**Visible**: Message and attachments appear once and draft state matches truth. | Locked in `connection-recovery` as `unknownNotReplayed`; unify under `unknown-receipt-recovery` next. | Pending PM sign-off |

## Anti-Drift Discipline

Whenever live behavior disagrees with this map, classify it explicitly as **doc drift** (intentional product change, update map after PM sign-off), **verification gap** (rule exists but lacks a bound `factId`/assertion), or **product regression** (code broke an agreed rule; keep a failing test first and fix code—never edit the map to mask a regression).
