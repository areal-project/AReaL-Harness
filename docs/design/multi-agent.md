# Agent 委派与准入

普通任务使用同一套 `agent_*` 模型工具和 `areal/agent/delegate` 客户端入口。协调 Agent 声明分析或修改意图、结果形式与依赖约束，Core 选择共享执行或 [Workgroup 隔离执行](workgroups.md)，以同一 `executionId` 投影状态、验证与交付。子任务仍使用生产 Engine 和独立历史，权限只能继承或收窄。旧 `areal/agent/spawn` 和显式 Workgroup RPC/CLI 保留兼容，不再构成普通模型的两套选择菜单。

## 执行方式选择

共享与隔离保留不同能力，不维护另一套模型循环。Core 在创建时依据结构化要求、现有授权、工作区和执行环境进行准入；选择结果及原因保存在诊断记录，用户无需选择后端。

| 任务条件 | 执行策略 |
|---|---|
| 只读分析、查找、审查 | 共享只读子任务，独立上下文 |
| 强耦合修改、需要当前环境、没有独立修改边界 | 共享工作区的独占写入子任务 |
| 已声明独立修改和精确写集合，工作区可快照且隔离运行可用 | 隔离执行，候选整合后交付 |
| 要求仅交付候选补丁或可信验收 | 必须满足相应隔离与验收条件；无法满足时返回明确错误 |

普通独立修改若不满足隔离条件，可在启动之前选择共享独占写入；已启动的执行不在失败后静默切换方式。共享写入互斥覆盖实际工具副作用，避免协调 Agent 与子任务同时改变被验证的代码。隔离计划的文件集合是职责边界，不是扩大宿主权限的授权。只读、工具拒绝、Profile、Runtime 与根预算约束始终有效。

创建隔离执行前，原生执行器会用独立空目录启动只读 Runtime 并确认关闭，以核验真实 native 沙箱前置条件；每个服务缓存已确认的可用或不可用结果。普通修改仅在探针明确确认初始化回滚且无遗留资源时改选共享执行。探针清理 UNKNOWN 会拒绝本次委派，不能退回共享；取消等待者也不会丢弃探针自身的清理。

结果分别投影执行状态、检查状态和交付状态。没有部署检查的自动隔离可生成候选，但必须标为未检查；模型总结和空检查不能获得可信验收通过标记。`changes` 在授权内交付到原工作区，`patch` 保留候选；Core 预检所有目标基线，记录应用过程，冲突、部分应用或未知结果不能伪装成已交付。检查与交付接口见 [Core API](../api/core.md#agent-tools)。

## 所有权与结算

模型派发的子任务可异步推进；父任务按完成顺序增量接收结果，正常结束前自动等待全部子任务并汇总。等待不持有模型/普通工具许可。RPC 手工派发保留父 Turn 结束取消子任务的语义。取消、超时与失败向后代传播，终态在资源关闭和持久化完成后发布。

旧研究 Agent 的创建、等待和取消也不占工作区读租约或工具执行槽，避免父任务等待与排队作者、子任务读取相互阻塞。其 pre/post hook 仍按每次实际执行取得工作区租约和工具许可，保留审批、权限与取消边界；同名外部工具不能获得协调工具的豁免。

`agent_report` 将 summary、evidence、remaining 写入历史，不结束任务。失败任务可交回最近报告，保留失败状态与 partial 标记；正常完成优先返回更新的最终回复。阶段报告不能替代独立验收。普通子执行绑定父 Turn；TaskRun 拥有的执行保留已有跨协调 Turn 生命周期。控制请求始终检查绑定所有者，结束后的子任务不能自行脱离所有者另开 Turn。

## 独立限额

| 配额 | 默认值与语义 |
|---|---|
| `max_threads` | 20000，含历史 Thread 元数据；归档仅释放热历史 |
| `max_active_turns` | 256，包含模型排队、工具等待和清理 |
| `model_concurrency` | 32，仅覆盖在途模型请求 |
| `max_children_per_turn` | 64，累计成功创建的直接子任务，不因子任务完成返还 |
| `max_agent_depth` | 8，根深度为 0；与扇出任一设 0 禁用委派 |

子 Thread 与首个 Turn 原子准入和持久化；失败不留空会话。容量不足立即拒绝，不占着父任务等待。清理或最终保存失败时保留活动占额，直到 Engine 结束并恢复；重启校验父子图但不自动恢复执行。

模型声明工具不保证会使用并行。修改任务应声明明确职责；统一入口对共享写入实行互斥，旧共享写委派仍需自行协调不重叠文件；宽度、真实模型请求重叠和任务收益分别测量。参数、分页和错误见 [Core API](../api/core.md#agent-tools)。

`agent_send_input` 是协作补充，不是紧急取消。Core 排空已发出的子任务模型请求以结算用量，再应用新输入；旧响应的工具不会执行。首包前等待沿用请求空闲期限，流式等待在每次活动后刷新空闲期限，并受原 Goal/worker 截止时间约束。显式取消仍可打断等待；缺失用量或超时保留 UNKNOWN，不伪造已结算。

正常接管使用 `agent_cancel` 的默认 graceful 模式，强制停止显式传 force；精确期限和回执见 [Core API](../api/core.md#子任务停止与计量收尾)。父作者比较源码变化、验证输出和快照 activity，并使用完整 executionId 与约定交接路径；旧委派接口继续使用 threadId。Core 先封闭后代准入，再传播取消；Turn 保留有界模型结算所有权，结算后继续既有资源清理与共享 Goal 门禁。资源释放和 usage 完整性分别报告，UNKNOWN 不因接管被清除。
