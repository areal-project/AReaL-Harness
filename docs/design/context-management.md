# 上下文管理

Core 负责完整请求预算、压缩与持久历史。[Core 契约](../api/core.md)定义公开投影，[配置指南](../guides/configuration.md)说明配置。显式窗口配置优先于已知模型默认值。未知模型 ID 由全局 131072 token 兜底，HTTP 请求输出仍默认 16384 token。

## 问题与目标

一个分配器对每次完整请求规划预算，保留最新真实用户请求与未完成工具操作；较早材料按需要压缩或回取。持久历史独立保存，不随模型投影裁剪。提高窗口不能替代保留策略。

## 配置收敛

| 配置 | 行为 |
|---|---|
| `model.context_window_tokens` | 设置用户工作预算；有服务报告时取两者较小值 |
| `model.max_output_tokens` | 常用配置；单次 HTTP 请求默认 16384，可按模型覆盖，必须为正数 |
| `context.mode` | 保留 auto / manual / disabled |
| `context.target_tokens`、`context.recent_tokens` | 目标与近期默认均为 0（自动）；显式正数保留为兼容边界偏好并报告来源 |
| `context.output_reserve_tokens` | 保留为高级预留下限；常规使用由输出上限自动预留 |
| 旧 token / byte 字段 | 继续解析并维持现有语义；停止在常用示例中推广，不能静默忽略显式值 |
| 用户原文与证据内部配额 | 删除两份独立的固定配额，消耗同一个完整请求预算 |
| 存储历史、请求字节与工具结果保护 | 保留独立职责；不能用 token 预算代替磁盘和传输保护 |

不新增“用户原文保留额度”设置。常用设置只需窗口、输出和压缩模式；供应商及模型参数的覆盖顺序保持兼容。摘要专用推理强度和输出参数继续作为高级设置，避免把已有支持变为无效配置。

## 已知模型窗口

服务报告窗口与用户工作预算分别保留。账号目录的 `context_window` 是当前报告窗口，不拿可选的 `max_context_window` 替代。工作窗口取报告值与显式用户预算的较小值；界面同时显示报告来源、报告容量和用户预算。账号未报告容量时使用全局兜底，不套用公开 API 的按名称默认值。自定义端点没有报告或用户预算时，才查完整模型 ID 默认表，未知 ID 使用全局兜底。

空闲会话的上下文查询投影下一次新请求的容量。新请求受理时，仅在供应商身份、端点、协议和凭据引用一致时更新报告容量及模型能力；已有历史、活动轮次和已受理队列保持冻结快照。不会为更新容量而切换账号或重绑定端点。独立 TOML 的用户预算仍使用 `model.context_window_tokens`，桌面参数使用 `contextWindowTokens`。 旧快照无法区分自动填充的窗口与同值的人工预算，因此保守保留已经保存的窗口参数作为预算，不因报告容量增加而放大。新快照将预算和报告分别保存。

以下默认值于 2026-10-20 核对官方文档。实际支持的精确 ID 以 `core/engine/src/model/context_windows.rs` 为准。

## 完整请求的统一规划

设模型窗口为 W，输出预留 R 取请求输出上限与显式预留下限的较大值，可用输入为 W − R。未知模型使用兜底窗口与默认 HTTP 输出上限时，得到 114688 token 的完整输入空间。规划与最终发送共用消息构造与计量路径，计入动态指令、工具 schema、媒体及协议封套；沿用供应商完整输入用量的校准，媒体代理估算仍需保守余量。压缩触发同时受最终预检的原始保守估算约束：较小的历史用量不能跳过硬窗口门禁，较大的真实用量仍可提前触发压缩。

按以下顺序分配，并保持原始角色与时间顺序：

1. 固定指令、当前 Turn 的最新真实用户请求及其附件、未完成工具调用和必须配对的结果属于必需部分；自动 Goal 续轮不是新的真实用户要求。
2. 从新到旧纳入可容纳的完整工具轮次与用户修订，优先维持最近执行连续性；首问不再享有永久优先级。
3. 更早的内容用一个有界 checkpoint 表示，包含摘要、可追溯原文引用与执行回执。用户原文、证据和摘要共享剩余额度；已完成工具结果优先引用，按需回取。
4. 最新请求即使超过旧软配额也不裁剪。必需部分本身无法容纳时明确返回 `LLM_CONTEXT_WINDOW_EXCEEDED`，不改为回答旧任务。

若选定边界的固定指令、近期完整轮次、最新请求与有效摘要已经达到软 token 目标，较早的纯文本用户修订仍可在硬窗口和既有字节额度内继续分配，避免软目标把修订额度冻结为零。旧附件和可选执行证据不使用这项余量；原文继续按时间排序，硬窗口预检与超额时的最近优先选择不变。摘要提示不能假设全部旧原文都会单独重放，必须保留未撤销的约束和用户指定的精确值。

自动模式先沿用 60% 可用输入窗口的压缩目标作为内部策略，形成压缩余量；目标无法达到而硬窗口仍可满足时记录原因，避免无进展的重复压缩。模型切换后重新规划；manual/disabled 维持显式压缩和超限失败边界。

上下文窗口限制单次请求，Goal token 预算限制整个目标的累计消费，两者独立。压缩减少后续请求携带的历史，不撤销此前已计量的输入或输出；摘要请求本身也计入 Goal 预算。缓存命中输入属于输入 token 的子集，计入累计 token 用量，不能按供应商缓存折扣从 token 预算中扣除。60% 是压缩后的目标，不是到达 60% 就触发压缩的阈值。

## 压缩提交与失败

求解先组装完整请求但不持久化本次动态提示，用完整请求与历史投影的估算差为压缩规划预留开销。未发送提示不会成为尾项，已完成工具轮次仍可整体压缩。压缩或 steer 改变历史后重新构建；提交锁内核验原历史边界、通过硬预检后才追加提示。恢复提示在接受前不消费，重建不占额外求解轮数；摘要调用仍遵守原计量、取消和重试边界。已发送请求的提示及推理上下文保持原样。

压缩分为构造候选、校验、原子提交。候选必须覆盖合法的已结算前缀、保留最新要求、维持工具配对、实现净缩减，并通过完整求解请求预检后才能替换旧 checkpoint。摘要只作为历史证据，不取得高于用户新指令的优先级。

HTTP 400 等摘要请求失败时保留旧 checkpoint 和原文，不自动提交丢失语义的降级摘要。只有已收到但格式不合格的摘要才使用现有有限验证修复；不对完全相同的永久无效 HTTP 请求进行验证重试。网络暂态失败继续复用现有取消、watchdog 与 Goal 账本约束。

旧投影仍可容纳当前请求时可以继续；否则停止并报告摘要失败和窗口不足。提交前检查历史边界与新 steer 是否变化，变化时重新规划，不能覆盖新请求。归档提交仍由 Store 保证先写不可变分段，再写快照引用；不重放执行副作用。

## 模块职责

| 模块 | 职责 |
|---|---|
| `core/engine/src/context.rs`、`history.rs` | 共享分配器、按原文时间顺序投影、原文回取、完整轮次边界与候选校验 |
| `core/engine/src/generation.rs` | 构造实际动态提示、共享计量、预检，在压缩或 steer 后重建请求 |
| `core/engine/src/desktop/context.rs` | 已记录指令/当前工具预算诊断与手动压缩 |
| `core/config`、`core/server` | 默认值、显式参数优先级与旧配置兼容 |
| `core/protocol`、桌面 schema | 公开失败通知与预算投影；Clients 消费 Core 诊断 |

实现遵循 Clients → Core → Runtime；GUI 只显示 Core 的预算与结果，不另行裁剪权威历史。读取旧 checkpoint 保持兼容，下一次成功压缩再生成新投影，不批量改写用户会话。

## 验收

使用本地模型 fixture 验证：多图修订、最新输入单独超限、首问被新需求替代、反复压缩与重启、旧 checkpoint、模型换成小窗口、显式输出覆盖、Goal 输出额度收窄、完整工具配对、摘要 HTTP 400/空内容/过长、取消与压缩期间 steer。分别断言实际 HTTP 请求内容、checkpoint 提交结果和磁盘原文，避免只验证 GUI 展示。供应商真实 tokenizer 与服务兼容性需另行集成验证。
