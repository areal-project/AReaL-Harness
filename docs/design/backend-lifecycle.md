# 后台生命周期收敛

本文定义后台收敛的目标与验收边界；具体能力是否已经可用，以实现与行为验证为准。

## 所有权

Host 是客户端唯一入口，持有项目登记、唤醒与跨项目配置。Core 保留执行、Store 与业务回执权威，项目服务证明子进程退出与资源释放。客户端只保存投影与未发送输入。升级协调器负责整套后台的短暂停机交接，不允许业务页面各自替换后台。

## 四项交付

1. 升级交接持久保存原操作身份，确认旧后台释放后启动目标构建，健康检查完成后清除交接记录。应用构建摘要在打包时生成；源码开发继续核对实际输入。UNKNOWN 只核查原请求。
2. 导航、停止项目历史与脱敏模型目录不等待执行环境初始化。运行会话仍从 Core 读取；持久化阅读不声明实时执行状态。发起写入前关闭原持久化读取租约，再按既有授权唤醒目标项目。
3. 空闲连续十五分钟后允许项目休眠。Core 原子确认空闲，Host 使用原项目代际及停止回执结算；休眠不改变用户的调度启停意图。未来定时任务只保留 Host，按 published 的下一次触发时间提前唤醒 Core；到期准入与去重仍由 Core 完成。退出需求登记后，无其他客户端或在途写入时立即回收空闲项目。其他客户端、桌面资源与在途操作不得被 GUI 退出误停。没有后台需求时允许 Host 退出；明确停止与自动休眠是不同意图。
4. 按方法、消费者、持久职责逐项迁移工作台到现有 Host/Core owner，同一职责的调用方切换后删除旧实现。原生能力留在 Main。剩余领域仍被使用时不能宣称工作台已退役。

## 验收

升级覆盖中断恢复、响应丢失、后继构建变化及锁释放；读取覆盖后台未就绪与停止项目；休眠覆盖忙碌、未知、定时任务、代际变化及再次唤醒。业务路径同时核对权威回执与客户端结果。所有进程测试使用隔离目录，不接管真实安装数据。
