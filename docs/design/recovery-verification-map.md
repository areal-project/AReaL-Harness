# 恢复样板功能地图

本表描述验收义务，不代表所有入口已经通过。命令与证据协议见[测试指南](../development/testing.md)。计划归属继续使用 [journey manifest](../../clients/gui/scripts/journey-manifest.json)，不另建选检器。

2026-11-22 的真实探索、历史反例和缩减结果见[样板验收记录](../benchmarks/reports/connection-recovery-exploration.md)，包括首跑阻塞、冻结源码身份及未覆盖范围。

| 用户目标与入口 | 权威结果 | 用户可见结果 | 可执行证据 | 范围与缺口 |
|---|---|---|---|---|
| 网页首次连接与选择项目 | 当前连接收到原成功 shell 基线 | 等待只显示加载，不闪失败 | 固定旅程 loading；探索每轮同样先延迟真实基线 | 尚不代表正式包启动 |
| 编辑后断线并自动恢复 | 新 connectionId 属于原 Host，恢复读取落在当前 owner | 无手动重连，项目、Thread、模型及草稿保留 | `edit → reconnect`；逐步状态、截图、请求/响应事件 | 同 Host socket 换代，不是 Host 进程换代 |
| 空闲后继续使用 | 原 `ifIdle` 回执完成且未设置显式停止；之后按需恢复 | 无失败提示，最终能继续提交 | `idle-reconnect → submit`；停止回执、新连接、Core Turn 与 UI | 直接触发生产回收路径，不等于真实十五分钟计时 |
| 恢复后按 Enter 发送 | 原请求受理，唯一 Turn 完成 | 对应完成结果可见，原草稿结算 | `submit`；发送请求、Core 身份、可见完成卡片 | 本地确定性模型，不代表真实供应商质量 |
| 发送响应丢失后继续 | 原 accepted 响应被丢弃；重连查原 commandId，未再 send | 仍选中原 Thread，原草稿结算，可继续编辑 | `unknown-submit`；故障命中、原持久回执、后续事件后无重复 Turn | 前置已有 Thread；首次创建响应 UNKNOWN 由其他旅程覆盖 |
| 明确停止后断线 | 调度停止意图保留，无新执行代际 | 重连不偷偷恢复执行 | 末尾 `stop-reconnect`；生产控制请求、原回执及三秒观察窗 | 控制请求用于状态注入，不证明原生菜单或系统弹窗点击；有限观察不证明永远不会重启 |

## 探索与回放

每轮从隔离的空项目开始。动作由验证过的有界计划驱动，真实页面与 Host/Core 提供观察。固定操作顺序之外还记录实际请求、响应和目录事件顺序。所有输出只包含合成内容；凭据和配对票据不进入轨迹。

成功要求每个计划动作执行、每步证据导入成功、最终提交有权威与可见结果、清理完成。失败必须保留首个断言、当前动作、原计划、已执行前缀及未执行部分。缩减用全新 fixture 重跑合法候选，不能把另一个错误或启动失败算成更短复现。

## 扩展边界

恢复样板通过后，先复用已经抽出的计划、证据与缩减机制覆盖普通提交、UNKNOWN 和显式停止的组合。历史重启、模型配置、Relay/手机、权限与调度分别需要自己的功能前置和权威结果，不能从这张表推导通过。新增公共操作应由第二个实际使用者驱动，避免复制整份 runner。

人工收益仍须固定连续变更样本并计量实际判断时间；动作数、绿色案例数和报告字段数不是效率收益。
