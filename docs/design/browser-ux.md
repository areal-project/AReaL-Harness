# Shared Browser 交互规格

当前源码交互与后续设计约束。以[主规格](browser.md)和[协议](../api/browser.md)为边界，复用现有 Button、反馈、Composer、ApprovalRequest、任务资源与差异入口。下述自然浏览流程尚待统一原生与安装包验收；设计参数和后续验收要求不等于已验证能力。

## 1. 信息结构

浏览器位于现有右侧工作区，可切换分栏/扩展视图，保留聊天输入与当前 Thread 身份。常规顶栏保留返回、前进、刷新/停止、地址、Page tabs 和独立批注；诊断、视口与控制详情收进“更多”。无需浏览器工具开关或人工/Agent 模式按钮。后台 Thread 的 Browser 活动不得抢焦点、展开用户正在阅读的另一面板或切换当前聊天。

操作活动与结果通过聊天及可展开的详情呈现，显示目标、进度和错误，避免将原始 CDP 消息或内部状态放入常规浏览流程。完成时的验证卡关联截图、检查与代码变更；历史卡不是可交互直播。

## 2. 控制状态

| 状态 | 用户看到 | 可用操作 | 退出条件 |
|---|---|---|---|
| human | 页面可直接交互；详情说明 Agent 观察暂停 | 正常浏览、独立批注 | 下一条明确用户消息/继续，经 Core 审批恢复 |
| agent | 聊天与详情呈现操作进度 | 直接在页面输入即可介入 | 首个人工输入先建立 Main 栅栏 |
| transferring | “正在交接”，同时说明在途结果可能未知 | 本机接管始终可用；不允许新 Agent 输入 | 栅栏已更新并结算可知部分 |
| waiting approval | 聊天中的现有审批卡，实际站点/动作摘要 | 允许/拒绝、接管 | Core 决定到达，不能凭按钮点击本地放行 |
| unavailable | 页面/宿主失效原因与恢复影响 | 恢复、核对历史；不显示伪直播 | 明确恢复并重新授权 |
| unknown | “操作结果未确认，不会自动重试” | 打开页面核对、查看回执、检查确认 | 用户核对并另发后续请求；旧记录不改 |

真实页面输入首先立即建立 Main 控制栅栏，撤销旧 Agent 代次并暂停动作和读取；等待已派发原生合成输入结算、释放按键后，将首个人工事件送入同一页面。无需先点接管按钮。无法收敛时保留“正在交接”，提供停止/关闭页面，不能让人和在途输入争写；这个过程不等待 Core 批准。已派发不确定结果保留 UNKNOWN，不自动重试。

“停止页面加载”“接管浏览器”“停止当前 Turn”“停止后台服务”是四种不同操作，标签和快捷键不可混同。浏览器接管不强制中止正在运行的无关开发服务器。

## 3. 核心场景

### A. 同页让 Agent 检查

用户已有输入未提交的页面 → 在聊天中明确请求检查或执行普通搜索 → 新聊天发现固定工具包，旧聊天在空闲明确发送时受控追加固定包 → 首次经 Core 批准的 `describe` 绑定同一 Page（无页才延迟创建空白页）→ 后续读取和动作按页面及代次审批 → 回复附证据。无需工具开关或页面认领按钮。E2E 须比较原生 WebContents 身份和 sentinel，不能仅比较 URL；不得通过 `thread/resume` 抢宿主或改写历史。

### B. 人工登录后继续

Agent 遇到登录/权限/高影响提交 → 页面保持打开 → 用户直接输入，Main 先 fence 并收敛旧输入 → Agent 自动读与诊断暂停 → 用户手工操作 → 下一条明确聊天指令或明确继续，经 Core 审批开启新代次 → 新观察后继续。没有跨重启登录承诺；窗口遮挡、切换或定时器不是恢复授权，也不自动上传人工期间内容。

会话已有未核对的工具 UNKNOWN 时，Composer 就近显示恢复提示；发送按钮先打开核对流程，不提交注定被拒绝的新消息。浏览器核对要求检查当前页面与操作结果，可记录登录后的可见状态；技术参数与原始错误默认折叠。取消、断线或核对失败保留草稿，只有 Core 保存核对事实后才能继续显式发送。历史 UNKNOWN 保留，不改写为成功，也不重放原操作。主会话以可操作的待核对状态呈现此停因，原始诊断仍可展开查看。

### C. 区域批注

批注与发送上下文不需要 Agent 工具启用或页面认领。用户进入批注 → 暂停 Agent 并取得 human 控制 → 生成带Page/视口来源的捕获 → 暂藏native页面，显示捕获（标“截图反馈，页面可能继续变化”） → 拖选区域/输入评论 → 草稿卡附缩略图、URL、时间 → 用户明确发送到原Thread。取消恢复native页面，不改变导航。原Thread切换后草稿不漂移，发送前提示目标。

当前源码路径：用户触发的 `captureRegion` 预览命令等待原生输入收敛，只截取可见且由人工控制的 Page。冻结编辑器打开期间（包括跨聊天切换）固定同一原生 Page；取消释放固定并恢复原 Page，不发生导航。区域选择将渲染图片坐标映射到截图位图像素。“加入聊天草稿”把评论、Page/文档/视口/位图来源、裁剪坐标和裁剪 PNG 追加到原 Thread 的 Composer 草稿；用户从 Composer 明确发送。只有选中裁图会在用户明确从 Composer 发送时通过现有 Thread 限定的 Core Blob/MediaRef 路径上传；完整截图保留本机。消息受理后 Core 历史才拥有正式批注。发送进行中或结果待核对时先阻止加入另一条标注。冻结编辑器跨聊天切换保存在内存；Composer 文本沿用本地草稿存储，图片附件沿用现有内存附件生命周期。

区域拖选使用冻结截图；元素点选使用当前可见原生页面的 CDP Overlay 检查模式。两条路径都通过同一受保护截图和原 Thread 草稿交付；原生行为仍待 B-29/B-30 验收。

### D. 元素批注

当前源码路径：用户在 human 控制的可见原生 Page 上点击“选择元素并标注”，Controller 独占该页的 CDP DOM/Overlay 检查模式，接收原生命中节点后关闭叠层，再执行区域批注已有的隐私保护截图。Controller 从同一 Page 读取实际 AX role/name、节点边界、Frame/文档与控制身份，裁出该元素的冻结图；页面和聊天换代、取消或超时会使迟到结果失效。返回的 `human:` Ref 只记录选择时证据，不进入 Agent 可执行 Ref 缓存；Agent 必须重新 `observe`。发送前复查同一节点的身份、语义、位置和视口，变化时保留旧图及文字并标 `stale`。用户补充意见后只把裁图和来源文字加入原 Thread 的 Composer 草稿，明确发送才走现有 Core Blob/MediaRef 上传与消息受理。网页无产品 bridge，原始 CDP 不交给模型；未获得项目实际带来源的映射时，React 源码位置显示未知。

无语义节点、Canvas 内部目标或不可核查的 iframe/Shadow 内容给出原因并转到区域反馈，不猜选择器。既有截图隐私保护若无法读取跨源 Frame，会拒绝图片；此时不得声称已提供区域裁图。B-29/B-30 的真实原生选择、过期与降级验收仍待 M2。

### E. 改代码并验证

Runtime启动或复用当前项目的服务 → 把真实已知端口交给Browser → 查看现状 → 用户批注 → Agent读代码并修改 → 等待已观察的热更新/页面条件 → 新观察/截图 → 检查表单行为及目标视觉 → 结果卡关联工具call、变更和证据。行为成功、视觉判断、人工认可分别显示；不能用“编译通过”替代视觉验收。

### F. 临时样式试改

仅human模式，支持有限属性（文本、颜色、字体、间距、尺寸）及撤销/重做；始终显示“页面试改，未写入代码”。记录原值和文档身份，只恢复由本次试改创建的覆盖；导航/HMR替换元素后停止回放并提示失效，不覆盖应用的新状态。用户可发送意图与前后证据，Agent再修改源码。刷新会清除临时覆盖；最终验证需在覆盖清除后进行，防止试改掩盖未改源码。

当前源码路径从可见原生页的“选择元素并试改”开始，沿用人工 Overlay 选择和隐私保护的选择前截图。试改表单保留原聊天归属，提供受限属性值、撤销/重做、Esc 取消和 Ctrl/Cmd+Enter 加入草稿；中文输入法组合期间不触发快捷键。前后证据仅裁切重新核查的同一元素；原图停留本地。加入草稿前清除试改，验证卡在试改生效时提示当前外观不可用于源码验收。页面更换或目标已被应用改写时，要求刷新来清除不确定的残留效果。Composer 发送失败沿用原草稿，不自动重发。


键盘激活“选择元素并试改”会打开本地冻结截图坐标选择器：输入横/纵截图像素坐标，方向键微调，Enter 确认，Escape 取消。Main 沿用截图身份、文档与视口校验及元素隐私限制；鼠标仍使用原生 Overlay。当前前台人工页面内按 F6 返回应用焦点。选择后聚焦试改属性，取消后聚焦发起按钮；加入原聊天草稿后聚焦 Composer，仍须显式发送。此路径不代表输入法或辅助技术的人工验收。

## 4. Native View 特有约束

React z-index不能被当作盖住WebContentsView的方案。可信原生overlay或独立本地视图需要处理resize/focus/IME、窗口遮挡和屏幕DPR；网页不能包含相同权限的preload。真实输入介入时由 Main 先撤销 Agent 准入并收敛旧输入，再保留首个人工事件；不能依靠 React 遮罩把接管按钮变成浏览前提。截图采集针对网页内容，默认不包含Agent光标、操作标签或工具栏。

在渲染窗口隐藏/最小化、页面后台和视口为0的情况下，不伪造截图或用旧图作为新证据；能力不足时提示需要可见页面。首期无需为此建设远程视频编码器。

DevTools由用户显式打开。打开前暂停Browser自动化，detach事件置不可用；关闭后重新attach、提升相应代次并重新观察，旧 preparedAction 无效。若某版本允许多调试会话也不能依赖这种行为绕过所有权。

## 5. 响应式、坐标与输入

控制页面的CSS视口与GUI显示缩放分开保存。固定视口初值可采用1280×720；调节范围320–3840×320–2160是可配置的初始策略，不是依赖浏览器默认。截图同时记录bitmap和CSS尺寸。缩放后必须测试中心、边缘、滚动后位置、iframe与Canvas输入；1×、2×屏幕和不同页面zoom覆盖。

真实键盘输入可直接触发人工介入，Main 栅栏和输入收敛先于首个事件送入网页，无需人工切换模式。中文输入法确认Enter不发送评论/聊天；接管时清理合成按键但不干扰用户正在合成的文本。Tab键导航可到达授权、URL、tabs、更多、批注发送/取消；焦点恢复到发起入口。控件带文本标签，控制状态改变用可访问通知，不依赖颜色。

## 6. 文件和权限

弹窗先归因opener、Thread和临时上下文，再决定显示/阻止；不创建未归属窗口。普通跨站登录跳转沿用 Chromium 网络行为并保持控制端点保护，不增加逐 Origin 提示；Agent 读取与动作仍单独审批。原生相机/麦克风/定位等首期默认拒绝并交给用户，不自动接受浏览器权限提示。

下载展示来源、名称、大小（未知时标未知）和状态；用户确认目标后保存，不执行文件。上传先交给用户的可信选择器，取消是正常可恢复结果；首期不让Agent指定任意文件路径。文件选择完成后，接管期间内容不自动被Agent读取。

当前源码路径：human 控制的当前可见页有“允许下一次下载”，30 秒内仅允许一次网页触发；Electron 原生保存对话框让用户选择目标，取消不产生保存文件。下载状态显示 Page 来源、发起 Origin（未知则明确标未知）、名称、大小或未知及完成/取消/中断，并允许取消进行中的项目。文件不自动打开；已发出的网络请求不因取消而自动重试。上传直接在 human 页的网页文件控件中使用系统选择器；取消后留在 human 页。下一条明确用户消息或继续经 Core 批准后，Agent 只能重新观察网页可见结果，不取得所选宿主路径或文件字节。B-39/B-40 的原生流程仍待 M2 验收。

## 7. 验收材料

每个发布候选应有同页交互、接管/交还、区域与元素批注、临时样式清除后的验证、错误与不可用状态的真实截图或短录屏。验证状态显示“未验证/通过/失败/结果未知”，不使用单一success绿标掩盖不同含义。详见[测试矩阵](../development/browser-testing.md)。
