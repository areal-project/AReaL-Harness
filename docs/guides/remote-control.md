# Remote Control：配置与部署

本文说明已实现的 Direct 本地配置与 Relay Host/PWA 接入；可选 Funnel 已有本地配置实现，公网能力未认证。真实手机、Tailscale 网络和组织代理的验收独立于本地源码与协议夹具。

## 本机内网连接与 Relay Service

在桌面「设置 → 手机连接」开启本机 Relay。应用自动选择电脑的私有网络地址和可用端口，显示手机 App 可扫描的配对二维码。手机与电脑不必在同一 Wi-Fi 或网段。公司 VPN 只要允许手机访问二维码中的 IP 和端口，也可使用此入口。电脑防火墙、VPN ACL 和访客网络隔离仍会影响可达性。

本机二维码使用私有 IP 的 HTTP 地址并标记 `local=1`。原生手机 App 通过受限的本机网络 WebSocket 连接；Host pin、Noise 加密、一次性邀请、桌面指纹核对和项目授权仍然生效。HTTP 页面不作为可信客户端加载，普通手机浏览器不能替代该原生路径。本机 Host 凭据只通过 loopback 连接交给 Relay，内网接口不提供登记码消费。

本机 Relay 运行不代表公网入口已建立。家庭路由器或运营商 NAT 后的电脑不能仅靠启动 Relay 就让蜂窝网络访问。应用不内置公共连接服务，也不预设官方地址。需要跨网时，可使用已可达的自建 Relay，或在外部服务配置中填写 HTTPS 地址与管理员一次性登记码。已保存的服务可切换，服务切换不删除桌面的设备授权；手机需使用对应的新连接链接。

「部署到 Linux 服务器」使用系统 SSH 配置及 ssh-agent，要求已信任服务器主机密钥、免交互 SSH 和 root 或免密 sudo。填写 `user@host`、SSH 端口和服务器 HTTPS 地址后发起部署。域名或公网 IP、80 和 443 端口必须从外网可达。部署器不自动修改现有防火墙或代理。Node 运行时按版本和 SHA-256 校验，Relay 由 systemd 运行，ACME 自动申请和续期证书。升级保留数据、证书和登记，移除默认保留数据；明确勾选删除数据才清除。

SSH 中断后的操作状态可能未知。先检查服务器状态，再决定是否重试。应用不会把连接断开当作未部署或已卸载。公共 CA、真实 Linux 服务器、真机扫码和实际 VPN 的通过情况以本次对应的验收证据为准。

## 当前可用范围

Direct 提供默认关闭的独立本机入口和本地配对确认。按 [GUI 指南](../../clients/gui/README.md)安装并构建，在桌面「设置 → 手机连接」启用本机入口，按「选择连接方式 → 打开配对链接 → 确认设备」完成连接：点击「生成配对链接」，复制配对链接到这台电脑的浏览器（也可在 Remote 页面粘贴）。链接两分钟内有效；页面先核对 Host，再申请配对。回到桌面核对完整设备指纹，勾选已有项目并选择「仅查看」（Observer）或「可操作」（Operator），确认保存后浏览器才能读取 Host/项目列表及工作、待处理摘要。所选在线项目在页面可见时每 5 秒刷新，部分加载数量明确标注；点击「打开会话」查看实时详情，「更早历史」逐页读取更早内容；每次只保留有界窗口。大正文显示预览与桌面查看提示，上游不可取的历史明确标注。关闭详情不停止工作；「刷新会话」重新取得当前状态和归属。断线清除旧正文，使用「连接 Host」重连后重新读取原会话；Core 重启后可用「刷新会话」取新基线。可用动作取决于设备授权和下文链接的已实现 API 范围。

「已授权设备 → 管理权限」可修改项目/预设或撤销；保存成功会立即断开该设备的旧连接，重新连接使用新范围。当前能力与提交限制见[API 已实现范围](../api/remote-control.md)。浏览器默认“仅本次使用”；在配对前选择“记住此设备”，成功后同 origin 刷新可恢复身份和 Host pin。浏览器存储不是系统钥匙串，共享设备不应记住。旧设备保留项目选择但需要复核；不会恢复旧写协议。安全存储不可用则拒绝启用。loopback 链接不能在另一台手机上访问。展开「手机访问与网络设置」后，Serve 向导可配置持久 HTTPS 转发；组织 HTTPS 模式只保存应用来源。手机真机与实际网络部署仍需独立验证。

验证命令与证据边界见[测试计划](../development/remote-control-testing.md)。本地 Serve/组织来源配置不等于真机可达性；Relay 本机严格 TLS 测试也不等于公网部署验收；Funnel 公网能力未认证。不得把 Core 或桌面管理端口作为替代入口。

连接前，网页说明如何打开桌面配对链接；申请后显示「请回到电脑确认」和完整设备指纹。连接后显示项目、工作列表和会话，连接设置折叠收起。会话与操作详情仍可展开核对原身份与回执；「已连接」和「已受理」均不表示执行完成。

### 记住设备、草稿与离线页面

“恢复本标签草稿”需要单独勾选，默认关闭；开启后当前标签刷新可恢复文本，重连不会发送。记住设备的未确认操作先保存原命令定位信息，刷新后显示“待核对”并只读查询原结果，不自动重发。unknown、pending 或 notFound 都不能当作未执行，仍可在桌面核对。

“清除此浏览器设备”停止连接并删除该站点的身份、Host pin、待核对信息和本标签草稿；看到失败提示时请用浏览器清除此站点数据。其他打开页面会停止旧身份连接。Host 端授权仍须在桌面撤销。换 Host 或换 origin 需重新配对，不自动迁移私钥。

短暂断线会自动退避重连，隐藏和离线时暂停；恢复前台会重建在线基线，不恢复旧订阅游标。页面可缓存静态离线壳，离线时不显示为已连接。新版本提示后，完成操作并关闭本站所有页面再打开；更新不会中途刷新当前提交。GUI 退出不停止已有后台 Host/Core；明确停止后台服务后入口不可用，页面不能启动或修复 Core。Direct 保存独立 loopback 端口，重启绑定同一端口并核对映射后才发布 HTTPS 来源；端口冲突时不另选端口接管映射。稳定端口不等于手机安装或后台运行验收。

### 查看原轮次结果

具有 review 授权的设备可在会话内点击「查看原轮次结果与变更」。页面固定原 Turn；长结果需要继续读取，失败或中断状态与部分文本一起保留。Task Run 状态单独查看，不能由 Turn 完成推断。历史 diff 只包含可验证的 Runtime 文本写入；缺少版本、Shell/重命名/删除/二进制等情况会提示不可用，不使用此刻工作区替代。

原 Turn/Item 的受支持图片需要显式点击才读取。单张不超过 16 MiB，尺寸和解码像素受限，动画及其他媒体请在桌面查看。图片读取可能较慢：当前原生接口每个远程块都会完整读取原 blob。关闭审查或会话、切换图片、断线或授权/服务变化会清除内容和临时图片。审查不改文件、不执行内容，也不表示批准工具操作。

## G1. 选择路线

| 项目 | Direct：无自建 AReaL 后端 | Relay：自建/组织托管后端 |
|---|---|---|
| 开发者建设 | Host 低权限入口、PWA、网络向导、配对与协议 | 相同公共组件，加 Relay 登记/转发/运维包 |
| 网络设施 | 现有 VPN/HTTPS；Serve 推荐，Funnel 可选 | 一个 HTTPS 域名、可接收 WSS 的服务器 |
| Host 入站端口 | 仅本地监听，由已有网络设施转入 | 不需要开放 Host 入站，出站 443 |
| 手机前置条件 | Serve 需要手机在 tailnet；Funnel 可用普通公网浏览器 | 普通公网浏览器/PWA，无需 VPN |
| 谁运维云端 | 不运维 AReaL 云端；依赖网络供应商/现有组织设施 | 个人或组织运维 Relay、TLS、静态客户端 |
| 配对体验 | 配好网络一次，然后扫码+桌面确认 | 管理员部署一次，桌面导入配置，然后扫码+桌面确认 |
| 产品厂商账号 | 不需要 | 不需要；P0 无统一自然人账号平台 |
| 离线 Host | 无法执行/读取新状态 | 同样无法；Relay 不代执行 |

Direct 与 Relay 复用同一授权和业务协议。公开发行的默认推荐路径可为组织预设 Relay；无服务器使用者始终可以选 Direct。启用任一路线不应产生另一条未经确认的公开入口。

### 路线与验收范围

下表区分源码能力、相应本地验证层和仍需独立验收的部署条件，不是一张已认证平台清单。Direct 与 Relay 使用同一 Native/Core 业务协议和验收断言；每次结果必须绑定实际源码、二进制及所选传输，不能用另一条路线或历史运行替代。

| 路线 | 已实现能力与本地验证层 | 独立部署门槛 |
|---|---|---|
| Direct loopback | 独立监听器、加密配对和生产 PWA；Native/Core 与浏览器业务分别验证 | 只供本机访问，不证明手机可达或安装包可用 |
| Direct Serve / 组织 HTTPS | 同一 Direct 协议；CLI 夹具验证 Serve 配置生命周期，组织模式校验应用来源 | 实际 tailnet/组织策略、可信 TLS、手机配对与撤销后的可达性 |
| Relay | 共用 Host acceptor、授权与 PWA；本机 Node 严格 TLS/容器检查与双传输 Native 业务验证分层记录 | 生产浏览器严格 TLS、公共 443、手机、运维容量及组织部署 |
| 可选 Funnel | 显式双重确认的公网范围切换；本地 CLI/配置夹具 | 公网能力未认证，需实际策略、TLS、手机与撤销验证；不影响其他路线独立验收 |

本地 Native、真实 Electron、系统安全存储、签名安装包和真机证据互不替代。Relay 浏览器 TLS 夹具未提供时，相关浏览器用例保持 UNRUN；Native 子检查成功不能升级为整个入口或发布矩阵通过。具体命令、次数与判定见[测试与发布门槛](../development/remote-control-testing.md)。

## G2. Direct 的实现与用户流程

Host 使用独立的 `127.0.0.1` 监听器提供同源 PWA 和 `/remote/socket`。转发目标由可信后台从实际存活的服务器取得，界面不能填写目标端口、Core 地址、桌面管理地址或可执行文件。后台继续使用同一份系统安全存储加密的 `remote.json`，不修改 Core 配置。

### Serve：tailnet 私人入口

在「设置 → 手机连接」启用本机入口，再点击「检测网络工具」。Host 需要可用的 Tailscale CLI、受支持的稳定版本（当前检查为至少 1.52.0）、已登录状态及已启用的 HTTPS 能力。手机必须加入有访问权限的同一 tailnet。本地检测不证明组织 ACL、手机成员资格或手机实际可达性。

选择空闲的 HTTPS 端口，点击「生成 Serve 方案」。核对显示的 HTTPS 来源与持久转发范围，勾选明确确认后点击「确认并应用 Serve」。后台先保存 pending 记录，再通过有超时和输出上限的参数数组调用 CLI；没有 shell 拼接、自动安装、配置重置或 Funnel 回退。已有映射或未知配置拒绝覆盖。确认精确映射且保存完成后，连接链接与新配对二维码才使用 HTTPS 来源。

映射记录和固定 Remote 端口均由后台保存。修改来源会取消邀请并关闭现有远程连接；新来源需要重新配对，不迁移浏览器私钥。「核对并恢复」只验证已有记录，不重复 apply；不存在或已更改的映射需要先移除旧记录，再创建新方案。

「关闭 Remote 并移除映射」先持久保存关闭状态并停止监听器，再等待撤销精确匹配的本应用映射。撤销失败保留待恢复记录和诊断，入口仍关闭；外部更改的配置不会被删除。「移除网络配置」可重试撤销。停止后台进程只同步关闭入口并保留 Serve 持久映射，不在退出时发起异步 CLI 清理；需要撤销转发时，应先使用设置中的关闭操作。重启先绑定原端口再核对记录；端口冲突会停用入口并尝试撤销本应用精确映射，撤销失败仍保留诊断，不能视为外部转发已移除。

### Funnel：显式选择的公网入口（未认证）

默认保持私人 Serve 范围。先创建本应用的私人映射，在「可选 Funnel · 公网入口」点击「生成公网 Funnel 方案」。后台只读检查现有所有权、存活 Remote listener、CLI、登录、HTTPS 和明确的本机 Funnel 端口授权（443、8443、10000）。多条歧义授权、未知能力或不支持的端口会拒绝；不会通过执行 Funnel 探测或自动开启功能。

核对具体 HTTPS 来源及「私人 → 公网」变化，分别勾选更改访问范围与再次确认公开到互联网，再点击「确认更改入口范围」。缺任一确认不会执行发布。新方案或配置变化必须重新确认；不能复用旧方案。同一个来源也会取消旧邀请、断开现有连接；已授权设备重新连接仍接受原有权限校验，配对时须生成新邀请。

「生成恢复私人入口方案」可显式恢复 tailnet 私人范围；此操作与精确移除不依赖仍有 Funnel 授权。最终保存失败会保留 pending。重启只读区分目标范围仍在、原范围仍在、映射缺失和外部漂移，需本地「核对并恢复」才能保存实际结果；不会重放发布命令。外部配置不覆盖。要退出公网同时停用 Remote，请使用「关闭 Remote 并移除映射」，并检查撤销诊断。

公网能力未认证。CLI/本机检查不证明手机公网配对、TLS、策略或撤销后的可达性；这些仍需受控外部验收。Funnel 不改变 Host 指纹、短期邀请、桌面确认、设备授权和逐操作检查，不公开 Core 或管理端口。

### 组织已有 HTTPS 入口

填写规范的 HTTPS origin，例如 `https://remote.example.org`，不带路径、结尾斜杠、凭据、查询或 fragment。选择组织私有或可能公开访问，并确认应用配置范围；可能公开访问还需再次确认。此操作只保存应用接受的来源和配对链接，不部署或验证组织的反向代理、证书、VPN 或 ACL。

组织代理必须只转发 Remote 监听器，保留精确的外部 Host 并支持 WebSocket upgrade。HTTP Host 与 WebSocket Origin 按同一个配置来源精确匹配；loopback 来源使用独立的精确匹配，不能混用。`Forwarded`、`X-Forwarded-Host` 或身份头不扩大信任范围。浏览器保持正常证书校验；代理若提供 Web 代码，即处于 Web 发布信任边界。

### 诊断与后续模式

设置区区分缺失/过旧 CLI、未登录或待管理员批准、HTTPS 关闭/未知、端口冲突、映射漂移与待恢复记录。手机无法访问时先核对 tailnet 成员资格及组织策略；Host 离线时检查电脑后台，邀请过期则重新生成。不要通过忽略证书或转发 Core 来恢复连接。

Serve 失败不会自动切换到 Funnel 或 Relay；公网切换只能在本地明确生成新方案并两次确认。

## G3. Relay 的开发与部署边界

部署只包含三个角色：TLS 反向代理、静态 PWA、单实例 Relay。可以使用同一服务器和一个域名；TLS 由现有组织设施或反向代理提供。SQLite 数据卷保存 Host 登记与一次性邀请消费，不保存会话/代码/模型钥匙。无 Redis、任务队列、集群调度器或业务数据库。

公开路径：`/` 提供构建好的 PWA，`/remote/socket` 处理 WebSocket，`/healthz` 仅给无敏感健康状态，`/enroll` 仅接受限流的一次性 Host 登记。管理不放在公开 Web：服务器本地 CLI 生成/撤销 Host 登记凭据。所有端点用 TLS、请求大小限制和日志脱敏。

实际配置字段、限额与固定 Node 版本见 [Relay 服务说明](../../services/remote-relay/README.md)。资源限额不代表容量认证。先运行 `pnpm --dir clients/gui build`，再运行 `pnpm --dir clients/gui export:remote /absolute/new/remote-pwa`；导出命令只复制并校验 Remote manifest 的资源闭包，拒绝已存在目录。将此目录配置为 `assetsDir`，不要部署整个 Desktop dist。

需要接入原生 App 时，管理员在 Relay JSON 配置中增加 `"allowedAppOrigins": ["capacitor://localhost"]`；配置样例中的空数组和省略此字段都拒绝 App 来源。只列出实际 App 使用的精确 `scheme://host`，不带端口、凭据、路径、查询、fragment、空白或百分号编码，且不能使用 HTTP(S)/WS(S) scheme。Web 来源继续放在 `allowedClientOrigins`。两份列表同时用于 WebSocket upgrade 和 client 注册；缺少 Origin 的 Client 仍被拒绝。原生 App 可伪造 Origin，最终 Host 身份与设备权限仍由 Noise pin 和 Host DeviceGrant 验证。

容器内部非 root 运行，默认文件系统只读，仅指定数据卷可写；宿主无需挂载用户项目。固定镜像/依赖版本，提供 SBOM/第三方归属及可复现构建说明；源码、静态客户端、配置样例和运行所需脚本全部公开。

## G4. Relay 管理员与用户流程

管理员先完成域名/TLS/数据卷/反向代理配置，用本地管理入口生成十分钟一次性 Host 登记 code，再把 endpoint 和 code 通过组织已有安全渠道交给 Host 使用者。不存在要求终端用户配置数据库或修改路由器的步骤。

桌面用户在手机设置中填写精确 HTTPS Relay origin 和一次性管理员 code，勾选信任确认后启用；连接成功后选择 Relay 配对传输。需要换 origin 时重新登记。Host 用独立 capability 连接 Relay；登记 code 消费后不再使用，capability 不进入手机二维码。

登记中会显示进度；登记失败时保留输入的地址、注册码和确认勾选，供检查后重试。登记成功后显示已登记的中继地址和注册码已使用的说明；注册码不回显。添加设备弹窗显示二维码和可复制链接；本机 HTTP 入口会明确标注仅供本机浏览器使用，连接手机需要中继或已配置的 HTTPS 入口。

桌面登记 HTTPS 和 Relay WSS 共用 Desktop TLS 配置：合并 Node 默认公共根与系统信任的 CA，保留标准证书链、有效期和主机名校验。不同团队使用相同 GUI 安装包，通过设备上的信任配置选择自己的测试或正式私有 CA；公共 CA 签发的服务端证书无需额外安装。安装包不包含团队 CA、证书私钥或登记码，也不需要通过终端环境变量启动。服务端必须提供叶证书和所需中间证书；发送根证书不能代替设备端信任。

### 团队安装内部 CA（macOS GUI）

1. 管理员通过团队已有可信渠道提供**公开根 CA 证书**及 SHA-256 指纹。使用 `openssl x509 -in team-root-ca.pem -noout -subject -dates -fingerprint -sha256` 核对来源、指纹和有效期。不要向用户分发 CA 私钥或把服务端叶证书安装为信任根。
2. 在“钥匙串访问”中将根 CA 导入当前用户的“登录”钥匙串；团队统一管理的电脑可由管理员部署到“系统”钥匙串。打开该根证书的“信任”，将“使用此证书时”设为“始终信任”，保存并完成系统授权。仅导入而未信任、仅对特定主机放行、或只在浏览器中接受证书警告，不满足此部署方式。管理员应仅为组织批准的 CA 设置此信任。
3. 完全退出 GUI 及其 Desktop 后台，再从 Finder 正常启动 GUI。Node 会缓存 CA；安装、移除或更换根 CA 后都需要重启。按正常流程填写中继地址和一次性注册码，确认后开启手机连接。无需设置 `NODE_EXTRA_CA_CERTS`。开发环境原有的该变量仍按 Node 默认 CA 语义生效。
4. 用“添加设备”生成新二维码并在手机上配对。iPhone 必须另行安装同一 CA 的描述文件，并在“设置 → 通用 → 关于本机 → 证书信任设置”启用根证书的完全信任；通过组织 MDM 或 Apple Configurator 部署时按其证书信任策略处理。桌面的信任设置不会同步到手机。

证书是否用于测试不改变校验要求。服务端证书的 SAN 必须包含访问域名；使用 IP 地址时须包含对应 IP SAN。测试 CA、服务端证书及中间证书均须在计划使用期内有效。相同根 CA 下续期或更换服务端证书不需要更新 GUI；轮换根 CA 时先向桌面和手机部署新根并重启，再切换服务端，完成迁移后移除旧根并再次重启。

此行为采用 Node 的默认根与系统根合并规则，不等同于浏览器全部证书策略：系统对另一来源的公共根设置的不信任或吊销策略，不保证覆盖 Node 默认根。有关系统信任读取规则见 [Node CA 文档](https://nodejs.org/api/cli.html#--use-system-ca)，iPhone 部署见 [Apple 证书信任说明](https://support.apple.com/en-us/102390)。当前发布安装包仅支持 macOS arm64；本节不声明 Windows/Linux 安装包已验收。

团队交付验收应在未设置 CA 环境变量的电脑上，从 Finder 启动同一安装包，分别验证团队 A/B 的受信任 CA 与公共 CA：登记成功、WSS 已连接、重启后恢复、新二维码完成手机配对。未安装的 CA、过期证书和主机名不符必须被拒绝。登记失败保留表单并显示 TLS 错误码；检查系统信任、服务端证书链和有效期，不关闭 TLS 校验。

用户在桌面点击配对，扫描含 Host pin 和 room 的 HTTPS 链接；手机生成设备身份，桌面确认其指纹及项目范围。以后手机打开同 origin，选择记住的 Host 即可恢复；换设备、清理浏览器存储、改变 Web origin 则重新配对。更换 origin 不自动跨站迁移私钥。

选择“记住此设备”会把公开 room 与已验证 Host 身份一起保存，因此从 PWA 根页面或安装后的入口重新打开仍能选择 Relay。相同 Host 重新登记后，打开新的连接链接并完成验证即可更新记住的 room；未验证或被拒绝的链接不会更改它。清除设备会一起清除路由信息。若桌面报告 Relay 协议/传输限额不可用，请升级为提供 Host ready 限额声明的服务，或调整过低的服务额度后显式重新启用；不会自动放宽服务限制。

不需要在 Relay 中注册自然人用户。P0 一个实例就是一个组织管理域；跨组织隔离用独立实例和凭据。管理员可撤销 Host 的路由登记；具体手机设备访问必须仍在 Host 本地撤销。两种撤销不是同一动作。

## G5. 成本与运维取舍

Direct 的代价主要是网络工具安装/身份配置、移动 VPN 切换和供应商可达性；减少 AReaL 服务端运维，但不能删除其外部依赖。Relay 的代价是域名、TLS、持续 WSS 连接、流量、更新、滥用防护与监控；换来手机只打开浏览器的体验。这里不估算未验证的价格或容量。

Relay 健康指标只需活跃 Host/连接、失败类型、握手延时、队列积压、字节量和重连；日志不打印加密帧、token 或业务正文。备份登记库即可；没有业务历史需要从 Relay 恢复。数据库损坏不允许退化为匿名 Host 注册。按受支持的备份恢复流程，默认禁用所有恢复的 Host 登记，逐一重新登记/复核后才能路由；不能让旧备份中的已撤销 Host 自动恢复授权。

升级先禁用新的 Host 登记、对旧连接排空/断开，客户端按既有策略重连，不缓存待执行命令。回滚需要匹配支持的协议版本；不能在错误恢复中降低安全条件。安全事件优先本地禁用 Remote、撤销设备/路由，再检查 Core 已受理工作；禁用连接不是取消已经执行的副作用。

### 发布与回滚条件

开放公网写控制前，发布负责人须核对同一冻结源码的必需 Direct/Relay Native 业务与竞态、安全及端口隔离检查、生产浏览器可信 TLS、实际网络和真机结果，并完成人工发布批准；安装包、第三方许可与发行检查沿用[发行流程](../development/releasing.md)。失败或未执行的必需项不能由源码、容器或协议夹具通过抵消。

若出现授权失效、私有端口暴露、TLS 校验退化、命令重复执行或无法确认的迁移/配置持久化，应暂停发布并关闭受影响入口，按上文撤销设备、路由或本应用映射。回滚只使用兼容现有加密配置与协议的已验证版本，保留身份、项目范围及命令账本；不回退旧写协议、不重放未知命令。Runtime `UNKNOWN` 或服务拒绝排空时保留失败记录并人工核对，强制退出或清理进程不表示已结算。恢复入口前重新验证原失败边界与撤销结果。

## G6. 简易配对的边界

“简易”验收为：网络/组织部署完成后，桌面最多选择模式与已有项目，手机扫一次码，桌面确认一次身份；不要求用户复制长期 token、编辑 JSON 或开放 Core 端口。首次 VPN/组织域名设置是额外前提，必须在 UI 提前说明。

二维码过期、Host 离线、手机不在 tailnet、组织 TLS 不可信、旧客户端、密钥存储不可用，均提供对应诊断和可执行本地处理，不统称“配对失败”。不许通过忽略证书错误、关闭鉴权或公网暴露高权限端口解决。

首发真机验收目标为 macOS Host、iOS Safari 和 Android Chrome 的 PWA/浏览器；这些目标不是已认证声明，只有实际验证的平台与路线组合才可列为已认证支持。页面隐藏、系统休眠和退出浏览器均不能作为后台推送承诺。
