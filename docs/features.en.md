## Limitations

- Narrowed tool execution on macOS uses Seatbelt and tracks and terminates observed descendants; rapid orphaning can still escape observation. Linux native uses Bubblewrap namespaces with Runtime seccomp and requires `/usr/bin/bwrap` plus user namespaces. Linux launchers support host execution in full-access mode. The product Rust launcher and per-execution Linux cleanup do not require Python; the latter uses the bundled Rust binary `areal-runtime-reaper` and readable `/proc`. See the [Runtime cleanup boundary](api/runtime.en.md#output-and-cleanup). The controlled Docker `outer-container-perf` profile remains the fixed benchmark workflow. Windows native Runtime support is unavailable.
- Core, stdio MCP servers and plugin Hosts are trusted processes outside the Runtime OS sandbox. Remote services own their permissions. Approvals cannot expand deployment grants.
- `UNKNOWN` requires inspection and is never automatically replayed. There is no cross-epoch Runtime recovery, external-writer CAS, cross-file transaction or verified cleanup of all escaped descendants.
- A pinned Codex app-server subset and Claude CLI message adaptation do not establish full official-client compatibility. DSH support covers selected tools/filesystem services, not Core loop replacement.
- Workgroups support up to 64 tasks and 32 Workers; the CLI defaults to `balanced + fixed` with 2 Workers. Greater width or adaptive admission does not guarantee a speedup.
- Real GUI providers/accounts, other platforms, signed/notarized distribution and production capacity need independent validation; deterministic local-model acceptance does not cover these boundaries. All 20 pro cases provide [public Dockerfiles](../tests/perf/suites/pro/README.en.md); historical source images are provenance only.
- Goals do not resume automatically after restart. Cumulative execution budgets are unlimited unless explicitly configured. History and settled Goal requests use immutable segments; hot unresolved ledgers retain a 4 MiB resource guard. Session/resource capacities and available disk still apply. clear retains ledgers, with no automatic ledger GC. Conservative tokenBudget admission estimates do not guarantee a strict provider billing ceiling; unknown consumption retains reservations and stops automatic continuation.

Release preparation supports complete macOS arm64 and Linux x86_64 glibc standalone bundles plus a macOS Homebrew formula, with SHA256 verification, versioned installation and relocated read/write checks. npm and Windows are not supported; availability depends on published GitHub Releases/tap. See [installation](guides/installation.en.md).

File-reference retention and consecutive-failure execution limits require explicit experimental settings and are disabled by default. Noninteractive stdin remains closed by default; see the [configuration guide](guides/configuration.en.md#reference-retention-and-bounded-tool-recovery). Availability does not establish improved task success.

Old-observation folding and extra empty-completion recovery are also disabled by default and require explicit frozen experimental settings. Correctness regressions do not establish end-to-end gains.

## Answer feedback

When trajectory export is enabled and the receiver supports feedback, settled replies accept optional up/down ratings, reasons, and an independent Side refinement. Submission includes frozen context. See [answer feedback](guides/user-feedback.en.md).
