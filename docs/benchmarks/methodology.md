# 基准测试方法

运行命令见[基准指南](README.md)。真实任务收益、确定性机制回归、并发原语容量分别报告，不互相替代。

1. 运行前固定源码、题目、镜像、模型、参数、资源上限、重复次数和选择规则；同题同重复配对，顺序随机交错。
2. 以可信最终验收判正确，不用 Agent 自报、退出码 0 或局部编译代替。原始题与派生子任务明确区分；记录空测试、跳过和评分异常。
3. 保留全部计划尝试，包括失败、中止、超时、补跑和淘汰题。答案正确、正常完成与有效评分是独立状态。
4. 报告全部尝试耗时/已知 token，再对双方都正常完成且正确的同题计算比值。选择第一条合格样本，不挑最快；展示配对数量，缺少样本不比较。
5. 未报告 usage 保持未知，失败部分用量是下界。缓存输入已包含在 input 中，不重复累加；CLI 累计与公共观察器覆盖分别标注。
6. 单个用户 Turn、模型请求数、工具调用数和进程数量分别计量。模型许可占用包含网络/流等待，不代表 GPU 利用率；工具成功率不代表解题正确率。
7. 测量日志可能含提示/源码/服务信息，发布前脱敏并确认再分发范围。保留来源摘要，但不把仅有摘要称为完整可复现证据。

提高 Worker 上限不保证收益。与单 Agent、固定并发对比时，保持相同输入、授权和最终检查，并同时报告验收/修复成本。小样本、事后选题、不同版本或模拟环境只能作限定条件下的描述，不推出一般排名。
