# 连接恢复汇总报告：固定样本判断成本对照

2026-11-22。结论：现有汇总报告减少了证据查找与拼接，但增加了返回的文本量；未证明减少人类介入或真人判断时间。保持连接恢复这一条旅程，不扩大验证范围。下一步候选是压缩现有报告的决策摘要，保留相同事实和原始证据链接；本轮未修改报告生成器。

## 样本与方法

固定使用 `areal-connection-pilot-20261121-08` 的三个既有结果：正确实现、加载误报变异、休眠恢复 guard 变异。没有重跑产品、增加变异或更换样本。两个不继承前文的独立 Agent，分别从原始证据和现有完整 `imported-journey.json` 开始判断。两组可追查相同的原始 JSON 与 runner 日志，目录改为匿名案例号，按相反顺序阅读。截图均未提供，因此这是文本证据分诊对照，不是视觉验收。

开始前封存评分答案，逐附件复核既有 SHA-256。通过统一读取入口记录实际文件读取、返回字节和时间；保留首次回答，不反馈答案、不重试。七个字段覆盖旅程状态、首错、未到达事实、清理、故障准备命中、完整 CI 与下一步动作。独立评审使用相同可用工具和继承模型配置；每组只有一名评审，无法排除个体差异。

## 实际结果

| 指标 | 原始证据组 | 汇总报告组 |
| --- | ---: | ---: |
| 样本业务结论正确 | 3/3 | 3/3 |
| 六项业务判定字段正确 | 18/18 | 18/18 |
| 对完整 CI 越界声称通过 | 0 | 0 |
| 读取的不同文件 | 22 | 14 |
| 初始入口、共同上下文以外的原始附件读取 | 16 | 8 |
| 全部文件读取次数（含重复） | 24 | 14 |
| 返回证据文本字节 | 14,272 | 27,064 |
| 读取调用 | 7 | 6 |
| Agent 首次读取至提交（秒） | 164.251 | 105.795 |
| Agent 声明需要人类补充判断的样本 | 0 | 0 |
| 首答后纠正或重试 | 0 | 0 |

汇总组少查 8 个不同文件，额外附件读取减半；但现有汇总 JSON 包含身份、附件摘要与重复观察，返回字节约为原始组的 1.90 倍。字节数是工具返回量，不等于实际认知负担。Agent 墙钟时间包含排队、工具和阅读顺序影响，不能换算真人节约时间。两组均无需升级判断，不能把 0→0 说成介入减少。

## 保留的协议和评分问题

两组首答前，共同补充了一次六个 `requiredFacts`，避免原始组猜测验收计划。原始组已开始阅读，因此多读了两次上下文；所有原始计量保留。不同文件数和额外附件读取指标不受这两次重复影响，时间和返回字节没有事后扣除。

机械评分原样为两组均 **18/21**：封存答案的 `fullCiPassed` 是 `false`，但材料未提供完整 CI envelope，两组均回答 `null` 并明确说证据不足。协议原本允许缺证据时填 null，因此这六处字段差异是合理保留未知，不是虚假通过。报告保留严格匹配分数，另列人工核对后的业务字段与范围判断；没有改写真值或首答。主代理进行了这一次评分口径澄清，未纠正任何评审业务结论。

## 决策与边界

- 支持的收益：同一批样本的证据更容易集中查阅，减少了追查文件。
- 不支持的收益：人工介入减少、真人用时下降、未知缺陷发现率提高。`humanMinutes=null`，`canConfirmHumanTimeReduction=false`。
- 不扩大旅程范围。若继续改进，应先让当前汇总报告更短，并在这三个固定样本上保持判断正确性；不增加测试数量来替代成本测量。
- 当前只做一次两组 Agent 对照，没有真人配对计时或统计显著性结论。原始读取组也有 runner 的结构化首错，未刻意退化成难读的无结构日志。

[结构化结果](connection-recovery-report-comparison.json)保存协议、首答、实际读取日志、源文件摘要、严格评分和口径澄清。30 处原始证据引用均与保留源文件核对一致。本地复算包在 `target/connection-report-comparison-20261122/`，运行 `python3 target/connection-report-comparison-20261122/score.py` 可复算原始严格分数；该临时包未提交。产品验收仍以原三样本执行证据为准，本次没有新增产品通过声明。
