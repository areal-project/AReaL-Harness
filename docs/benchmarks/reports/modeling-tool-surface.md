# 建模工具集合对照

在新建制品工作区中，默认工具集合会把目录查看、目录创建和逐文件写入分成较多模型轮次。现有 `--tools` 可以显式缩小可见集合，让模型通过命令组合操作。此对照验证这一配置选择；没有修改 Runtime、默认工具、权限或外部任务生成器。

## 固定对照

两方均为 `9aa2d028d2a8ef255e3699109baf963e976c4ee7` 的同一 ci 构建及冻结 Runtime。默认组只排除委派；精简组使用 `run_command,read_process,image_read,write_process,terminate_process,task_state,read_tool_result`。使用同一已见龙舌兰公开建模输入、中立提示，固定十对新生成、交替启动次序、作者并发 2；没有替换失败或按中途分数停样本。

所有作者请求均通过 Arena/HTNN 使用 `gpt-6-astra / medium`，共同评审为 `max`，未使用当前账号额度。每根预算为墙钟 900 秒、80 个物理请求、80 个模型轮次、输入 4,000,000、输出 196,608、上下文 131,072；单请求输出 8,192。此前 16,384 上限的其他实验单独保留，不混算。

## 结果与准入

20/20 根正常完成，公开输入保持一致，实际 GLB 独立导出及标准视角渲染均成功。精简/默认的配对墙钟几何均值为 **0.800**，即降低约 **20.0%**，95% 配对 bootstrap 区间 [0.735, 0.870]。十对中 9 对更快。

成功模型响应从 143 降至 113；物理请求为 151 / 120，缺失用量为 8 / 7。已知输入小计从 2,053,650 降至 1,318,969（35.8%）；未知消费仍按配置上限保守记账，不能把已知小计或缓存输入下降直接换算成总消费、账单下降。

已知未缓存输入反而从 167,442 增至 240,057。保守输入比的 95% 区间上界为 1.278，未通过 token 改善门槛；本次准入依据是时延与质量，不能宣称计费改善。

每对使用一次联合盲评：实际参考图，以及每件作品的源视角、统一 front/right/top，匿名标签位置 5/5 平衡。四个视觉维度等权计分。精简减默认的质量差均值 **-0.087**，95% 配对区间 [-0.300, +0.125]；无精简组严重质量失败。它通过调用前登记的 0.5 分非劣界限和性能门槛（几何均值 ≤0.90，区间上界 <1）。这不证明质量完全相同。

## 参照与被拒候选

另行固定五组 AReaL 开/关组合看图与 Codex 0.166.0 Code Mode 的对照。Codex 实际轨迹会组合读取和多文件创建，但完整任务也会分开渲染、等待和看图。可选进程附图候选虽然组件测试减少一次模型边界，完整任务仅 1/5 根采用，配对时延中位比 1.056；一根被代理的 UNKNOWN 输出预留耗尽预算终止，不能算作原生不可恢复或成功提速。该候选不合入。

[Claude Code 工具说明](https://code.claude.com/docs/en/tools-reference)仅作设计参照，没有同模型 CC 成绩。隔离下载的 CC 2.1.314 未成功启动，未虚构原生运行结果。

## 范围与复算

十次重复属于同一已见来源，不是十个独立任务，也不证明游戏、白模、软件工程或全局默认收益。AReaL/Codex 另有构建、提示和图片预处理差异；上述十对因果对照两方保持一致。评审使用同一模型，仍可能有共同偏差。

只记录为新建、独占、以命令生成制品工作区的显式选项，使用方式和能力缺口见[工具指南](../../guides/tools.md#按工作区选择可见工具)。已有代码库需要的 CAS、历史或其他工具应保留，默认配置不变。

[机器可读证据](modeling-tool-surface-evidence.json)包含全部二十根、配对值、门禁和冻结证据哈希。几何均值为 `exp(mean(log(command_wall/default_wall)))`，使用种子 20261031、有放回配对重采样 20,000 次，区间取排序后的索引 500 和 19,499；质量使用配对均值。原始请求/响应、失败、盲评图像与源码保留在操作者独立归档，不随此摘要公开，不能声称仅凭仓库就能完整重跑全部材料。
