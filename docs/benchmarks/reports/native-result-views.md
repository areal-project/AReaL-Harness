# 内置搜索与历史结果回取实验

基线 `3c64f4f` 与证据中的 `native-v4` 冻结二进制使用相同的 `grok-4.7` 配置。最终六类常规探针各三对，双方均 18/18 正常完成且通过独立验收。新版总输入 token 减少 16.2%，未缓存输入减少 2.5%，输出 token 增加 9.2%，耗时未改善。独立的大 MCP 结果测试中新版 3/3、基线 0/3。它证明回取链路可用，不能算作同等正确率下的成本比较。

新结果视图仍默认 `observe`；本实验显式使用 `on`。内置 rg 和原文快照/回取不依赖该开关。[脱敏证据](native-result-views-evidence.json)保留 146 次尝试（含合并主线后的 7 次回归），配对性能结论只使用 `paired-v4` 的 36 次和 `snapshot-v4` 的 6 次。早期失败与无效夹具均保留，没有只挑成功重试。原始私有模型轨迹未公开，摘要可核算统计，但不包含完整公共复现材料。本报告与[前一轮工具优化](tool-optimization.md)使用不同基线，不应相加收益。

## 实验条件

沿用当前模型路由及采样配置，没有覆盖 temperature 或 reasoning effort。macOS arm64、debug 构建、Python/pytest 版本及二进制 SHA-256 见证据中的计划。seed=163，相邻配对并随机交错，两个宿主执行槽；每次独立工作区、HOME、Store。Turn 180 秒、stream idle 60 秒、工具调用最多 80 次。`--direct` 只清除测试子进程代理。部分实测与本地构建/回归同时运行，因此耗时只作描述，不能作为隔离的性能测量。

四个现有探针覆盖简单修复、长测试输出、多行失败上下文和批量编辑；新增 `search-groups` 在 65 条匹配的中间放唯一有效配置，`repeat-log` 在精确重复日志中夹诊断，`snapshot` 通过部署侧 stdio MCP 返回约 50 KiB、700 行库存，唯一有效值在中间。最后一项使用受限沙箱，夹具不在任务工作区；验收还要求源工具恰好调用一次且使用 `read_tool_result`。答案由 Agent 退出后的宿主断言检查，原测试/配置文件不得改变。

六类常规探针的最终 36 次均正常完成，没有缺失输入/缓存/输出 usage。可选 reasoning 计数存在缺失，汇总为 `null` 并另存已观测部分；不能补零。输入含缓存，未缓存为输入减缓存；不按未知价格换算费用。p95 使用 nearest-rank，18 次样本下等于最大值，稳定性有限。

## 大结果与迭代发现

最终 MCP 测试每次新版都调用源工具一次、回取七页、写出正确答案。三个新版尝试的耗时为 33.20、29.60、35.74 秒，输入分别为 213,501、213,689、213,839 token。基线在首次 MCP 调用的旧 16 KiB 接收上限处失败。回取提高了可完成性，同时确实增加了页读取和上下文成本；这里没有节省 token 的结论。

| 轮次 | 尝试 | 解释 |
|---|---:|---|
| pilot | 7 | 5 次正常正确；1 次答案正确但超时；1 次模型未发工具即停滞 |
| paired-v1 | 42 | 暴露自定义命令申请输出限额超过父 Scope；snapshot 夹具还可从宿主读取，相关答案分数无效 |
| paired-v2 | 42 | 常规 36 次全部正确；snapshot 6 次因 runner 禁用部署 MCP 而无效 |
| snapshot-v3 | 6 | 真实 MCP 已可用，但普通 TUI 没有广告回取工具，新版 0/3；据此修正可见性并补广告断言 |
| snapshot-v4 | 6 | 最终隔离的 MCP 测试：基线 0/3，新版 3/3 |
| paired-v4 | 36 | 最终常规测试：双方 18/18 |
| merged-regression | 7 | 合并主线 `3bf7613` 后的统一 CLI 版本，七类场景各一次，全部正常完成且正确 |

修正包括：自定义命令预算收窄到父 Scope，纯文本/结构化 MCP 接收上限提高到 8 MiB，插件输出上限在现有帧内提高到 96 KiB，回取工具在普通及研究会话均可见。若显式 allowlist 禁用了回取，不发无法使用的引用。确定性测试覆盖 UTF-8/转义分页、原文逐字节重组、跨 Thread 拒绝、重启/GC/配额和存储失败、投影固定、唯一中间证据及实际 MCP 链路。

合并主线后的 7 次回归也保留二进制、配置与夹具指纹；这组没有重跑基线，不产生新的性能比较。

冻结的模型测量之后，脚本复跑还发现启动取消时临时目录先于子进程清理的既有竞态。最终提交已调整顺序并通过确定性生命周期测试；该退出修正不包含在上述模型测量中。

MM480 已按原任务结果冻结 24 题清单（16 个零分/失败、8 个成功对照），记录在证据文件；144 次配对尝试未执行。原生产 runner 的外部媒体与嵌套容器适配源码未恢复，当前 Grok 路由也未在该生产沙箱验证。Linux amd64 编译不等于这条部署链已通过。本报告不声称 MM480 提分、生产适配完成或普遍加速。

## 复跑和回放

按[开发指南](../../development/README.md)构建两个独立版本，本报告测量的旧布局包含四个 server/TUI/Runtime 文件、`launch.py` 和新版完整 `tools/`。合并主线后 runner 也支持统一 CLI 布局：`areal`、两个 Runtime 文件、`launch.py` 和 `tools/`。发行包的 Runtime 与 tools 位于 `libexec/areal/`。冻结目录不能在测试中被重新构建覆盖。准备配置所需的凭据环境变量，运行：

```sh
python3 tests/perf/native_tool_ab.py \
  --variant "baseline=$BASELINE_BIN" --variant "native=$NATIVE_BIN" \
  --view-mode native=on --model-config "$HOME/.areal-harness/config.toml" \
  --output target/perf/native-result-views --repeat 3 --seed 163 --jobs 2 --direct
```

可用多次 `--case` 选择场景；默认七类、42 次。runner 保存原始计划、模型与夹具指纹、逐次结果。内置 rg 清单与 MCP 夹具指纹已补入后续计划；本报告较早计划未包含它们，证据用单独 supplemental 字段保存，未改写原计划冒充预注册。

读取一个 Core Store 的统计与离线模拟：

```sh
python3 tests/perf/result_view_report.py path/to/core-data --output report.json
python3 tests/perf/result_view_report.py path/to/core-data --replay --output replay.json
```

回放验证 Blob 摘要后调用相同的 Rust 投影实现，不发模型请求。只覆盖已保存原文，不补造旧轨迹的截断内容、不模拟 Thread 总配额；未记录 argv 的历史 `read_process` 可能无法重建命令分类。prefix 指纹用于诊断消息/schema/instructions 变化，不证明 provider 缓存命中。当前行为见[工具契约](../../guides/tools.md)，不能把离线候选节省写成实测账单收益。
