# 固定 75 题的 executionFocus 效率观察

显式启用 `executionFocus` 后，75 份候选作答均完成并通过原生执行及用量审计。在 70 个有效原版配对中，候选/原版耗时中位比为 **0.901**，总 token 中位比为 **0.798**。同批配对总 token 为 36,918,769 / 46,667,225，减少 **20.9%**。这些结果支持保留显式效率候选；单体建模的 token 反例和浏览器启动异常增加仍限制默认推广。

这是任务发起者指定的首轮开发观察，以耗时和 token 为主指标、质量与异常为护栏。它不是五次重复的正式统计比较，也不是未见来源确认。模型随机性、评分噪声和不同时段的网关负载仍存在；没有追加重复直到分数理想，也没有修改产品默认值。

## 版本、任务与比较边界

| 项目 | 冻结设置 |
|---|---|
| 任务 | SWE Pro HARD 10、自制仓库长任务 5、3D 建模 20、游戏建模 10、单体建模 10、历史 BlenderWorld 20 |
| 模型 | Arena 提供的 `gpt-6-astra`，`reasoning_effort=medium`；模型调用未使用本地账号额度 |
| AReaL | Core `1f6cc627a1754b32c32a5c396a9e58c8dd727deb`，候选只启用 `executionFocus`，程序化工具候选关闭 |
| Codex | 原生 CLI `0.166.0`，使用共同协议接入与任务环境；不代表 Codex 产品所有运行模式 |
| 根预算 | 512 个请求、16,777,216 token；单请求上下文 131,072、输出上限 32,000；自动重试 0 |
| 环境 | 建模和自制任务在 Arena Linux；SWE 在本地 Docker amd64，两方同镜像及资源限制，模型仍走 Arena |
| SWE 纠正 | 两组 AReaL 同用 Runtime `4b5f9acdf351650c4002232e3e34cc7a3f9e26c7`；前 5 题使用已完成的代理纠正配对，后 5 题按预先固定集合使用共同直连三组对照 |

原 SWE 的只读工具 seccomp 故障不能算正常解题开销；旧作者、原评分和费用均保留，未进入纠正后的有效效率配对。后 5 题没有依据成绩选择回退旧结果，也不跨代理/直连路径比较墙钟。运行层修复不是 `executionFocus` 的效果。

单请求输出上限是请求参数，不宣称网关绝对强制执行；累计预算按实际回执结算。统计使用同题、同模型及可比环境下的配对比值，小于 1 表示减少。不同运行环境的绝对墙钟不直接合并；质量量纲也不混合。缺失或无效的对照不补零、不推算比值。最终正常退出不等于全部工具无错误，也不等于全部质量要求已满足。

## 对原版的结果

| 类别 | 有效配对/固定题数 | 耗时中位比 | token 中位比 | 可知质量配对 | 候选/原版质量均值 |
|---|---:|---:|---:|---:|---:|
| SWE | 10/10 | 0.920 | 0.718 | 9 | 0.889/0.889 |
| 自制长任务 | 5/5 | 0.814 | 0.676 | 5 | 1.000/1.000 |
| 3D 建模 | 18/20 | 0.720 | 0.835 | 18 | 72.22/69.72 |
| 游戏建模 | 10/10 | 0.801 | 0.823 | 10 | 75.00/75.00 |
| 单体建模 | 10/10 | 0.950 | 1.177 | 9 | 72.78/70.56 |
| BlenderWorld | 17/20 | 0.950 | 0.698 | 16 | 0.7442/0.7548 |

70 对中 48 对更快、51 对 token 更少；配对比值的几何均值为耗时 **0.912**、token **0.822**。中位数、几何均值和同批 token 小计方向一致，但不能据此声称所有题或所有模型受益。检查点的 75 份候选中，73 份质量可知；一份原评分失败，一份仍在评分。原版有 5 份作者未通过执行审计，因此没有可比效率值。

SWE 的 9 个已知原版质量配对逐题一致，剩余一份原版评分受依赖头文件编译故障影响。BlenderWorld 一份有效候选的评分器因额外渲染文件而失败。这些评分 UNKNOWN 不算 0，也不追加作者重跑去获得理想分数。

## 机制证据与反例

正常 SWE 的原版/Codex 请求次数中位比为 1.938，每请求 token 比为 0.994；额外往返比单次请求负担更突出。启用策略后，候选/Codex 请求比仍为 1.409，尚有差距。对于每一对，`总 token 比 = 请求数比 × 每请求 token 比`；单独求得的几个中位数不能直接相乘。

10 对 SWE 的显式 ≤1 秒等待从 152 次降到 8 次，进程工具调用从 191 次降到 128 次，返回仍在运行从 83 次降到 28 次；工具失败均为 35 次。现有等待默认值已经较长，这支持减少不必要短轮询的方向，无需强制覆盖模型的等待参数。策略还包含独立读取和委派契约指导，不能把组合收益全部归于一句等待提示。

工具统计的离线复核覆盖全部 75 份候选及 70 份有效原版归档。读取器按 Core 的历史链合并顺序还原压缩分片，验证 SHA，并对继承的相同调用去重；缺失、损坏或内容冲突会使审计失败。8 项读取控制通过，这 145 份归档均没有引用历史分片，因此上述计数不变，也未发现新增 seccomp 故障。该复核不重跑作者或评分，不消除已记录的 Chrome 异常。

Codex 的 5 份自制题轨迹有 63 次模型请求、58 次 exec 程序，其中 15 次模型往返执行多个记录动作，证实其实际采用组合操作。程序化工具仍需测量净效果：本项目的缓存候选、早期程序化候选和浏览器混合候选没有同时改善两项指标，已停止扩量；不能因为 Codex 或 CC 提供某能力就默认启用同类机制。

单体建模 7/10 题 token 增加，中位比 1.177，失败工具从 10 次增到 29 次。游戏建模的失败工具总数虽然均为 19，但明确报告 Chrome 启动失败的题目从 2 个增到 5 个；单体同类暴露从 5 个增到 6 个。失败工具数不是独立基础设施事件数，恢复成功也不能消除异常差异。完整端到端消费保留，不删除这些题来提高收益。

## 成本、复算与使用范围

本次 Astra 对照保留 150 份原基线、75 份原候选、16 份代理路径纠正和 15 份直连纠正，共 **256 次作者尝试**。已知 token 下界为 **167,955,500**，另有 **11 次请求**缺最终用量；不得把未知消费填零。上述 20.9% 是 70 个有效配对的 token 差，不是整个研究过程的净节省。其他缓存、程序化、临时目录候选及构建、短控制、评分成本独立记账，没有算成作者收益。

证据 JSON 包含 75 个匿名化样本的三方终态、用量、质量及分组统计，可以复算可用配对的中位数、`exp(mean(log(ratio)))` 和 token 小计。原题身份以摘要关联操作者归档，完整请求、产物、失败和评分轨迹没有随仓库公开；仅凭这个摘要不能独立重跑全部材料。

可通过[配置指南](../../guides/configuration.md)使用现有显式配置：

```json
{"policy":{"executionFocus":true}}
```

该开关不改预算、隔离、工具结果、取消或验证要求，不按题号、Benchmark 或已知答案分流。[Core 策略实现](../../../core/engine/src/agents.rs)与注册默认值在复核的主线 `eeabc5002bd4c27701bad1f955a3e94709435b63` 中未改变，但静态一致不等于新版本性能复测。

本检查点停止追加 Astra 作者重复，保留显式候选及上述限制。Qwen 3.8 27B 的完整覆盖尚未完成，已见输出触顶和旧路由断流分别保留；失败早退不计提速。默认推广和跨模型收益尚无充分证据，通用门禁仍见[Agent 改进方法](../../development/agent-improvement.md)。
