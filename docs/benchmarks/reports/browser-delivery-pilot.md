# 本地 HTML 与浏览器任务试点验收

回复中的 HTML 默认进入内置 Browser。Agent 通过 `openDocument` 审批文件范围并展示结果，后台聊天不抢焦点。实现与文件范围见 [Browser API](../../api/browser.md)。

源码 Electron 的文档协议通过 25 项断言，完整桌面路径通过 6 项检查并正常退出。既有 Browser Core 回归通过 33 项检查，前后源码哈希一致。Rust 审批测试通过 8 项，Browser 契约通过 76 项，任务与清理单测通过 25 项。类型检查和 GUI 构建通过。

六题试点从新聊天冷启动，由 Core 审批后的 `describe` 创建原生页。最后一轮普通任务 5/5 完成，停止题确认权威状态为 interrupted、观察期副作用稳定、停止后无新审批和在途模型请求。六个实例均正常清理，源码与运行产物前后校验一致。[结构化摘要](browser-delivery-pilot.json)保留各轮状态与原始证据位置。

调试中的不利结果均保留。静态 Profile 错置动态工具、公开 create 不支持的字段和手工页面预热分别造成启动阻断。随后固定模型误把末条运行上下文当作工具回执，造成六题流失败。下一轮普通题通过，但停止后继续回应审批导致 UNKNOWN。修复分别经过实际输入校验器、生产计划、真实持久化回执及停止边界回归验证；没有修改答案或评分条件来接纳失败。

这轮使用确定性本地模型，只证明测试链路和源码桌面行为。真实供应商、模型自主生成 HTML 后主动打开、安装包与跨平台尚未验收。不能据此报告 Agent 效率或整体能力提升。真实模式的预算、辅助请求与重试口径见[评测方法](../methodology.md)。后续优化需在固定模型和预算下比较任务成功率、请求与 token 成本及耗时，普通任务与停止安全分别报告。
