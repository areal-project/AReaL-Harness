# Agent 改进目标与方法

Benchmark 用于暴露缺陷、检验机制和测量收益。优化对象是 AReaL-Harness 在真实任务分布上的可靠交付能力。失败题可以成为回归用例；产品设计必须说明它解决了哪一类问题，以及为什么对未见任务仍然成立。

本文是开发、提示词调整、工具设计、配置默认值、评测适配和 PR 评审的共同约束。执行分层遵循[架构](../design/architecture.md)，比较与统计遵循[评测方法](../benchmarks/methodology.md)。历史成绩不构成当前能力承诺。

## 目标与比较口径

在相同模型、可比资源、固定任务分布与可信验收下，推动 AReaL-Harness 的交付质量、耗时和交付成本超过官方 DeepSeek Harness（DSH），逐步接近 Codex。长期覆盖软件工程、浏览器、文档和数据，四领域各占 25%；领域内部按预先固定的来源组与任务权重统计，不能靠扩充某个母题的变体改变整体权重。

| 维度 | 判断依据 |
|---|---|
| 质量与可靠性 | 满足公开任务、保护无关状态、真实完成交付；分别记录功能正确、正常终态、有效评分与待审 |
| 效率 | 全部计划尝试的时间、请求和用量，以及双方正常正确配对的耗时与成本；保留失败、摘要、重试、子任务、验证及修复成本 |
| 泛化 | 未参与调优的任务、独立来源与不同领域仍成立；同源多次重复不增加独立来源数 |
| 工程约束 | 权限、隔离、取消、UNKNOWN、兼容性和账本正确，不能用扩大授权换取分数 |

质量与约束是前提，随后比较效率与资源取舍。每轮在运行前固定最小收益、允许退化界限、样本、领域覆盖、预算及停止规则；未固定这些规则或证据不足时，只报告差距，不宣称“超过”或“接近”。耗时、token 和金额分别报告；缺少价格、完整用量或账单时不能直接宣称费用优势。

区分两条比较：同模型评测用于识别 Harness 差异；实际产品使用可比较各自模型与工具组合。经共同协议桥运行的某个 Codex CLI 版本，只代表该组合，不能推出 Codex 原生产品的整体能力。模型身份、协议、提示、工具、推理参数和资源差异必须披露。

## 改进覆盖面

| 能力 | 应调查的问题 |
|---|---|
| 任务理解与约束 | 后续修订是否生效，范围和保留要求是否明确，是否把推断当成用户要求 |
| 规划与行动选择 | 是否先读真实接口，分解是否必要，何时改变失败策略，验证是否有针对性 |
| 上下文与证据 | 用户要求、参考资料和当前状态是否区分；省略什么、如何恢复、是否及时恢复 |
| 工具与环境 | schema、路径、分页、版本与 stdin 语义是否清晰；结果是否完整，是否保留部分副作用 |
| 恢复与预算 | 临时错误、永久拒绝、空回复、截断与 UNKNOWN 是否区分；恢复是否有界且完整计量 |
| 委派与调度 | 任务依赖、共享写入、隔离交付、父子所有权、等待与取消是否正确；并行收益是否抵得过协调成本 |
| 验证与收尾 | 检查是否覆盖要求和真实产物，是否验证旧版本，是否在已完成后继续无效消耗或提前停工 |
| 持久化与可观测性 | 重启与压缩是否保留事实，能否把模型、工具、存储和环境损失分别解释 |

从实际瓶颈选择改动层次。模型等待长不自动证明本地执行慢，任务失败不自动证明需要更多 Agent；增加工具、提示词、并行度、重试或预算都必须有对应假设。

## 从失败到修复

1. **冻结证据与有效性。** 保存源码和未提交差量、二进制、配置、提示、工具、模型、环境、公开输入、评分器及完整尝试身份。先排除坏题、错误评分、协议接入与部署漂移；Agent 不接触隐藏答案和评分材料。
2. **重建完整执行链。** 对齐用户要求、模型请求、工具参数和结果、状态变更、预算与最终产物。区分观察到的近端停因和推测的根因；同时检查成功对照与反例，不能只解释最差轨迹。
3. **提出可证伪假设。** 写明触发条件、失效机制、涉及的契约、预期改善和可能受损的任务。说明什么结果会推翻假设；优先用无模型回放或最小复现排除它。
4. **修复最小充分机制。** 在正确的共享边界改动，保持 Clients → Core → Runtime 依赖方向。Core 管任务、历史和调度；Runtime 管权限、执行事实和资源生命周期；适配器只处理公开接入契约。通用修复不要求大重构。
5. **验证契约与反例。** 必要的回归覆盖触发类别、边界、合理替代输入、无关状态保护和恢复。改名、换数据、调顺序可以发现写死内容；它们仍属于同源稳健性检查。测试验证真实行为，不只验证新增字段或提示出现。
6. **隔离测量行为策略。** 提示词、压缩、恢复、调度与性能阈值先在开发集做同条件对照。优先单变量；必须联合修改时先报告组合效果，再消融，不能把组合收益归给其中一项。
7. **确认并决定推广。** 未参与调优的来源隔离任务验证迁移，检查原成功任务与其他领域是否退化。根据预先门禁选择推广、限域、继续实验或拒绝；失败后不反复扫描阈值直到这几题通过。

确定性正确性或安全缺陷可以凭清晰不变量、充分复现和必要回归修复，无需为每个修复启动昂贵模型实验。此时只能声明契约修复；通用任务收益仍未验证。纯文档、格式及不影响 Agent 行为的变更无需补造模型评测。

## 通用修复与定制化的边界

| 情形 | 判断 |
|---|---|
| 某题暴露多轮压缩丢失用户修订，修复原始用户输入的保留 | 通用正确性修复；同类输入和恢复边界应有回归 |
| 某题的指南中部丢失，按文件回执的协议保留正文、身份和分页 | 可接受的机制假设；还需检验预算、过时证据和实际使用效果 |
| 按公开 MIME、工具 schema、环境能力或显式 Profile 适配输入和执行 | 合法能力适配；记录配置、边界及成本，不扩大原任务授权 |
| 根据题号、套件名称、固定业务内容、答案或私有路径改变策略/预算 | 禁止作为通用产品逻辑；公开的实验分层须显式配置、单列结果，不能暗中匹配 |
| 为某题硬编码操作顺序、目标值、答案格式，或读取隐藏 Reward 指导动作 | 禁止；属于答案污染或评测绕过 |
| 看到一次失败便加入“必须总是……”的全局指令或硬阈值 | 有过度泛化风险；先证明适用条件、合理反例和兼容性 |
| 修复评分器误拒，对全部 Harness 的原始产物同版重评 | 可接受的独立评分修订；保留原始分数、修订理由与版本，不能改评分迎合某方产物 |

通用性不等于忽略任务信息。模型应根据用户需求与公开环境选择行动；Core 可以根据读写意图、依赖关系和资源状态调度；领域工具可以实现稳定公开协议。禁止的是依靠测试身份或答案建立捷径。

判断一项改动时，应能回答：移除题号、改名、换业务值或换一个实现同类契约的系统后，它为何仍有用？合理的反例会怎样处理？能力是否经过生产 Engine/Runtime 生效，其他入口是否也能使用？维护成本是否低于收益？如果理由只能是“这道题就这么做”，就不能推广。

## 评测数据与实验边界

- **开发集**用于观察失败和调优；**确认集**在方案冻结后检验迁移；**回归集**保护已知契约和成功路径。已查看、据以修改或反复选阈值的题进入开发集；同源变体不能重新标为来源隔离确认题。
- 一旦确认结果用于下一版修复，该题后续属于已见开发材料。有限次数的确认仍按原计划报告；下一次独立确认换新来源。没有未见来源时明确标注泛化未知。
- 构建、输入和评分链路修复与 Agent 策略实验分开。共同工具对三方应用相同契约；协议桥不替模型决策，不增删任务要求，不反馈隐藏分数。
- 外部累计预算、模型单次窗口、传输字节、输出上限和并发分别固定。主请求、辅助请求、标题、摘要、恢复和子任务全部归属根账本；默认无限累计预算不能当作有限预算实验的成绩。
- 每次冻结包含适配器、附加提示、自动续轮、完成标记和默认配置。只读输入格式转换可在适配层；额外规划、动作选择与完成反馈属于被测 Agent 策略，必须披露并单独比较。
- 功能正确、正常结束、有效评分和独立审查分别保存。不得挑最快成功、丢弃预算停止、将待审记零，或把缩小请求体和省去估算 token 当作成功率或实际费用。

策略对照必须同时增加独立任务/来源覆盖与同题重复，不能用多次重跑一个母题替代泛化。正式比较每题每方至少 5 次；开发对照、全局确认的来源及样本最低规模、区间估计与停止规则统一遵循[评测方法](../benchmarks/methodology.md#重复次数覆盖面与证据规模)。先登记规模与判定门槛，证据不足保留实验状态；不能把最低次数当作统计充分性。

## 默认值与评审门禁

新增性能或启发式策略默认保留为显式可关闭的实验候选，直到同条件开发对照和来源隔离确认支持其适用范围。全局提示、固定重试次数、压缩/保留阈值和调度策略同样受此约束；不是只有写死答案才会过拟合。正确性修复按契约证据评审，并明确未证实的性能收益。

原文存在不等于模型及时取得关键事实；减少输入字节不等于减少执行总消费；并发原语可用不等于端到端加速；恢复成功不等于可以重放副作用。发生负向结果时，停止晋级并分析机制，不能仅凭新增单测抵消真实退化信号。新机制不能直接继承旧版本的正向或负向效果结论。

使用 [PR 模板](../../.github/PULL_REQUEST_TEMPLATE.md)保留简短、可审查的说明：

1. 问题类别、具体证据、近端停因与机制假设；不只列题号。
2. 共享修复位置、适用条件、反例，以及提示、工具、默认预算和适配器是否变化。
3. 实际运行的机制测试、开发对照、来源隔离确认及未执行项；区分实现、契约和效果。
4. 全部尝试中的收益、退化、成本和局限；明确是否具备推广默认值的证据。

评审无法据此解释迁移机制，或改动依赖题目身份、隐藏答案、评分宽松化及单方预算优势时，不得按通用改进合入。缺少泛化证据的行为候选可继续隔离研究，不得写成已支持的整体能力。
