# 对话流与 Composer 体验验收合同

本页定义桌面“组织任务 → 提交 → 执行 → 阅读 → 继续”的验收合同，不表示当前实现已通过。阅读标准 C1–C7 和既有量化门槛继续有效；下文补充 Composer、跨阶段状态和证据要求。现有行为见 [Messages 阅读合同](../../clients/gui/renderer/src/Messages.md)，接口见 [Core API](../api/core.md)。

## 问题定义

用户需要连续阅读自己说了什么、Agent 如何回应，以及任务当前处于什么状态。打开、补页、刷新、切换返回和后台输出都是同一段阅读体验的一部分。

本次要解决的问题是加载和更新期间的阅读连续性。用户报告了回复先出现而提问缺失、等待明显和内容跳动。读取、投影与布局各自如何导致这些现象，需要通过下面的用例定位，不能仅凭截图确定根因。最终记录齐全，不能证明加载过程中完整可读；数据请求结束，也不能证明正文已经显示并稳定。

本期优先保障普通用户的体验。会话轮数少但工具输出多、单轮执行时间长，仍是普通场景。不能用内部原始日志大小把这类会话归入极端长历史。这里的“优先覆盖大多数用户”是产品取舍，没有用户分布数据时不能宣称已覆盖某个百分比。

## 阅读对象

- **基本对话**包含用户消息、对外回复、原有消息顺序、关联轮次及执行状态。用户消息中的附件保留可识别的入口。
- **过程详情**包含工具参数与完整输出、模型上下文、执行轨迹和大附件内容。它们可以晚于基本对话加载；默认折叠的内容无需提前展开。
- **阅读位置**是一个稳定消息或段落及其视口偏移，不只是滚动条数值。
- **可读时刻**是目标位置的基本对话已呈现且可以操作的时刻，不是接口返回、`complete=true` 或占位出现的时刻。

这只是体验上的分类，不预先要求新增持久模型、缓存层或 API。

## 体验标准

| 编号 | 标准 | 可观察的通过条件 |
| --- | --- | --- |
| C1 | 对话完整、顺序可信 | 已发布阅读区间中的回复具有对应的用户上下文。分页不能展示一段新回复却把其提问留在尚未加载的页。消息不漏、不重复、不跨轮错配。 |
| C2 | 基本对话先可读 | 工具原文或轨迹读取被延迟时，用户消息和回复仍能先呈现。不能为了补齐一轮的全部内部记录而一直空白。 |
| C3 | 主动阅读不被打断 | 用户离开底部后，分页、流式输出、重观察和异步排版不把用户拉回底部，也不让内容反向跳动。 |
| C4 | 上下浏览尽量无感 | 正常补页不插入“正在加载历史”等文字行，不清空正文，不要求反复上滑才能补齐已经露出的同一段基本对话。 |
| C5 | 返回后接着读 | 同一进程切走再返回，恢复原消息或段落及偏移。内容已离开缓存时，先恢复所需阅读区间；等待期间的新导航优先。 |
| C6 | 跟随与回看明确 | 用户在底部时跟随新内容。用户上滑后停止跟随，显式返回最新才恢复；流式结束与过程折叠不改变这个意图。 |
| C7 | 故障不抹掉已读内容 | 补页或详情失败时保留已确认正文和位置。确需用户处理的错误提供局部恢复入口，不把未加载说成“没有更多”。 |

C1 不要求用户气泡始终和长回复处于同一屏。用户主动滚入长回复中间、恢复已保存的位置，或跳转到指定消息都合法。判断依据是对应提问是否已纳入同一可读区间，而不是截图中是否同时出现两个气泡。显式跳转到未加载区间时也要建立上下文，不能静默显示孤立尾部。

执行中的用户消息可以先于尚未生成的回复出现。无用户提问的系统事件按其真实来源显示，不为凑齐问答制造消息。完整性以权威记录中实际存在的消息及关联为准。

首次打开没有可复用内容时，可以显示不改变阅读区几何的轻量占位。占位不算可读，也不能用更长的等待来换取“最终齐全”。后台刷新保留已确认正文。用户主动展开、改变字号或窗口宽度可以改变总高度，但仍需保持当前阅读锚点；稳定性不等于禁止一切高度变化。

## 初始量化门槛

以下是设计与实现要接受的初始门槛，不是已有性能结论。首次测量必须绑定机器、构建模式、数据和负载；若需要调整门槛，必须记录原因，不能随失败结果自动放宽。

| 指标 | 门槛与测量边界 |
| --- | --- |
| 完整性 | 全部必测用例中，最终基本消息 ID、顺序和关联与独立权威数据一致。加载中每个可见提交或采样帧也检查 C1；不能只等最终静止再断言。 |
| 非用户位移 | 用户停止输入后，补页、刷新与详情到达造成的锚点位移不超过 2 CSS px。用户滚动期间不得因加载出现反向位移；边界钳制和用户主动导航单独判断。 |
| 重复打开 | 应用与 Core 已就绪且会话已访问时，从选中会话到目标基本对话可读，p95 不超过 200 ms。 |
| 首次读取 | 应用与 Core 已就绪但未读取该会话时，同一指标 p95 不超过 1 s。应用冷启动单独记录，不混入此项。 |
| 滚动响应 | 受控本地环境中，输入至可观察滚动反馈的 p95 不超过 50 ms；连续浏览不得出现超过 100 ms 的无响应区间。主线程长任务、帧间隔和画面证据一起判定，不能仅凭“没有长任务”判流畅。 |

正确性用例不以多次重试掩盖首跑失败。延迟测试每个主要数据类型至少执行 20 次，报告样本数、p50、p95、最大值和失败数；基准比较交错执行。调试构建与生产构建分别报告。CPU 编译竞争、后台负载或探针开销使数字不可比时，标为证据不足。

## 用例设计

用例按失败机制选择，真实会话是样本，不是独立修复分支。每条用例同时检查过程与终态。

| 编号 | 数据与操作 | 必须验证 |
| --- | --- | --- |
| T1 | 短会话首次打开，再切走返回 | C1、C2、C5；记录首次可读与返回可读时间。 |
| T2 | 只有 2 至 3 轮，但每轮有大量工具记录，单轮原始体积超过传输页 | 仍按普通会话验收；先看得到提问和回复，内部记录不阻塞基本阅读。 |
| T3 | 相同基本对话，分别配少量、大量及故意延迟的工具原文 | 基本对话内容和顺序相同；详情被屏障阻塞时 C2 仍成立，首屏耗时分别达标。 |
| T4 | 40 轮普通会话，完整轮次、用户与回复之间、过程内部三种分页边界 | C1、C3、C4；真实向上和向下输入跨越边界，消息不临时缺失或重排。 |
| T5 | 长文本、表格、代码块和图片，字体、图片尺寸与高亮晚到 | 初次布局和滚入视口都不产生非用户跳动；异步变化后阅读锚点仍正确。 |
| T6 | 在历史中阅读，同时后台流式输出，随后完成并收起过程 | C3、C6；历史阅读不被拉走，底部跟随路径仍工作。 |
| T7 | 保存中段阅读位置，切换会话、释放页缓存、重新观察后返回 | C1、C5；核对同一消息或段落，而非只比较相同 scrollTop。 |
| T8 | 旧页请求未返回时反向滚动、切换会话或显式回到底部，再释放响应 | 新输入优先，旧响应不能抢回位置、串入别的会话或覆盖新意图。 |
| T9 | 旧页或详情超时、失败、重连与游标失效 | C7；保留已确认内容，恢复不重发用户消息，不无限重试。 |
| T10 | 同一轮有追加用户输入、多个对外回复、失败或中断结算 | C1、C6；不能把“一轮只能一个提问和一个回答”写进算法或测试。 |
| T11 | 明显超过本期普通规模的历史或超大单条消息 | 有界读取、已有内容可读、操作可取消或恢复；性能单独列报，不拖累普通路径设计。 |

T2 与 T3 固定基本消息，独立改变内部记录规模。T4 需要真实触发分页，不能通过扩大观察预算让测试不再分页。T8 使用可控响应屏障，不能用固定 sleep 猜测先后关系。

鼠标滚轮、键盘翻页与滚动条至少分别覆盖一次边界读取。自动化输入覆盖确定性行为；物理触控板与快速往返浏览保留人工验收，不能把模拟输入等同于设备手感。

## 证据与执行顺序

1. **定义问题和标准。** 用 C1 至 C7 描述缺陷，先记录门槛与范围，不选择补丁。
2. **设计用例。** 为 T1 至 T11 建立夹具、操作、独立期望和观测方法。先补过程断言，再跑当前实现；分别标记失败、通过、未执行与证据不足。
3. **比较设计。** 根据失败矩阵确定所需能力，比较沿用现有读取与最小接口调整。解释每个方案如何满足各标准、代价和兼容性；不能仅靠增加页大小宣称解决语义完整性。
4. **实现。** 按选定边界交付完整纵切。先保护基本对话，再处理详情。只有当前用例需要时才增加机制。
5. **统一验收。** 复跑失败用例和受影响回归，再运行两个不同类型的真实历史副本。记录源码版本、Core 与 Renderer 产物身份、隔离状态、原始失败和清理结果。

当前测试入口包括 `test:history-compat`、`test:conversation-reading`、`test:history-recovery` 和 Core `bounded_history` 集成测试。这些是可扩展的既有入口，不表示已经覆盖本页全部用例。测试计划维护在本次工作的证据目录；本页不存放个人会话内容、一次性测量或历史通过宣称。

每条执行记录至少包含用例编号、对应标准、夹具身份、初始阅读位置、输入与响应释放顺序、独立期望、实际结果及证据位置。独立期望从夹具原始消息生成，不能从被测投影反推。逐帧采样需报告采样间隔及漏检限制，不能声称覆盖两次采样之间的全部状态。

进入设计前，先用当前版本建立失败矩阵，区分内容未返回、投影缺失、DOM 尚未呈现和内容已在视口外。进入实现前，每个设计决定都要对应一条失败用例和一个负责边界。T3 若证明基本阅读被工具原文读取阻塞，再评估 Core 的基本对话读取接口；单纯把更多原始记录一次拉完不能替代这项验证。

实现交付必须给出“标准、用例、设计决定、变更、证据”的对应关系。单条真实会话通过、静态检查通过或最终消息计数齐全，都不能单独作为整个对话流已修复的结论。

## Composer 与跨阶段合同

一次任务包含未提交草稿、附带上下文、已受理操作和执行结果。这些对象的身份不能由气泡是否出现、输入框是否清空或动画是否停止推断。运行与历史事实仍由 Core/Runtime 拥有；Composer 拥有用户尚未交付的意图，阅读宿主拥有视口、选区与展开状态。

| 编号 | 不变量 | 反例与验收 |
| --- | --- | --- |
| D1 | 同一个按键只消费一个用户意图 | 中文候选确认不发送、不选择命令；确认后再次主动 Enter 可按设置发送；Slash/Mention 菜单开启时 Enter 只选择；改绑快捷键与换行分别检查。记录 compositionstart/end、isComposing、keyCode 和实际受理次数，不照搬固定 500 ms 窗口。 |
| D2 | 草稿与上下文按项目/会话隔离，恢复不静默降级 | A/B 会话往返、renderer reload、应用重开分别检查文本、图片、文件与引用。不能恢复文件字节时，至少保留可识别的待重附记录及明确提示；不能只恢复正文后悄悄少发上下文。恢复不读取超出原授权的路径。 |
| D3 | 提交身份与反馈可信 | 连续点击和按键不会重复受理；上传中、尚未受理、已排队、执行中、明确失败、结果待核对分别表达。回执丢失时先对账，不重放未知提交；明确失败保留可恢复输入。 |
| D4 | 异步完成不能覆盖后来意图 | 上传、配置和提交等待中，按实际产品允许的入口切会话、编辑或取消；旧回执只能结算原草稿/操作，不能清空新内容、抢焦点或把附件放入新会话。若编辑被暂时禁止，必须验证禁用期间和恢复时的内容与焦点。 |
| D5 | 停止、审批和排队由执行事实驱动 | “请求停止”不等于“已停止”；审批点击不等于工具成功；队列不冒充运行。确认归属、终态和实际副作用；持续故障展示用户能处理的具体问题。 |
| D6 | 阅读细节跨输出与结算连续 | 打开图形、选中文本或展开工具后推进正文、工具结算和回合完成。图形仍打开，选区/人工展开按同一内容身份保留；关闭回到可识别入口。已删除或改变的内容单列边界。 |
| D7 | 键盘与布局不阻断任务 | 窄窗、大字号、纯键盘下可完成输入、附件操作、发送、停止、菜单关闭和结果使用。焦点可见，菜单关闭不顺带停止任务；普通正文不撑宽整个页面，宽表/图形局部滚动。 |

### 发送稳定性的所有权与验收

交互归类为 I-INPUT / I-READ / I-OBSERVE，沿用 INPUT-TRUTH-01、READ-CONTINUITY-01 与 OBSERVE-TRUTH-01。编辑器拥有即时正文，草稿存储拥有按会话保存的未提交内容；`submitMessage` 拥有冻结的提交内容，Core/Host 拥有受理结果；`pendingMessage` 仅提供本地预览，`Messages` 的阅读状态机统一管理布局与滚动。正文渲染器负责渐进显示，不应为加载代码块而把已有文本替换成不同尺寸的“加载中”。

按下列边界设计改动，不通过延长等待或增加动画掩盖布局中间态：

| 边界 | 约束与最小决策 |
| --- | --- |
| Markdown 未就绪 | 保留正文、换行及既有文字样式，无额外占位内边距；加载完成后继续使用现有 Markdown renderer。复杂 Markdown 本身的重排仍需按 T5 验收，不承诺纯文本回退与任意图表等高。 |
| 新建预览到正式阅读区 | 两者共享 `--message-reading-inset`，创建回执不改变同一气泡的阅读起点。换行只表达一次：纯文本回退使用 pre-wrap，Markdown 使用 br 并移除其后附加的序列化换行；保留原文连续空格，避免 pre-wrap 重复解释换行。 |
| 草稿清空 | 多行输入允许一次收缩；原生窗口不移动，输入区不能收缩后无原因再增长。不能把这种正常收缩与用户消息来回跳动混为一谈。 |
| 待发到正式消息 | 本地预览和权威投影交接时正文持续可见；同内容气泡位置与尺寸保持，受理和投影两种先后顺序分别验证。 |
| 可编辑 / 可准备上下文 / 可提交 | 三种能力语义分开。现有已打开会话在提交或结果未知期间会锁编辑；取消锁定前必须先使清理只消费提交快照对应的草稿 revision/附件，迟到成功与恢复结果不能清空后续输入。不能只删 `disabled`。 |
| 草稿保存与渲染成本 | 复用已有内存草稿、150ms 合并写入、投影引用复用及轮次 memo。存储异常的跨草稿隔离和 snapshot 更新造成的无关 render 是需要故障注入/测量的风险，不由源码宽订阅直接推导全树逐 token 重绘。 |

发送抖动必须从动作之前开始取证，覆盖首次/第二次 × 单行/多行 × 点击/Enter，以及冷/热 Markdown。每帧记录 Composer rect/高度、消息 viewport、待发/正式气泡 rect、scrollTop/scrollHeight、焦点和动作时间；真实 Electron 另取原生窗口 bounds，并关联受理/投影与首段回答。不得等 pending 出现或等若干帧后才作为几何基线。

`send-continuity-ui-smoke.mjs` 的生产组件 fixture 覆盖最初帧与两种回执交接；它只控制提交边界，不能替代真实 Electron/Core。文本原样可见、纯文本待发气泡高度波动不超过 1 CSS px、Composer 无反向增长以及已有消息交接断言分别检查。首次冷加载时把正文替换为较高 loading 占位应让测试失败。性能继续使用 P1 的 p95 100ms 初始预算，DOM/rAF 代理与实际可见反馈分别报告。

| J4 执行介入 | 运行中追加/排队、审批、停止，同时保持后续事件到达；核对状态、归属和实际副作用 | D5；Composer、TurnActivity、Core/Runtime；`test:stop-turn`、`test:composer`。 |
| J5 阅读控制 | 足够溢出的真实回复中上滑、选中旧段落；继续输出并完成；显式返回最新再恢复跟随 | C3、C6、D6；Messages、conversationReading、readingViews；`test:conversation-reading`、`test:reading-checkpoint`。 |
| J6 结果使用 | 流式闭合图形放大、缩放/平移、完成后关闭；宽表横滚、长表固定表头、复制/下载 | D6、D7；Messages、MessageResponse、DiagramReader、MarkdownTable；`test:content-reading`。 |
| J7 性能干扰 | 短稿、约 30k 字符稿分别连续输入；再在长回复流式更新时输入和回看；检查真实字符增长及布局 | 下述 P1/P2 与既有滚动门槛；TextContentPlugin、Composer、Messages；需在真实浏览器/桌面记录，不能由纯函数测试替代。 |

### Composer 性能口径

这些是新增的初始预算，不修改既有阅读门槛。先区分客户端反馈、提交受理、供应商首段输出及执行完成；不同时间段不能合并成“响应时间”。

- **P1 输入反馈**：从 renderer 接到真实输入事件，到对应字符进入 DOM 并出现下一次可见反馈，p95 目标不超过 100 ms。每种工作负载至少 20 个有效样本，记录 p50/p95/max、丢字/重字、longtask 与帧间隔；百分位使用排序后 `ceil(p*n)-1`。必须验证正文确实增长。
- **P2 前后台互不阻断**：分别报告空闲输入、流式更新中输入、回看历史三组，明确内容规模、增量频率、已挂载消息数和工具详情状态。不能以空白页面速度代替流式场景。
- `keydown → 下一 rAF 回调` 仅是绘制前代理指标；rAF 到达、DOM 更新、屏幕绘制是不同边界。只采到代理指标时标为证据不足，不能据此宣布 P1 正式通过。
- 本地 IPC 受理、模型首段响应另列耗时；不能把 Playwright/CDP 往返或供应商等待归为本地输入延迟。构建、CPU 负载和探针开销需记录；不受控环境不作跨产品快慢排名。

## 验收记录与发布判定

每项记录使用 `PASS`、`FAIL`、`UNVERIFIED` 或 `BLOCKED`，同时记录边界和理由。`BLOCKED` 是启动、构建、测试驱动等前置条件阻止观察；`UNVERIFIED` 是未测或证据不足。一个脚本退出零、部分阶段跑过或截图存在，都不自动授予整条旅程 PASS。

最小记录字段：合同/用例 ID、源码提交与 dirty 状态、Core/Renderer 身份、OS/浏览器/窗口/字号、数据规模、动作与事件顺序、独立预期、实际值、原始样本/截图/trace、失败分类、清理结果。正确性反例要让目标断言失败；不要用探针主动抛出的“采样完成”异常冒充产品失败。保存首次失败和后续修正，不能通过更换定位器、环境或等待条件抹掉原记录。

故障注入必须先证明目标操作经过的当前边界确实失败，再断言草稿保留、提示和恢复。例如 Host 已将部署技能复制为运行快照时，移走原始技能文件不代表正在使用的技能读取失败。记录实际请求的资源身份、错误回执和受理次数；注入未命中时判为夹具失效，不把等待错误提示超时归为产品缺陷，也不跳过该恢复用例。

发布底线是范围内的 D1–D6 与 C1/C3/C7 没有已确认未解决的内容丢失、串会话、重复受理、状态误导或阅读控制权丢失。性能预算独立判定，不能用低延迟抵消数据错误。未测的原生 IME、真实供应商、安装包、平台或辅助技术能力明确保留，不以静态检查代替。

## 双产品基线

对比单位是同一用户旅程，不是组件外观或内部状态实现。六条旅程分别记录功能覆盖、操作成本、恢复成本、打断次数与性能；数据正确性不能由其他得分抵消。未测子项不得随整条旅程获得 PASS。

| ID | 固定旅程 | 最小验收与观测 |
| --- | --- | --- |
| B1 | 写提问并添加文件、图片与引用 | 核对标签、预览、移除、实际请求上下文；从已聚焦编辑器起记录操作数。注入文件不代表原生选择器通过。 |
| B2 | 新草稿/已有会话 A/B 往返、reload、独立重开 | 分别记录正文、文件字节或待重附状态、引用、光标；缺失上下文须阻止发送或明确移除。reload 不代替进程重开。 |
| B3 | 输入法确认、再按 Enter、Slash/Mention、换行、撤销 | 操作前后正文及实际受理次数；物理 IME 和合成 composition 分列。菜单按产品能力适配，不要求同名命令。 |
| B4 | 受理前失败、受理后丢回执、恢复重试 | 先证明故障命中真实边界；不丢草稿、不覆盖新意图、不重复执行。无可控协议时标 BLOCKED，不用 UI 定时器模拟成功。 |
| B5 | 输出中回看、选区、并发短/长稿输入、返回最新 | 明确流速、历史规模及段落身份；记录锚点、字符完整性、事件至 DOM/rAF/paint 各自边界。最终位置不足以证明全过程。 |
| B6 | Mermaid 放大缩放平移，表格阅读复制导出 | 分别在流式闭合和完成后操作；保留入口、关闭焦点、连续性、复制内容及下载字节证据。缺少入口先记功能差异。 |

共享素材由下面命令生成，包含逐文件 SHA-256：短稿、30,000 字符长稿、文本文件、测试图片、80 段初始正文、40 个建议间隔 100 ms 的增量、Mermaid 和八列三十行表格。驱动消费相同文件；协议适配只转换传输，不通过内部 setter 替代待验收动作或持久化。产品默认 Replay 内容不同则单列，不称同负载。

```sh
node clients/gui/scripts/support/conversation-baseline.mjs /tmp/conversation-baseline-materials
```

### 可执行入口与证据边界

`pnpm --dir clients/gui test:conversation-baseline-provider` 验证同一素材经真实 ACP stdio 与 SSE HTTP 传输后的内容、门控和辅助请求隔离；它只验证测试供应商，不验证产品 UI。自动标题等辅助路径使用本地确定性响应；验收环境不发现 Claude CLI。需要真实 CLI 的专项只使用显式配置的 Codex CLI，另记凭据和供应商边界。

源码桌面构建完成后，从仓库根运行：

```sh
AREAL_CORE_BIN=/absolute/path/to/areal \
AREAL_CONTENT_READING_EVIDENCE=/absolute/path/to/new-evidence-directory \
node clients/gui/scripts/conversation-dual-product-areal.mjs

AREAL_CORE_BIN=/absolute/path/to/areal \
AREAL_CONTENT_READING_EVIDENCE=/absolute/path/to/another-new-evidence-directory \
node clients/gui/scripts/conversation-dual-product-rich-areal.mjs
```

第一个入口覆盖三组各 25 次输入、实际流式重叠、阅读锚点及最终供应商正文；第二个覆盖共享 Mermaid/表格素材的流中打开与复制。每轮使用新证据目录，保存 `manifest.json`、原始样本、供应商记录和清理回执。B1–B3 结合 `test:composer`；B4 使用 `test:send-admission` 的受理前拒绝、结果未知及受理后丢回执场景。必须看到故障边界回执和权威历史，不能只看错误提示。

T3 的 `clients/gui/scripts/conversation-dual-product-t3.mjs` 与 `clients/gui/scripts/conversation-dual-product-t3-functional.mjs` 为外部隔离产品的手动驱动，不接入常规 CI，也不负责下载或修改 T3。固定参考提交、Replay 适配与服务准备条件见[双产品实测记录](../../design/archive/research/conversation-dual-product-baseline.md)。

固定两边提交、dirty 差异摘要、构建类型、OS、运行时、窗口 CSS 像素、缩放、字号、主题、语言和后台负载。冷/热运行分开，交替串行运行。每种性能负载至少 20 个有效原始样本；跨产品排名还需同素材、同边界和重复轮次。单边历史证据标为 reused，不能冒充本轮受控对照。React 耗时、IPC 受理、供应商首段与屏幕呈现分别报告。

每项结果包含起始状态、真实动作、可见结果、源码所有者、证据路径、采样方式、PASS/FAIL/UNVERIFIED/BLOCKED 和限制。功能另列完整支持/部分支持/不支持/产品选择不同/未验证。源码推断不能填为实测 PASS。截图按同状态同尺寸配对；操作计数只比较相同起终点，不计测试准备或隐式跳过步骤。

防止漏检：附件恢复变更跑 B2；编辑器/持久化变更跑 B3 及 B5 长稿；消息投影/列表变更跑 B5 并检查规模增长；故障夹具变更先确认注入生效再跑 B4。复用已有 runner，源码检查不替代桌面验证。回归保留修复前目标断言失败或隔离错误注入证据，首败和后续通过均留档。探索脚本未接入 CI 时明确标记，不宣称已有自动阻断。
