# Develop and validate the Android app

Android and iOS share `clients/gui/renderer/mobile/index.html`, `MobileClient`, `MobileWorkspace`, `MobileCommands`, Messages, and Composer. `clients/mobile/android/` is the controlled native project generated by Capacitor 8.5.3. Product adapters and instrumentation use Kotlin 2.2.20 with Gradle. Both platforms use `clients/gui/dist/mobile/`. The scanner plugin requires Android 8.0 (API 26); compile and target SDK are 36. An Android version does not prove WebView compatibility. Before loading business modules, the entry checks the secure context, WebCrypto, `AbortSignal.timeout`, and `Promise.withResolvers`, and shows an update message when capabilities are missing. A minimum usable WebView version requires a real gate on that version.

The scope matches the [iOS development guide](ios-development.en.md). It includes QR and pasted-link pairing, desktop approval, identity restore, foreground reconnection, project/session browsing, historical and live messages, ordinary session creation, model and permission selection, sending, queueing, stopping, and UNKNOWN command reconciliation. Task details are read only. Approval/question replies, file/Diff opening, and app push are not connected. Pairing uses scanning and pasting; there are no App Links or custom deep-link consumers.

## Environment and builds

Install Node/pnpm compatible with GUI engines, JDK 21, Android SDK Platform 36, Build Tools 35.0.0 (required by AGP), and Android Studio or a standalone emulator. The official `cap add android` generated the Gradle wrapper; use the checked-in version. Set `JAVA_HOME` and `ANDROID_HOME`, and add SDK `platform-tools` to PATH. Run from the repository root.

```sh
pnpm --dir clients/gui install --frozen-lockfile
pnpm --dir clients/gui mobile:typecheck
pnpm --dir clients/gui mobile:android:build
pnpm --dir clients/gui mobile:android:open
pnpm --dir clients/gui mobile:android:run --target <device-id>
```

`mobile:android:sync` builds the mobile web entry and runs `cap sync android`. `mobile:android:build` produces `clients/mobile/android/app/build/outputs/apk/debug/app-debug.apk`. The Debug application ID is `com.example.arealharness.debug`; Release uses the development placeholder `com.example.arealharness`. Select an application ID you own and configure signing before publication. This workflow does not publish an APK or configure external services. Existing iOS `mobile:sync`, `mobile:ios:live`, and other scripts remain separate.

Use an isolated emulator for Live Reload.

```sh
pnpm --dir clients/gui mobile:dev
# In another terminal.
pnpm --dir clients/gui mobile:android:live --target emulator-5554
```

The script verifies this worktree's development server at `127.0.0.1:5174`, uses the official `cap run android --live-reload --host 127.0.0.1 --port 5174 --forwardPorts 5174:5174` to build and deploy. Exit restores the generated configuration and Android Manifest and removes port forwarding. Source edits reload while the development server runs. Debug allows HTTP only for local `127.0.0.1`. Release uses the local HTTPS Origin. A Relay connection also requires the actual development origin to be allowed. The production `https://localhost` allowlist does not include this HTTP development address.

## Platform boundaries

`ArealKeychain` exposes the same `load/save/clear/deviceName` contract as iOS. Android Keystore holds the AES-256-GCM key. `noBackupFilesDir/remote-device.enc` contains only the encrypted envelope, atomically replaced through `AtomicFile`. The decrypted value remains the entire existing DeviceStore `schema: 1` string, including UNKNOWN locators. Native code does not interpret business records. The plaintext UTF-8 limit is 262144 bytes. Missing records load as null. Corruption, missing keys, and decryption failures reject reads and overwrites; the user must explicitly clear the record before pairing again. App backup is disabled; keys and identities do not migrate between devices.

Android hello sends `clientKind: "android"` and requires a desktop version accepting that value. Old Hosts reject Android hello, and old configuration parsers cannot read configurations containing Android grants. After approving an Android device, downgrading directly to an older desktop version is unsupported. This field is display metadata and grants no authority. Desktop Settings shows an Android phone icon and label.

The local Android Origin is `https://localhost`. Relay operators must add that exact value to the existing `allowedClientOrigins`; iOS `capacitor://localhost` remains in `allowedAppOrigins`. HTTPS does not belong in `allowedAppOrigins`. This local implementation does not modify existing Relay deployments. Release uses system TLS trust with chain, hostname, and expiry validation. Debug accepts system and user CAs; the gate runner's temporary test CA enters only its Debug APK.

The system handles a visible keyboard first. App Back then cancels the Composer model/permission sheet, clear confirmation, Settings, and pasted-link input, before navigating session/new/Task → work list → projects. Cancelling a sheet does not submit configuration. Back at the root minimizes the app. The scanner plugin owns Back inside its native activity. Keyboards, camera permission, and vendor gestures require physical-device acceptance.

## Reproducible gates

Before the first product gate in a new worktree, run `npm ci --prefix services/remote-relay --ignore-scripts` and `pnpm --dir clients/gui --filter @areal/gen-ui build` to prepare the Relay and desktop fixture dependencies. workspace/commands also require `AREAL_CORE_BIN` and `AREAL_RUNTIME_BIN` from the same complete fixed slot. The macOS test environment must permit Runtime Seatbelt preflight.

Use only a new isolated emulator for this task and select its serial explicitly. Runners do not select physical devices or modify system CAs. Relay fixtures have their own Node-version requirement; set `AREAL_RELAY_NODE` to a compatible executable when needed.

```sh
AREAL_ANDROID_SERIAL=emulator-5554 pnpm --dir clients/gui test:mobile-android-storage
AREAL_ANDROID_SERIAL=emulator-5554 pnpm --dir clients/gui test:mobile-android
AREAL_ANDROID_SERIAL=emulator-5554 AREAL_MOBILE_SCENARIO=workspace pnpm --dir clients/gui test:mobile-android
AREAL_ANDROID_SERIAL=emulator-5554 AREAL_MOBILE_SCENARIO=commands pnpm --dir clients/gui test:mobile-android
```

Workspace/command scenarios require absolute `AREAL_CORE_BIN` and `AREAL_RUNTIME_BIN` paths in the same deployed verification slot. The runner holds `scripts/verification.py`'s `slot_lock` across the entire fixture lifetime. Deploy source-matching binaries as described in the [testing guide](testing.en.md), then set these environment variables before running the scenarios.

The storage instrumentation gate checks save, load, clear, rejection of corrupted records and missing keys, the size limit, and absence of identity plaintext on disk, including a process kill between save and restore. Product gates reuse the real Relay and shared `product-driver.ts`. The debug-only `DebugActivity` injects scenarios and collects redacted results. Release source sets contain no diagnostic Activity, message bridge, or test CA. Workspace/command scenarios use the existing real Core and deterministic local model fixtures. Each product run clears only the dedicated Debug app on the explicitly selected isolated emulator before its initial pairing. It preserves data between restore cases. The runner temporarily reverses the Relay port through adb and closes its app, services, and forwarding on exit. Reports under `.scratch/android/product/` include source version, Android/WebView environment, results, and screenshots; failures also include stage and logcat. Override the location with `AREAL_MOBILE_EVIDENCE`.

Set `AREAL_ANDROID_HOLD=1` to retain the app and fixtures for up to ten minutes after initial pairing, for keyboard and Back checks. Remove `hold.json` from the evidence directory to continue the automated cases. Exit still runs cleanup.

Builds, instrumentation, real WebView, Core/Runtime, real providers, physical camera/keyboard behavior, and Release packages are separate acceptance boundaries. iOS simctl results are not Android evidence. Fixtures do not validate real providers or external Relay configuration.
