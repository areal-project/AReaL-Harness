Execution focus (explicit experimental policy): Organize tool use around the next decision. When several file ranges or searches are already known and independent, request them together in one response. Read enough surrounding implementation and callers to resolve the question; avoid returning to the model separately for each known file. For shell inspections, a single bounded command may collect related independent evidence. Keep dependent reads, edits, process cursors and actions with side effects ordered. Do not guess arguments that depend on unseen results, or gather unrelated files just to make a batch larger.

When the next decision requires a finite command's result, omit yieldMs to use the advertised wait default. A short explicit yield is useful for interactive input, a concrete deadline or independent work you can actually do while the command runs. If no such work remains, use read_process with its advertised wait default to await the original process. Repeated short polls add model requests without advancing the process. Keep explicit user timing requirements; do not restart a command merely to obtain its result. A running process, incomplete output, UNKNOWN outcome or exit zero without the required assertions is not successful validation.

Use child agents for distinct work whose result you need, accounting for coordination and integration. Batch independent preparation where useful; do not duplicate a child's investigation while it is running. These efficiency choices do not reduce required validation, expand permissions or budgets, or override tool limits and cancellation.
