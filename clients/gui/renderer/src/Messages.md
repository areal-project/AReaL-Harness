# 对话阅读组合合同

`R-MESSAGES-001` 本次准入限于投影、阅读与展开收起。Core 拥有执行与历史权威；生产宿主拥有命令、附件、子面板与原生资源的生命周期。完整对话模式与 SidePane 不在 Base 范围内。

## Messages

`R-MESSAGES-002` [Messages.tsx](Messages.tsx) 由 [App.tsx](App.tsx) 挂载，在主阅读区或嵌入上下文中展示传入的任务投影。已受理占位、逐步内容与终态内容保留各自身份。阅读历史时保留可见内容锚点；显式返回最新后恢复跟随。阅读状态按 project/thread 隔离。失败、结果未知与完成分别表达。投影不重放未知是否受理的提交。传入回调继续拥有业务动作；只读消费者不会因此获得编辑能力。移动端完整阅读页可传入 `showTurnNavigation={false}` 隐藏轮次导航栏，同时保留消息滚动、阅读锚点与自动历史分页。该参数默认开启。`embedded` 仍用于外层拥有滚动的嵌入内容，不能代替完整移动阅读页。触摸指针与滚动条共用起点记录，由后续真实滚动方向决定向上读取意图。

工作区文件引用的行内展示与悬停路径合同见 [R-COMPOSERSURFACE-007](../../packages/ui/src/conversation/composer-surface/composer-surface.md#工作区文件引用)。

## 同窗口 Renderer 恢复阅读

`R-MESSAGES-003` 此有限合同已通过隔离真实 Electron/Core 验证，见 [E-RECOVERY](../../design-system/base-evidence.md#e-recovery)。同一主窗口的 Renderer 重载或崩溃后显式重载，保留当前任务中仍已加载的可见正文段落与段落偏移。恢复期间的新输出不把正在阅读历史的用户带到末尾。显式返回最新后恢复跟随，后续重载也保留该选择。App 与 Composer 继续恢复所选任务和未发送草稿，Core 权威快照继续恢复历史与活动执行，不重放原提交。

`R-MESSAGES-004` Messages 继续拥有阅读状态。进程内缓存保留布局状态；同窗口 `sessionStorage` 只保存带版本的“跟随最新”或语义阅读锚点。锚点包含 turn、item、段落索引和可见偏移，按 project、thread 与主窗口阅读上下文隔离。内存与持久化均最多保留最近访问的 32 个阅读上下文，序列化内容最多 65,536 个字符。不保存正文、Core 历史、DOM、选择文本或过程展开状态，也不增加 Main 或 Core 恢复接口。存储不可用、内容损坏或写入超限时，进程内缓存仍按相同容量边界保存与淘汰。

`R-MESSAGES-005` 权威历史尚未补齐时，未解析的锚点保持待恢复。后续已加载内容可用时再定位，不把临时末尾位置写成用户选择。用户滚动、键盘或显式导航优先于待恢复锚点，迟到的历史补齐不能覆盖新选择。恢复只定位当前可用正文，不自动拉取未加载的分页或完整条目。

`R-MESSAGES-006` 本合同不承诺同一字符、完整应用退出后的阅读位置、过程展开状态、跨窗口或嵌入阅读区恢复。真实供应商、其他平台和安装包需要各自验收。原外观切片的进程内阅读证据不证明本合同。复验入口见 [GUI 生命周期](../../README.md#生命周期)。

## TurnProgress

`R-MESSAGES-007` [TurnProgress.tsx](TurnProgress.tsx) 由 Messages 使用，接收有序子项与摘要事实。未结算时默认展开，结算后可收敛。读者明确选择后，不再自动改变展开状态。没有可用摘要时保持展开。原生摘要按钮可通过键盘到达，并提供 expanded/controls 关系。子项保持挂载，查看历史不会重置详情或重放工作。失败与未完成提示来自调用方事实，不合成为成功状态。

## TurnExecution

`R-MESSAGES-008` [TurnExecution.tsx](TurnExecution.tsx) 由 Messages 使用，按顺序组织过程项。单个工具、思考组或纯 Agent 列表直接展示。有摘要的已完成回合，只有在没有失败或未完成项时才可自动收起。人工展开选择保留。分组摘要与活动区域可通过键盘到达；动画要求回合活跃、连接正常且没有待处理交互。失败或未知工作保持可见，不因出现最终消息而变成成功。用户主动暂停（`userPause`）后，不展示额外的暂停标题、命令资源提示或过程组末尾状态；耗时、过程与工具原始记录仍可查看。意外中断及其他失败继续显示原有提示。

## ToolEvent

[ToolEvent.tsx](ToolEvent.tsx) 由 Messages 使用，提供有名称的摘要与保持挂载的原始记录展开区。Enter 或 Space 可切换原生按钮；expanded/controls 标识已支持的详情关系。运行中、完成、失败与未知标签来自现有展示所有者。文件、命令、图片与 Agent 入口交给各自原所有者。本次仅准入工具摘要与原始记录展开两种变体，不纳入宿主生命周期及全部工具专有变体。交互式结果入口仅在传入状态为 opening 时禁用，不据此判定执行完成。

## 证据与边界

`R-MESSAGES-009` [E-CONVERSATION](../../design-system/base-evidence.md#e-conversation) 映射本地 phased/legacy 过程与阅读题目。已完成检查必须列明实际条件，不代表全部状态与变体组合、原生资源焦点、重连、真实执行、供应商或安装包已验收。

## 对话信息流

`R-LAYOUT-005` 活动类型、图片与命令组默认收起、组内纵向滚动，以及右侧上下文的新增设计要求见[对话流设计草案](../../design-system/conversation-flow.md)。该草案明确区分活动组与过程总组，列出当前源码差异；未实施部分不视为下列合同已经完成迁移。

`R-LAYOUT-006` 共享内容与阅读组织见[任务推进与过程阅读](../../../../design/patterns/task-progress.md)，请求与回执含义见[控制与审批](../../../../design/people-and-agents/control-and-approval.md)，父子关系与停止交接见[委派与交接](../../../../design/people-and-agents/delegation-and-handoff.md)。以下保留 GUI 的 CONV-* 合同与实际所有者。

`R-LAYOUT-007` 以下是 P-CONVERSATION 的目标合同。参考依据见[信息流观察](../../design-system/references.md#对话信息流的动态观察)，复验题见[动态信息流题](../../design-system/exercises/conversation-flow.md)。该完整模式尚未准入Base候选0.1.3；已准入的仅是下述动态题验证过的过程/阅读组合；另有真实 Electron E1 对话专项，范围见复验题，不能据此提升完整模式或所有桌面宿主准入。

`CONV-OWNER-01`：执行、内容展示和阅读意图分别拥有状态，不合成一个页面大枚举。暂停意图、轮次终态与工具结算分别表达：Core 已记录 userPause / coreRecovery 时，即使未确认的工具结果使轮次成为 failed，也保留对应中断原因；UNKNOWN 仍可见并进入原核查路径，不能显示为正常完成或已确认终止。核查只记录实际检查的事实，不重放工具或改写原结果。

| 事实 | 所有者 | 决定什么 |
| --- | --- | --- |
| 等待、执行、需确认、完成、失败与未知 | 原 Core/Runtime 权威投影 | 状态反馈与合法动作；不由文字、动画或折叠推断成功 |
| `R-LAYOUT-008` 用户消息、过程、工具、最终回答与资源入口 | Messages / TurnExecution / ToolEvent | 保留身份、顺序与语义层级，组合展示而不改写原始历史 |
| 跟随最新、回看历史、手动展开与返回 | Messages 既有本地阅读所有者及所属详情组件 | 滚动与展开选择；不提交、恢复或重放执行 |

`CONV-INPUT-01`：若存在预测指令或建议，它属于未发送输入；出现建议不等于用户提交。采集回复增长时排除 Composer、用户提示和预测建议。业务页不得因建议自动提交或把建议插入已受理消息历史；不据本条规则新增预测功能。

`CONV-CONTENT-01`：按 Core 的消息身份、顺序及 commentary / final_answer 展示。当前正文增量完整可读；工具开始、运行、结束与结果分别表达，不能用模型正文中的“已执行”冒充工具回执，也不能用命令等待代替正文增长证据。

`CONV-GROUP-01`：本轮过程与最终回答是不同层级。正常完成且已有明确最终回答时，目标默认将过程文字和常规工具活动收入可展开的过程总组，最终回答独立可读；展开后保持原文与活动顺序。总组→活动摘要→具体命令输出各有明确身份与展开入口，不强制每条内容都套三层。需确认、失败、未知或尚在运行的资源应保持可发现的状态与合法动作，不能只因 final 出现就当作已结算内容隐藏。

`CONV-RHYTHM-01`：对话时间线只有一种节奏。正文、过程说明、活动行、子代理行与底部过程状态共用 `--text-conversation`（跟随内容字号）与 `--conversation-line`（14px 时 20px），块与块之间只由 `--conversation-gap`（12px）分隔一次，不叠加首尾外边距。活动行与正文同字号，只靠颜色与图标区分层级。过程耗时标题在运行中与完成后都显示，与用户消息之间、与其下第一条过程内容之间各只隔一个 `--conversation-gap`；只有耗时标题而无过程内容时，标题分隔线与最终回复之间同样保留一个 `--conversation-gap`。运行中过程默认展开，完成后默认收起。当前状态只在回合底部一行。参考依据是 Codex 26.1013 的截图实测（14/20.5px、块节距约 33px），不复制其像素或品牌。

`CONV-ACTIVITY-01`：两条可见文字消息之间的工具调用合成一组，不论读、改还是运行命令；思考组、子代理创建与完成等行各自成段并打断分组，组内顺序与原始历史一致。只有一项时不建组，直接显示该项自己的行（如“已运行 git add …”）。多项时为一行可折叠的组，标题是过去式短语串，按固定顺序：修改文件、其他工具（浏览器、图片、等待、具名工具）、探索（读取、搜索、列目录、读技能与计划）、运行命令，如“已修改 2 个文件，已探索，已运行命令”。只有修改文件带去重后的已完成文件数，其他短语不计数；失败数在标题末尾写为“· 1 个失败”。标题不随子项运行切换时态，进行中只由回合末尾一行表达（`CONV-STATUS-01`）。组图标取第一个短语的阶段。每行为“动作 + 对象”：对象取文件名、命令、搜索词、技能 ID 等人能认的参数，拿不到时只写动作（“已列出目录”），不回退成工具的内部名称。失败的步骤留在原位，行尾写明结果（“失败 · exit 1”）。标题与行动作取自界面词条（`chat.activity.*`），跟随界面语言；英文后续短语首字母小写（“Edited 2 files, explored, ran commands”）。实现见 `activityStage` / `activityRuns` / `activityRunStages` / `activityRunLabel` / `TurnExecution`，回归见 `conversationPresentation.test.ts`、`TurnExecution.test.tsx` 与 `scripts/activity-runs.test.mjs`。**为什么：**按文字说明分组与读者的阅读节奏一致：模型说一句话、做一串事；短语串让人不展开就知道这串事的性质，改动文件数是唯一值得一眼看到的量，失败仍可发现。**推广：**新增工具沿公开工具身份归类，阶段只影响展示。**检查：**`clients/gui/scripts/activity-runs.test.mjs`

`CONV-PROCESS-01`：对话时间线以 Core 的 `commentary` / `final_answer` 为边界，不按文字内容猜测思考或工具事件。耗时位于过程顶部并控制整段过程的展开与折叠；已完成过程默认折叠，最终回答及交付内容不在折叠范围。回合完成自动折叠时，跟随底部的读者继续跟随；离开底部的读者以该过程标题为锚，标题已滚出视口时放到视口顶部，最终回答从首行可见（回归见 `scripts/conversation-flow-smoke.mjs`）。工具分组独立默认折叠，展开后列表限高 `--activity-list-max-height` 并支持上下滚动；列表下方还有内容时底部渐隐 `--activity-list-fade`，滚到底后渐隐消失，内容放得下时不渐隐。时间线在 Composer 上沿渐隐 `--conversation-fade`，不拦截指针。时间线底部仅在回看历史时显示“滚动到底部”入口，不显示运行中的文件变更数量浮条；回合结束后的文件变更卡片位于最终回答中。长过程仍在六行高度内滚动，当前流式正文完整展示。过程和活动区域支持键盘聚焦与滚动；打开单条命令或文件比较时，列表取消限高，避免与具体输出同时形成双层滚动。这是过程阅读的专用机制，不改变已发送用户长消息的展开行为。执行中的状态只在回合末尾一处，见 `CONV-STATUS-01`。成功图片结果、可打开的子对话保留轻量入口，原始记录按需查看；文件变更默认显示前五条，多余部分可展开或收起，行数继续取自 Core 本轮比较。Markdown 图片仅通过现有会话授权的 Core blob 读取直接显示；不自动读取任意本机路径或远端图片。普通链接直接打开，独立本地网页链接显示预览卡片，点击仍经过现有 Main 导航策略，不探测服务状态。`design-system.html?conversation` 提供同一生产组件的隔离预览，不连接用户 Core。

`CONV-STATUS-01`：一个回合只有一处实时状态，位于回合末尾，是一句话加左向右亮色扫光（ThinkingStatus）。这句话固定一行，超出宽度省略，状态变化只换文字、不改变高度。工具运行时这句话是当前动作与目标摘要（“正在运行命令… pnpm test”）：目标取第一条非空行并折叠空白，heredoc 只保留到起始标记（`python3 - <<'PY'`），多行命令以“…”结尾；完整命令与输出在活动行和命令详情里。模型思考时是公开思考摘要或 Thinking；上方的工具行保持静态，不再各自扫光。实现见 `statusTarget` / `TurnActivity`，回归见 `TurnActivity.test.tsx`。终态、reduced motion、连接中断、模型重试和待确认结果用静态文字；其中需要你注意的状态（连接中断、模型重试、结果待确认、没有决定卡时的等待）带警示图标，图标用 attention/unknown 状态色、文字用正文色。过程标题按 `R-CONTENT-033` 不重复这些状态。宿主已在 Composer 里显示待处理的审批或提问卡时（`Messages.decisionShown`），回合末尾不再重复“等待你的确认或回答”；没有卡片的只读或嵌入视图仍显示这句静态文字。审批卡内的“查看完整请求”“授权范围说明”等展开入口是文字按钮，不带展开三角；卡片内边距 12px，标题、正文与按钮之间各 4–8px。理由：多处同时扫光或同一等待说两遍，读者分不清哪一处才代表“现在”；把状态收在末尾一行，和 Composer 里唯一的决定入口各司其职。

`CONV-DISCLOSURE-01`：默认展开状态和用户选择分别记录。已完成历史的过程组初次收起时不挂载详情；首次展开后保持挂载，再次收起不重置详情状态。在同一组/详情身份存续期间，不用无关增量或刷新重置人工选择；父组收起与子项展开值分别处理，重新打开父组应恢复其仍存续的详情状态。跨轮次或新总组不得继承不属于它的展开状态。这是本产品验收约束，不能仅凭一次参考的完成总组截图声称已验证。

`R-LAYOUT-009` 连续展开沿原 ToolEvent / TurnProgress 使用现有 Base UI Collapsible 的测量高度与中断处理，内容身份保持挂载。命令详情采用已观察的 300ms 高度过渡与可逆箭头；过程总组箭头保留本产品 normal token，不将所有交互改成一个全局时长。快速反向须从当前呈现高度连续返回，不能等待旧动画结束再响应；减少动态效果时立即切换，隐藏内容不可继续接受焦点。原始记录、文件等其他详情未因本条自动通过动效验收。

`CONV-READ-01`：跟随最新时，新内容可推进视口；用户主动向上阅读后，后续正文增长应保留其阅读锚点。展开、折叠及完成收敛改变内容高度时，区分布局引起的scrollTop调整与读者离开最新的动作，不因一次尺寸变化擅自恢复跟随。返回最新是显式阅读动作；等待可观察到的到达条件后才称跟随已恢复，点击返回成功不等于滚动动画已经结束。实现阈值与坐标留在原阅读所有者，不由页面按截图硬编码。 历史分页沿同一阅读所有者：主动向上滚轮、向上导航键或滚动条输入在顶部附近授权一次自动读取；布局、冷打开、跟随最新和 observer 重入不自行授权。每次输入最多自动读一页；不足一屏时累计自动补页最多两页，手动加载或窗口重建后重置，失败后保留手动按钮，成功合并前后按可见正文锚点恢复。Desktop 每窗口最多缓存四页较早正文，卸载页的游标留在当前快照内，Renderer 在原位置提供“加载此处历史消息”；回读不会提交任务，也不提高正文缓存上限。重新观察、游标失效或释放最后一个视图会清理这些游标。超大条目仍需独立显式分片读取。

只有 Messages 时间线拥有对话纵向滚动。非草稿 conversation-pane 使用 clip 约束越界内容，避免 overflow:hidden 在焦点/scrollIntoView 时成为第二个可滚动容器并移动 Composer。重访子面板后再次发送，以及正常/暂停收敛过程中，均需连续核对 Composer 在窗口内、外层 scrollTop 保持零；仅在某个终态看见输入区不足以通过。

`CONV-RESOURCE-01`：图片、网页来源、子代理等保留对应内容的轻量入口与真实状态；打开和返回应保持父聊天身份与阅读上下文。活动列表随主对话滚动，具体命令输出可沿用既有有界阅读器。网页摘要或引用不能当作独立网页面板已打开，子代理完成也不替代父任务完成。 图片检查复用MessageAttachment的共享查看器：真实图像字节、缩放比例、实际大小、适应窗口及有界平移分别可核查。100%表示一个图像像素对应一个CSS像素，不按设备DPR放大；缩放只改变本次查看，不重新读取或执行工具。关闭仍由原Dialog恢复触发焦点。不得用带文字的色块冒充已加载图片。

`CONV-COMMAND-01`：命令入口展示原始命令与工作目录；详情将同一进程的开始、输出读取、结束投影为一份连续记录，stdout/stderr不以模型正文替代。只有明确且无歧义的processId关系才能归并；输出读取不是重新执行。运行、已结束、退出码、输出未收集完整、失败和未知分别表达，不能用工具调用返回成功推断进程已经退出。详情展开由原ToolEvent和CommandDetails拥有，不能由场景脚本预设展开结果。

`CONV-PARALLEL-01`：子代理在父时间线里是两条事件行，不是带状态的卡片。成功的创建回执画为“<标题> 开始工作”；父对话通过 agent_wait / agent_wait_any / agent_wait_all 观察到子代理已结束（回执 `settled: true` 且非超时）时，在那条等待回执的位置画“<标题> 已完成 / 已中断 / 失败”。没有这样的回执就不画完成行：读取子对话、子任务在别处完成、或父任务命令结束，都不改写父时间线；实时状态归子代理面板与任务上下文。两行与正文同字号同节奏（`--text-conversation` / `--conversation-line`），各自成段、不并入同类工具分组；整行即打开子对话的入口，不另放“查看”或运行中按钮，原始记录箭头只在悬停或聚焦时出现。标题优先用该子对话的标题，其次是真实委派的 prompt / input 内容，不能只放不具辨识度的短ID。子对话与父任务互不推断完成。打开子对话复用AgentConversationPane，父消息阅读所有者保持挂载。关闭面板只结束阅读，不能停止、重启或重放任务；窄容器可以覆盖主视图，但返回须保留父聊天与人工展开。理由：开始与结束是父对话里真实发生过的两件事，画在发生的位置，阅读顺序就是执行顺序；把实时状态塞进创建行会让历史行随时间变化，和时间线的含义冲突。

`CONV-SCENARIO-01`：复杂信息流必须有一条有意义的复合任务作为组合样板，包含命令增量、并行子代理、资源查看和最终收敛。固定输入沿既有投影接口到达，场景仅拥有到达顺序及面板选择；分组、进程归并、阅读锚点与详情状态仍由生产所有者处理。每个关键状态关联参考证据、实现帧和差异判断；缺少对应参考的时序标为产品选择，不能把独立采样拼成一次真实参考旅程。规则/目录检查、行为通过和视觉一致分别报告。视频候选、关键帧核查和差异裁决按[默认设计流程](../../design-system/structured-flow.md#执行顺序与每步完成条件)及[准入合同](../../design-system/governance.md#差异筛选准入)执行；本规则仅拥有信息流组合，候选意见不直接改变过程、阅读或业务状态所有权。

`R-LAYOUT-010` 减少动态效果沿同一有效偏好覆盖正文、过程箭头、侧面板和任务列表运行图标；静止图标仍表示真实运行，不把“停止动画”投影为任务已结束。图片缩放反馈可保持即时，不为所有资源虚构淡入/退场动画。按[E2 专项](../../design-system/exercises/conversation-flow.md#真实-electron-连续动效专项-e2)将视频与 RAF/输入/阅读证据关联。

## 混合内容与过程标题

`R-CONTENT-031` Messages将Markdown、原生内容和已验证的Gen UI引用交错展示。Gen UI仍要求已完成助手消息与有效制品；MCP Apps沿原工具结果宿主，不经过新的只读数据目录。不新增SDK/依赖，不承诺任意HTML、MathJax或全部TeX宏包。公式开启单美元兼容，保留代码/价格排除；未闭合单美元公式先显示文字。KaTeX沿已有版本提供MathML、mhchem与选区原式复制。

`R-CONTENT-033` 过程耗时跨语言统一显示英文：运行中为`Working for 15m 29s`，完成后为`Worked for 15m 29s`，作为可折叠的过程标题在运行中与完成后都显示。失败的工具步骤留在所在活动行，行尾写明结果（见 `CONV-ACTIVITY-01`）；过程标题仅显示耗时与展开箭头，不显示任务状态或警示图标。具体活动中的结果未知和需要恢复的动作继续沿原所有者展示。断连时不冒充继续精确计时。
