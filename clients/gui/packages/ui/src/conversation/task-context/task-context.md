# TaskContext 任务上下文

## 何时使用

`R-TASKCONTEXT-001` 需要核对当前工作涉及的对象或输入时，从对话顶部按钮打开。它是任务上下文卡片；文件、网页或子任务历史的阅读器是另一用途。

## 组成

具名 aside、标题、actions、可选返回、纵向滚动正文；Section 分区及次级标题，Item 统一图标/头像组、命名动作与尾部元信息，Sources 负责三项预览/查看全部/添加入口。id、hidden 和 onKeyDown 由宿主接线。

## 状态

`R-TASKCONTEXT-002` 产品顶部卡片默认收起，组件不自行决定开关。按钮 expanded/controls 对应同一 id；打开后保留来源折叠选择。Sources 初始展开，标题保持透明背景，使用明确的“展开／收起”文字动作，不隐藏提示或使用三角标记。组件收到空集合时显示紧凑空态；产品摘要卡只列有内容的区块，没有来源、子代理或定时任务时整块不出现，添加入口统一放在卡片底部。

## 行为

`R-TASKCONTEXT-003` 顶部按钮切换，Escape 或点卡片外关闭并回到入口；系统文件选择框夺走焦点不算关闭。有未暂存改动时按钮旁常驻显示 +x −y，范围写在悬停提示里。非模态不锁定正文或清空草稿。进入子代理历史暂收起卡片，关闭阅读器后恢复。宽窗有限高度卡片，窄窗单独阅读。

## 内容

`R-TASKCONTEXT-004` 卡片使用菜单表面和紧凑行式布局，项目标题为次级色。改动（Changes）单行展示名称与增删统计，统计范围通过无障碍名称及打开后的改动面板说明；不把工作区修改全部归 Agent。关联项目来自真实关系，子任务标题与头像/运行中、已完成状态分两行，状态独立。来源以单行呈现，文件完整路径保留在悬停提示与无障碍名称中；用原 id 区分，图片/网页/文件只是引用类型，不意味着已抓取全文。

## 可访问性

`R-TASKCONTEXT-005` 宿主通过 headingRef 聚焦详情，返回原入口；标题是入口消失时的回退。宿主传入 Sources 展开／收起的本地化文案；Sources 标题由宿主传入本地化文字，提供 expanded/controls 和独立添加按钮；隐藏卡片不留可聚焦内容。

## 规则

`R-TASKCONTEXT-006` 共享分区、图标/头像和尾部状态的布局由本组件维护；宿主使用 Section/Item 组合，不复制摘要行样式。选择依据见[深入查看与返回](../../../../../../../design/patterns/inspect-and-return.md)及[表达角色](../../../../../../../design/foundations/roles.md)。

`R-TASKCONTEXT-007` 来源默认最多三项，超过提供带总数的全部入口。onAdd可选；宿主没有合法添加动作时不渲染加号，不能用空回调伪装能力。宿主拥有数据、草稿与导航，组件不扫描项目、维护 Core 状态或读取凭据。

## 右侧任务上下文

`R-TASKCONTEXT-009` 顶部按钮打开的任务上下文卡片回答“当前工作涉及什么”。顺序为当前工作归属与 Changes → 关联项目 → Subagents → Sources。它与中间时间线共用对象身份：时间线按发生顺序叙事，卡片按对象整理入口，不能分别维护一份执行事实。

| 区块 | 摘要形态与内容 | 用户动作与范围 |
| --- | --- | --- |
| `R-TASKCONTEXT-010` Changes / 变更 | 当前项目名称、明确的变更范围、文件数及可信增删统计 | 打开原 Diff/变更面板；工作区变更可能包含用户或其他任务修改，不能全部归为本 Agent 产出 |
| `R-TASKCONTEXT-011` Related projects / 关联项目 | 用户要求列出当前 Worktree 下的其他项目；每项显示名称与展开入口 | 设计默认：项目详情先收起，展开后查看其归属与已有资源入口。仅列确有上下文关联的项目；无关系数据时不拿所有最近项目代替 |
| `R-TASKCONTEXT-012` Subagents / 子代理 | 用户要求有列表；设计默认：摘要展示有限头像与按真实状态分类的计数，展开为具名任务列表 | 打开同一个子对话；失败、待决定、未知与运行中状态可见，不能用“11 done”概括混合状态 |
| `R-TASKCONTEXT-013` Sources / 来源 | 可折叠区块、总数、添加入口；展开时最多三项及“查看全部（总数）” | 设计默认：首次打开右侧时展示三项预览；收起只留标题/总数，查看全部进入原宿主中的完整来源列表，返回恢复原位置 |

`R-TASKCONTEXT-014` 这里的“关联项目”描述产品上下文关系，不断言多个 Git 仓库物理处于同一个 Git Worktree，也不因展开而切换 cwd 或修改执行范围。关系与标识要在原 Worktree/项目合同明确后绑定；本轮不新增跨项目查询服务。

`R-TASKCONTEXT-015` Subagents 入口首先打开全部列表，按Active/Needs attention/Done区分任务状态，配合头像、状态图标和文字。完成项过多时先展示十项，可展开和收起；Active为零有明确空态。点击某项进入该子代理历史，显示请求、过程、活动与结果；返回保留列表展开、阅读位置与原行焦点，关闭恢复原入口。宽窗将子任务阅读器与主对话并列，暂收上下文卡片；窄窗进入单独阅读区，不替换成一段概括说明。

`R-TASKCONTEXT-016` 父任务与子任务状态分别提供。预览增加独立子任务状态切换，涵盖一项运行中/全部完成/一项需要确认，不从父任务结算推导子任务。运行中的历史可显示Working及公开模型过程摘要，无摘要时回退Thinking；已确认完成显示Worked和最终结果，未知显示待确认。用户标注确定当前过程文字亮度从左到右扫过；周期是实现选择。减少动态效果保留静态文字，离屏与后台停止；不在完成态或未知态继续扫光。

`R-TASKCONTEXT-017` 任务概览卡片与深入阅读的面板是两个用途。顶部入口在所有宽度可达；阅读子任务时暂收卡片，关闭后恢复。复用 WorkbenchShell / SidePane 的尺寸与导航，不按截图百分比固定侧栏，不叠出第二套常驻侧栏。打开项目或资源不丢失主聊天草稿、阅读位置及来源入口。

`R-TASKCONTEXT-018` 各区块分别处理读取状态：首次加载显示读取中；确认空集合后才显示“无变更/无子任务/无来源”；局部读取失败在所属区块反馈，不伪装成零项。刷新时保留已确认内容与人工折叠选择；断开连接或旧数据无法更新时标注可能过期。迟到响应只能更新原项目/会话，不覆盖当前上下文。

### Sources 管理输入

`R-TASKCONTEXT-019` 用户要求的 Sources 是输入来源集合，可容纳图片、网页、文件及其他已有引用类型。工具生成的截图、编辑文件和执行回执属于过程证据或产物，不因被展示就自动进入输入列表。Agent 读取过的文件可作为明确标注的“读取记录”入口，但与用户提供的输入分开表达；采用后的分类含义归[上下文与证据](../../../../../../../design/people-and-agents/context-and-evidence.md)。

| 条目组成 | 规则 |
| --- | --- |
| 身份与类型 | 使用原 URI、资源 ID 或引用身份；显示图片/网页/文件等类型，不只凭文件后缀判断 |
| 可识别名称 | 文件名、页面标题或可理解的名称为主；路径/域名为辅助。无标题时展示已有定位信息，不补造名称 |
| `R-TASKCONTEXT-020` 归属与状态 | 区分草稿待发送、已随消息提交、显式引用、读取记录；存在于列表不证明进入本次模型请求、被理解或验证 |
| `R-TASKCONTEXT-021` 预览与打开 | 图片可预览，网页交给原浏览器/链接入口，文件交给原文件阅读器；不可读取时保留名称与状态 |
| `R-TASKCONTEXT-022` 三项预览 | 设计默认：按首次加入顺序稳定展示，刷新不跳位；同一资源身份不重复，具有独立版本的引用不静默合并 |
| 查看全部 | 超过三项才出现；完整列表在有界区域纵向滚动，支持返回三项预览；零项显示简短空态与可用添加动作 |
| 添加与移除 | “+”沿原附件/引用能力进入主草稿，发送前可移除；不静默写入正在执行的上下文。已发送历史只读，移除草稿引用、释放上传与删除资源是不同动作 |

`R-TASKCONTEXT-023` 支持网页这一设计类型不代表本轮承诺自动抓取、持久化网页全文或新增上传后端。不支持的来源仍可显示原引用并说明可用打开方式。

## 非模态阅读

`R-CONVERSATION-009` 卡片使用非模态阅读：可以继续主对话，显式按钮/Escape关闭；当前不因普通外部点击自动丢弃阅读状态。窄窗保留顶部开关和返回入口。这个关闭策略、阅读器优先及返回恢复是产品选择，不从静态参考推断。
