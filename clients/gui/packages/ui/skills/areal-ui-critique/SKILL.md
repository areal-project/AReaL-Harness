# 审查 @areal/ui 界面

本 skill 只管“怎么审”。怎么改见 `areal-ui-guide`；交付要回答的五项见[完成条件](../../../../design-system/governance.md#完成条件)。

## 1. 先取证据

在仓库根运行：

```sh
pnpm --dir clients/gui design:build
pnpm --dir clients/gui test:design
pnpm --dir clients/gui test:design -- --conversation-system
```

`test:design` 最后一行 JSON 的 `scratch` 是本次证据目录：截图、计算样式、`manifest.json`、`accessibility.json` 与 `contrast-matrix.json` 都在里面。改动涉及的场景没有截图时，先补检查用例，再下视觉结论。

## 2. 亮暗分别看

同一状态的亮色和暗色截图各看一次，逐项写下：

- 层级：主阅读内容、次要信息与动作是否一眼可分。
- 对齐与间距：与相邻同类组件对比，而不是与画布或参考截图对比。
- 状态：默认、悬停、焦点、展开、运行中、失败各自可辨，且焦点环可见。
- 弹出层：打开后把鼠标移出触发行并悬停各菜单项，位置不变、触发按钮仍可见；以 `test:design -- --popup-anchors` 报告为准。
- 文字：长标签、窄窗口、18px 字号下不截断关键动作。
- 对比度：以 `contrast-matrix.json` 为准，不靠肉眼判断。

## 3. 判断题

CI 不判断下面几项，逐条回答“是 / 否 / 不适用”，回答“否”的写进问题列表：

- 页面只给 `@areal/ui` 组件布局，外观来自 variant 或 slot（基线里的存量不算新问题）。
- 同一个概念没有出现第二套实现，例如另写一个输入框或审批卡。
- 新增的通知是用户需要知道或能处理的；其余信息在原处说明。
- 高级功能默认收起；默认界面对普通用户没有多余选项。
- 文案短，用词与[术语表](../../../../../../design/content/terminology.md)一致。
- 加载中、未知、已提交等未确认状态没有显示成成功或“没有”。
- 只有桌面端才有的能力，结论注明是否在桌面验证过。
- 改动组件旁合同里带规则 ID 的强制规则逐条对照过。

## 4. 观察与推断分开

每条结论标明来源：

- **观察**：附截图或报告文件名，写明主题、字号、窗口宽度。
- **推断**：只从源码或 diff 得出的结论，句首写“推断：”。自动折叠、等待时长、滚动跟随和焦点移动不能从静态截图得出，只能写成推断或待补证据。

## 5. 输出

按严重程度列出问题，每条包含：位置（文件或组件）、证据（截图或报告）、违反的规则 ID、建议的最小修改。没有问题时写“未发现问题”，并列出实际看过的主题、字号和窗口。注明证据来自设计预览、源码 Electron 还是安装包；本 skill 默认只覆盖设计预览。

视觉基线由用户确认，审查结论不替代用户验收。
