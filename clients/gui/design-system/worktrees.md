# Worktree 设计系统：配置、准备与管理

状态：生产 UI 已按本文迁移，代表状态的视觉对照与交互覆盖见[Worktree 验收题](exercises/worktrees.md)。本文继续拥有目标规则；实现与验证限于列明范围，不扩大全局 Token、执行合同或 Base 准入。适用桌面项目模式，首期脚本平台为 macOS、Linux。产品名称统一为 **Worktree**，设置导航使用 **Worktrees**。

目标是让用户在发送前选清工作位置，发送后看懂准备过程，进入聊天后保留轻量的工作区身份，并在设置中管理目录与项目环境。视觉以用户提供的九张 Codex 截图为参照，沿用 AReaL 的字体、语义色、图标与公共控件。

## 视觉基础与几何

以下尺寸是**后续实现的局部候选值**，不是从截图实测得出的事实，也不是对全局 Token 的修改。若大字号或长文案迫使调整，先保持列关系、对齐与可达性，再在原组件所有者记录差异。

| 对象 | 目标规则 |
| --- | --- |
| 设置内容列 | General、项目列表、环境编辑共用一条居中阅读列；候选最大宽度 41rem，窄窗占可用宽度。沿 SettingsWorkspace 外边距，不给各区块单独设置宽度 |
| 配置浮层 | 候选宽度 20rem，上限为窗口可用宽度减两侧 `--spacing-inline`；主菜单、分支、环境子页等宽，右边缘与齿轮对齐。优先向上，碰撞时由公共 Popover 调整位置 |
| 行结构 | 图标 / 主标签 / 弹性空间 / 当前值 / 尾部动作；名称列 `min-width: 0`，尾部动作不收缩。同类行共享左右边缘与图标列 |
| 控件密度 | 配置菜单与资源行采用紧凑列表密度，最小行高沿 `--spacing-control-lg`，文字增长时自然增高；设置输入与开关仍沿原交互类型尺寸，不缩成截图位图大小 |
| 组内与组间 | 图标、标签和值用 `--spacing-inline`；字段之间用 `--spacing-field`；页面区块之间用 `--spacing-section`；容器内边距用 `--spacing-panel` |
| 表面层级 | 页面底色 → 一个安静的设置组 / 浮层表面 → 必要的输入或日志内衬。项目列表行不再套卡片；完成标识没有常驻大边框 |
| 圆角与边线 | 外浮层沿 `--radius-overlay`，输入/按钮/列表高亮沿 `--radius-control`；组内分隔使用原边线角色。不得从截图采样 hex 或新增相近灰色 |
| 文字 | 页面标题沿 SettingsPage；普通标签、项目/会话名使用 regular；说明、当前值与状态摘要用 UI caption / 次级前景；正文沿内容字号；代码和日志用 `--font-mono` |
| 状态 | 运行使用已有状态色及文字；正常完成降低强调；失败用错误角色；未知用明确文字。禁用、次级、完成是不同语义，不能共用一层低透明度 |
| 图标 | 沿现有图标集：文件夹 / 本机 / 齿轮 / Git 分支 / GitFork / 勾 / Chevron / Plus / Trash。图标尺寸沿原控件，不以 emoji 或新品牌图替换 |

`WT-VISUAL-01`：先核对轮廓、阅读宽度、对齐和层级，再核对局部细节。禁止以加粗所有标签、每段套边框、显示完整 UUID 或缩字号弥补信息组织问题。明暗主题沿同一语义角色，不能仅在深色截图中成立。

## Composer：上下文条与配置菜单

`WT-PICKER-01`（WT-R09）：入口在 Composer 上方的上下文条最右侧。左侧为项目文件夹 / 项目名、本机图标 / “此电脑”；齿轮独占尾部点击区域。上下文条与输入框组成同一视觉单元，不再加独立设置标题或外层卡片。长项目名优先截断，齿轮始终可达。

主菜单顺序固定如下；这是一组菜单行，不是纵向表单。

```text
配置本地环境                         次级标题
↗  新 Worktree                       [开关]
⑂  分支                   当前分支…    ›
⚙  环境                   未选择环境    ›
```

上面的字符仅表示槽位，实际使用原图标。行内当前值右对齐、单行省略；不在值下再放输入框。说明只在必要的禁用原因、失败或子页中就近出现，不在主菜单常驻一段创建原理。

| 条件 | 呈现与动作 |
| --- | --- |
| 合法 Git 项目，新 Worktree 关闭 | 每个新会话默认关闭，不继承旧偏好；开关与三行均保留；分支显示当前来源；环境禁用。来源分支可以预选，但必须说明它仅影响新 Worktree，不在原目录 checkout |
| 新 Worktree 开启 | 分支与环境入口可用；无环境也是合法选择。开启、切换来源或选择环境只修改草稿，不创建目录 |
| 非 Git / 项目外模式 | 不提供可用的创建开关；若保留入口则给出“需要 Git 项目”的原因。环境始终是项目配置，不能从另一项目补值 |
| 读取选项中 / 失败 | 原值保留；行内反馈读取状态。失败有明确重读入口，不能显示“无分支 / 无环境”冒充空集合 |
| 已存在的会话 | 使用真实工作区身份入口查看目录、分支、环境和 Actions，不沿用“新 Worktree”开关暗示可搬迁 |

### 分支与环境子页

`WT-PICKER-02`（WT-R08）：进入分支选择时替换同一浮层的内容，齿轮锚点不变，不在第一层旁边再堆一个弹窗。顶部为返回按钮与“分支”，下方搜索，再是分组列表。选中行使用一个轻量背景和尾部勾；hover、focus 与 selected 分开表达。

- 当前来源、Local branches、Remote branches 只在有相应数据时出现。当前分支与选中起点不是同一含义，不能只靠蓝点区分。
- 来源有本地改动时保留真实提示“仅使用已提交版本”；本期不出现可点击的“包含本地改动”。不复制截图里的能力暗示。
- 搜索过滤可用分支；空查询、无匹配、读取失败三种状态分别呈现。列表有界纵向滚动，搜索和返回留在列表外；长名称可在聚焦或详情中读全。
- 选择后返回主菜单并更新分支行；返回不改变值；Escape 先返回父菜单，再次 Escape 关闭。以上为设计决定，静态截图未证明该动态行为。

`WT-PICKER-03`：环境子页沿相同的返回、选择、选中标记与滚动结构。首项“无环境”，随后仅列当前项目已保存环境；底部“配置环境…”进入设置的当前项目环境页。无环境时保留简短空态和配置入口，不要求用户先建环境才能发送。

从配置入口进入设置保留项目、Prompt、附件、来源分支及选择。保存并返回后刷新同一项目的可选环境；已删除的选择显示失效并要求重新选择，不能静默换成另一环境。设置返回恢复该项目的合理入口与焦点，不自动发送。

## 时间线：准备、取消与完成

`WT-PROGRESS-01`（WT-R04～06）：用户 Prompt → Worktree 准备记录 → 助手内容，顺序可核对。准备期间展示的是已提交意图预览，不能暗示模型已收到；真正受理后沿同一消息身份衔接，不出现两条相同 Prompt。准备记录与首条请求绑定，不浮在另一轮或另一项目的历史上方。

| 层级 | 默认形态 | 内容与动作 |
| --- | --- | --- |
| 准备摘要 | GitFork + “正在创建 Worktree”轻量行 | 当前真实阶段；必要时一行等待说明 |
| 准备详情 | 一个弱边框区域，可展开；设计默认首次收起日志 | 有证据的阶段列表，控制行，必要的原始输出；不为每阶段单独套卡片 |
| 控制行 | 左侧“展开详情 / 收起详情”，右侧“不使用 Worktree”“取消” | 动作保持具名、同一基线；窄窗可换为第二行，不能挤掉其中一个 |
| 日志 | 仅详情展开后显示的内衬区域 | 有界纵向滚动，长命令/路径换行、原文可复制；日志增量不自动打开详情或抢焦点 |
| 已创建 | GitFork + “Worktree 已创建”一行 | 可进入详情核对目录与分支；随后仍在绑定 / Setup 时，另有准确等待说明 |
| 已就绪 | 保留轻量创建事实；普通聊天恢复 | 不常驻完整阶段清单、成功大卡片或居中全宽“查看详情”按钮 |

阶段标题只能来自实际可用的 Git / 宿主 / Setup 投影。没有细粒度进度时只显示“准备工作区”，不虚构“检出 80%”、已完成阶段、计时或 ETA。`created` 只说明 Git checkout 已确认，`ready` 才表示绑定与环境准备均已确认；不用同一个绿色成功态掩盖两者。

`WT-PROGRESS-02`：准备期间 Composer 保持原位，以“正在等待 Worktree 准备…”说明不能重复发送。停止 / 取消走原请求的取消路径。点击取消后立即显示“正在取消”，只有权威确认才显示“已取消”；已创建目录是否保留必须说明。不能因关闭详情、切换聊天或请求返回就宣称进程停止。

“不使用 Worktree”是显式改用原目录的用户意图：先确认原准备取消，再发起新的明确请求；等待期间禁止重复点击，失败或 UNKNOWN 不能自动回退。已确认失败时保留 Prompt、记录与可用恢复动作；UNKNOWN 只提供原请求核对入口。具体允许动作沿宿主，不在设计层新增“重试即可”通路。

`WT-PROGRESS-03`：手动展开跨日志增量保持，终态收敛不抹去可核对的记录；回看历史时不强制滚到最新。准备日志不是第二条独立聊天时间线，沿[对话阅读合同](patterns.md#对话信息流)与[活动层级](conversation-flow.md#主阅读列与活动层级)处理。

## 侧栏与会话工作区身份

`WT-IDENTITY-01`（WT-R04～06）：会话名称仍为侧栏主内容；尾部以一个紧凑 GitFork 标明 Worktree。不得为每个会话常驻第二行 UUID 分支或完整路径。正在准备时可以显示准备态，已绑定后才标为“在 Worktree 工作”，取消且未绑定不能留下成功标识。

标识使用可读名称 / tooltip，说明“Worktree”、当前状态与完整分支；目录在工作区详情可读。它与未读点、运行状态分别占位，不相互覆盖。颜色只辅助状态，减弱动效后仍能区分正在准备与已绑定。

会话头部的工作区入口展示真实目录、分支和已选环境；可用 Actions 位于此入口的详情内。Action 只在实际宿主允许时可运行，显示真实运行、失败和未知结果，不把“已接受”写成“已完成”。Actions 不塞入侧栏会话行，也不扩成另一个常驻工具栏。

## 设置：页面骨架与 General

`WT-SETTINGS-01`（WT-R01、03）：设置导航只有 Worktrees 一个入口。页面标题“Worktrees”，简短用途说明，下方 General / Environments 两个轻量导航标签。刷新作为标题区的尾部图标动作，具名且不清空当前编辑。两页共用相同起始边缘和内容列。

### General

顶部“创建与清理”区只有一个设置组，按下面的顺序排列；组内使用轻分隔和共享右对齐控件。

| 行 | 标签 / 说明 | 控件 |
| --- | --- | --- |
| Worktree 根目录 | 留空使用默认位置；默认 `~/.areal/worktrees` | 右侧路径输入，窄窗换到说明后；改值只影响未来创建 |
| 创建前获取上游 | 准确描述 fetch；不承诺自动合并 | 右侧开关 |
| 自动清理旧 Worktree | 说明仅清理符合安全条件的目录；不声称有恢复快照 | 右侧开关，默认值沿实际配置 |
| 保留数量 | 固定 / 活动 / 受保护目录可能超过数量 | 右侧数字输入；关闭自动清理时保留值并说明其生效条件 |

分支前缀是 AReaL 的已有配置，但不在参考主组中。设计决定：放入独立“高级创建选项”披露区，避免打断参考中的主设置顺序；不删除能力。General 沿当前显式保存合同，修改后显示同列末尾的“保存 / 放弃”，不要暗示自动保存。

### 按项目管理目录

`WT-LIST-01`：设置组下方留区块间距，呈现一个紧凑列表，而不是每个项目一张大卡片。项目头行用文件夹图标与项目名；其下工作区行按相同缩进排列：层级入口 / 可识别名称 / 弹性空间 / 查看详情或删除。

- 名称优先使用绑定会话标题，其次为分支，再无名称时使用短标识。完整路径、分支、环境、状态在展开详情中可读，不能只藏在不可复制的 tooltip。短标识不取代真实身份。
- 行首 Chevron 表达目录层级展开；选中 / 展开 / hover 是三种状态。纯图标删除按钮具名，hover 和键盘聚焦时可辨，不依赖红色小图标解释后果。
- 一次只给正在操作的行 busy 反馈；读取失败、删除受阻、结果未知在该项目 / 行附近显示，不把整个列表变成空态。
- 删除前显示目录身份及“移除目录，保留分支和历史”，沿现有删除确认合同。未提交、未跟踪、忽略文件、未合并提交、活动执行等阻挡原因用原检查结果说明；不增加强制删除按钮。
- 空列表显示“尚无 Worktree”；未知项目归属明确分组，不猜成当前项目。刷新保留已确认列表与展开位置，删除只有确认成功才移除该行。

页面只有一个主纵向滚动区；目录列表随页滚动，详情中的短字段不额外套独立滚动容器。

## 设置：Environments 与环境编辑

`WT-ENV-01`（WT-R01）：Environments 默认是项目列表。顶部“选择项目”，右侧“添加项目”沿现有项目添加入口；它不创建一个同名环境。每行项目图标、项目名、必要的归属说明、尾部添加 / 进入入口。点击项目进入其环境列表，已有环境按名称列出，并有“新建环境”。这个中间层为多环境场景的设计决定，不由图 1 的加号推断已存在。

环境编辑是独立内容页，不追加在项目选择器和完整环境列表底部。返回路径固定为“环境 > 项目名 > 环境名 / 新建环境”，返回项目时保留列表位置；不同时叠一条 Back 和同功能面包屑。未保存内容继续受原设置导航保护。

`WT-ENV-02`（WT-R02、07）：编辑内容自上而下为页面标题 → 名称组 → Setup script → Cleanup script → Actions → 保存。

| 区域 | 组成与对齐 |
| --- | --- |
| 名称 | 一个安静的圆角分组，标签在上、全宽名称输入在下；项目归属在导航中明确，不在名称旁重复完整路径 |
| Setup | 标题左、Variables 入口右；下一行说明执行位置与时机；下一行 Default / macOS / Linux 标签；下方完整宽度的代码输入 |
| Cleanup | 标题、执行说明、独立的三平台标签、代码输入；与 Setup 的左边缘、编辑器宽度和节奏一致 |
| Actions | 标题左、“添加 Action”右；简短用途说明；空态为安静的整行占位，不再套标题卡片 |
| 保存 | 内容列末尾右对齐的主按钮；旁边可放“放弃”。保存中保留值并禁用重复提交，失败就近显示，成功只表达配置已保存 |

Setup 与 Cleanup **各自拥有当前平台标签**；切 Setup 到 macOS 不改变 Cleanup 或 Action 正在编辑的平台。切换标签保留未保存的其他平台文本。空覆盖回退 Default 的真实规则就近说明；标签不以“空”冒充“禁用”。代码输入使用单一边框和等宽字体，候选最小高度为六行代码的行高加内边距，可增长 / 纵向滚动，不能横向撑宽页面。

Variables 入口打开小型只读说明，列出 `AREAL_WORKTREE_PATH`、`AREAL_PROJECT_PATH`、`AREAL_WORKTREE_BRANCH` 的含义与可复制名称；不显示截图的 `CODEX_*` 变量，不诱导填写凭据。主执行位置为新 Worktree 的项目根；保存脚本不执行脚本。

### Action 的有限形态

`WT-ACTION-01`：已有 Action 行以名称为主、必要的命令摘要为次，尾部“编辑 / 删除”；添加或编辑在所属行下展开名称与脚本，沿同样的平台标签规则。不要让每个 Action 常驻三个大编辑器。顺序沿已保存配置，删除仅移除配置；运行入口在会话工作区详情，不能把设置里的“保存”变成运行。

通用用途可以是“构建”“测试”“启动开发命令”，这些是名称示例，不预填会执行的项目命令。没有 Action 时不出现虚假的可运行按钮。当前受管命令的超时与后台进程限制沿现有指南，不把“启动”描述成持久服务管理能力。

## 有限例外与共享规则

下面是对[控件选择](patterns.md#控件选择)的**本领域有限例外**，只限所列用途；由 Worktree 组合承担，不增加公共控件的新默认值。

| 例外 | 为什么需要 | 限制 |
| --- | --- | --- |
| General / Environments 标签导航 | 参考强调同一设置领域内的两个页面 | 采用真实 tab / 导航语义，不当作布尔设置；仍复用原标签控件 |
| 三个脚本平台标签 | 用户需要来回编辑同一个脚本的多个平台版本 | 这是编辑面板切换，允许三个可见标签；不推广到普通三值配置 |
| 分支 / 环境的行式选择 | 长列表需要搜索、分组和返回，参考主菜单要求单行 label/value | 沿公共浮层与选择语义组合，不另造通用 Select；普通设置仍用 SettingsSelect |
| 目录行首 Chevron | 表达树层级，保留紧凑的文件目录语言 | 只用于目录树；普通设置说明仍用明确“展开 / 收起”的披露入口 |
| 目录行尾图标删除 | 管理列表需要稳定窄动作列 | 始终可键盘触达、有可访问名称及确认；普通设置操作继续文字按钮 |

## 状态、内容与可访问性

`WT-STATE-01`：可见文本取决于权威状态与用户动作。以下补齐截图未覆盖的状态，是设计决定；不得将其写成 Codex 已观察行为。

| 状态 | 必须看见 | 不可出现 |
| --- | --- | --- |
| 加载 / 刷新 | 所属项目、已有值、局部忙碌说明 | 把暂未读到当成没有分支或环境 |
| 无匹配 / 无资源 | 区分搜索无匹配、环境为空、目录为空 | 一律用同一句“暂无数据” |
| 创建 / 绑定 / Setup | 当前确认阶段、等待发送、可用取消入口 | 伪百分比、模型已开始回答的暗示 |
| 已创建但未 ready | 创建事实与剩余准备说明 | 解除发送等待或显示完整成功 |
| 取消中 / 已取消 | 正在核对终止 / 已确认取消；目录与草稿去向 | 点击即显示已终止、静默改用原目录 |
| ready / 正常聊天 | 一行创建标识、真实工作区身份、普通 Composer | 成功大卡片长期占据主阅读列 |
| failed | 哪一步失败、保留内容、宿主允许的恢复动作 | 不加条件的“再试一次即可” |
| UNKNOWN | 结果待核对、原请求核对入口 | 自动重跑、自动删除或回退 |
| 保存 / 删除 / Action 忙碌 | 所属对象与重复操作限制 | 只显示全页 spinner 丢失上下文 |
| 删除被阻挡 | 可理解的真实原因、目录仍保留 | 成功 toast 后实际目录仍在、强制删除捷径 |

文字沿现有 i18n；中文“Worktree / 分支 / 环境 / 设置脚本 / 清理脚本 / 操作”，英文与参考相同用途保持简短。状态使用动词与对象，不把内部 UUID、枚举或错误码当作主要说明。详情可保留必要的技术身份以便核对。

- 齿轮、返回、刷新、添加、删除、工作区标识均有对象相关的可访问名称。tooltip 是补充，不能承担唯一说明。
- 主配置不是 `menu` 内嵌不可达表单：含开关的浮层沿 Popover 的普通焦点序列；分支和环境列表采用单选列表语义，选中状态可读，不只显示勾。
- 键盘可打开、切换、选择、返回、关闭；关闭回到原触发器。进入设置再返回时保留同项目草稿；不存在的旧触发器不能抢焦点。
- 平台标签具备 tab / tabpanel 关系与键盘切换；输入关联标签、说明与错误。折叠区暴露 expanded / controls，隐藏内容退出焦点序列。
- 状态摘要使用适度的 live region；原始日志不逐字播报。失败与未知在详情收起时仍可发现。后台任务不能因增量抢当前窗口焦点。
- 窄窗优先保住名称、当前值、尾部动作及返回；必要时设置行上下排列，不缩小字体。日志、代码与详情路径可读全，页面无横向溢出。
- 沿原动效与 reduced motion；静态截图不提供新时长。减少动态效果时保留状态文本与静态图标，不以停止旋转表示执行结束。

## 固定样例与后续验收

页面合同拆为[配置选择](surfaces/worktree-picker.json)、[准备过程](surfaces/worktree-preparation.json)、[设置管理](surfaces/worktree-settings.json)。它们引用已有模式及控件，分别登记代表截图的对照状态与未覆盖范围；不把部分截图提升为所有状态通过。

| 题目 | 固定输入 / 操作 | 视觉与交互通过条件 |
| --- | --- | --- |
| 菜单关闭 / 开启 | 一个 Git 项目，长项目名，开关两态 | 上下文条与齿轮位置稳定；三行结构，值右对齐；无纵向表单或常驻长说明 |
| 分支搜索 | 当前分支、远端分支、30 个本地分支、长名称、dirty 来源、无匹配 | 同一锚点子页；搜索 / 返回不滚走；单选可辨；dirty 不伪装成可复制来源 |
| 环境配置往返 | 无环境 → 配置 → 新建两个环境 → 保存返回选择 | 项目归属不丢；Prompt / 附件 / 分支保留；不会自动创建或发送 |
| 创建详情 | Prompt 提交，分阶段投影，展开日志，再追加输出 | Prompt 只一份；阶段真实；控制同排；人工展开保留；日志有界且可复制 |
| 已创建 / Setup / ready | checkout 已确认，随后 Setup 仍运行，再就绪 | 已创建不等于可发送；最终收敛成一行，普通 Composer 与工作区标识可见 |
| 取消与异常 | 取消中、确认取消、明确失败、UNKNOWN；分别尝试不用 Worktree | 状态与合法动作逐项准确；不提前报终止或静默回退；收起仍可发现异常 |
| 侧栏身份 | 普通会话、准备会话、已绑定会话、长标题、未读与运行态 | 标题仍是主内容，无 UUID 第二行；尾部图标不碰撞，可访问名称完整 |
| General 与目录 | 默认根、自定义根、三个项目、长路径、空列表、活动/脏目录拒删 | 单一设置组与紧凑目录；高级项不挤主组；拒删保留行及真实原因 |
| 环境编辑 | Setup macOS、Cleanup Linux、Action Default 各自有未保存文本 | 独立平台切换不串改；编辑为独立页；保存不执行脚本；返回有保护 |
| Action | 零项、三项、长命令、运行/失败/未知 | 空态安静，列表可识别；设置只配置；会话入口沿真实状态显示结果 |
| 边界组合 | 明暗主题，UI 字号 14 / 18，宽 / 窄，键盘与 reduced motion | 不靠缩字体通过；当前值、返回、取消、保存和删除均可达；无页面横向溢出 |

逐状态对照 WT-R01～09 时保留 AReaL 品牌与安全语义差异；截图缺失状态按本稿目标验证并明确标注。当前 [renderer 与 Electron 验收范围](exercises/worktrees.md)分别报告视觉、交互和真实 Core 路径；尚未验收安装包、物理输入或 Linux 实机，不声明逐像素一致。

## UI包采用

WorktreePicker、WorktreeStatus、WorktreeDirectory、WorktreeSettings、WorktreeWorkspace从私有@areal/ui/wip消费，样式入口为worktree.css，各自有同目录MD及独立可操作实例。原WorktreeStarter、WorktreeStatus/Actions与WorktreesSettings仍拥有选项读取、事件投影、草稿、版本校验、确认及实际执行。包内不请求服务、不保存配置、不自动重放未知请求。

操作失败/成功通知采用统一NotificationToast；提示自动消失不清除原记录或目录详情中的受阻原因。
