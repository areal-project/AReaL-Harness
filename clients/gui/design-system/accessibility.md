# 无障碍验收

`R-ACCESSIBILITY-001` 默认主题的 serious、critical 问题、默认对比度矩阵失败和新增 moderate 问题阻断 `test:design`。自定义主题的矩阵输出作为诊断。矩阵使用 Chrome 对实际 `paletteVariables` 与 CSS 混色求值，并将透明色叠在明确记录的背景上；纯数值对比度计算不依赖浏览器。这样保留生产 CSS 的插值和透明度语义，不用另一套调色公式替代生产结果。

## 默认主题修订

`R-ACCESSIBILITY-002` Base 0.4.1 提高了最弱元信息、已结算状态和浅色次要文字的可读性。警告橙色按钮使用黑色文字。审批快捷键使用次要文字角色。旧 `theme-baseline.json` 继续作为 Base 0.4.0 快照，只有 `theme-accessibility-revision.json` 列明的四个角色按精确输入和输出更新；其他角色必须与旧快照一致。D3 的颜色等价证据保留，本修订属于 D4 的显式行为改变。

`R-ACCESSIBILITY-003` 主题设置仅在用户选择的前景与背景低于 4.5:1 时提示，保留用户颜色。这个提示只测量正文前背景，不声称所有派生表面都可读。默认主题门禁覆盖已登记的文字与控件表面对，第三方生成页面不在范围内。

## 键盘与动效

`R-ACCESSIBILITY-004` 生产组件的键盘路径在设计 smoke 和 Electron 交互 smoke 中核对。输入与发送、审批、提问、Esc 归属和设置页按真实组件执行。不要把程序调用 `click()` 作为键盘验证。减少动效时全部 `motion-*` Token 归零；系统偏好生效，除非宿主的 `data-reduced-motion` 另有设置。

## VoiceOver 抽查

`R-ACCESSIBILITY-005` 每个发布周期在真实应用中记录以下人工结果，不从 axe 结果推断。

- 发送。输入名称、编辑内容和发送后状态可理解。
- 审批。请求正文、批准与拒绝可定位，结果更新会被正确朗读。
- 停止。当前 Turn 的停止入口可达，停止受理与后台终止能区分。
- 设置。分组标题、控件值、校验信息和返回焦点符合阅读顺序。

`R-ACCESSIBILITY-006` 记录源码提交、macOS 与 VoiceOver 版本、旅程和结果。尚未人工抽查时明确写未验证。
