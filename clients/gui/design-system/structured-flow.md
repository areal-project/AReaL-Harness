# 结构化数据到高保真实现

## 页面合同字段

| 字段 | 决定什么 | 校验边界 |
| --- | --- | --- |
| schemaVersion / id | 合同版本和稳定身份 | v1、唯一 ID |
| `R-FLOW-005` pattern | 页面组合模式 | 必须在 registry 中 |
| `R-FLOW-007` reference | 已有生产参考，或选定 screenshot / figma 视觉目标 | 代码路径存在；视觉引用必须明确，不能用 nearby option 替代 |
| slots | 页面各槽位所用组件 ID | 模式槽位完整、ID 已登记；不是 JSX 执行器 |
| `R-FLOW-009` states | 每个状态的到达条件及可观察结果 | 模式必需状态不能缺；实际交互由独立验收确认 |
| conditions | 主题、字号、宽窄与 reduced-motion | 声明本次适用条件，不意味着跑过所有组合 |
| invariants | 跨状态保持的约束 | 非空，语义由评审核对 |

`R-FLOW-011` 模式的`ruleSource`与`rules`在registry中成对登记；文档用单个`规则ID`后接中文冒号定义正文。页面合同完整引用ID，不复制规则文字。states可以是多条独立状态轴的验收检查点，不能据此新增Core枚举或全局状态机。

`R-FLOW-012` 所有路径相对 `clients/gui/`，截图等本地材料的路径仅放本地证据副本；公开合同保留稳定来源、采纳结论与缺口。当前样例明确标记 pending，不能作为 Codex 对齐或 AReaL 运行通过证明。

## 执行顺序与每步完成条件

| 步骤 | Agent执行 | 本步完成条件 |
| --- | --- | --- |
| `R-FLOW-015` 3. 视频提名候选 | 按[视频分析提示词](templates/video-analysis.prompt.md)，向已授权的视频工具提供限定材料和[输出schema](templates/video-analysis.schema.json)。分析者输出可见事件、候选差异与建议复核时间段，保留请求、原始结果、实际模型/采样限制。 | 原始输出可读取，候选ID唯一、媒体引用存在、时间范围合法且有不确定性；视频未成功读取时明确标记，不能从brief补造事件。 |
| 5. 筛选并定位所有者 | 在既有 run 报告中裁决；缺少载体时复制[核查模板](templates/evidence-review.template.json)。 | 按[差异筛选准入](governance.md#差异筛选准入)裁决。没有成立缺口时，记录无需修改并结束该问题。 |
| 6. 实现最小切片 | 沿既有Token/组件/组合修复确认差异，页面只填内容与合法动作。新公共状态进入原生产预览；验收标记留在DOM或实验控制台，产品消息只呈现用户任务所需内容。 | 改动可映射到采纳项与原所有者；没有并行组件、数值副本或由fixture步骤推导的新业务状态机。 |
| 7. 重放与比较 | 在最终源码/构建上重放受影响的全部状态，按原关闭条件检验行为、数据结果与画面。使用真实操作和可观察到达条件。 | [按改动选择检查](governance.md#按改动选择检查)及[完成条件](governance.md#完成条件)规定代表条件、证据和未覆盖项；原失败方式已有对应证据。 |
| 8. 更新与交付 | 将通过验证的设计决定写回唯一规则位置；按需更新 surface、inventory及registry，后者有变化时同步派生物。 | 按[完成条件](governance.md#完成条件)审阅与交付；Base 版本和视觉基线按[Base 准入](base.md#使用与变更)处理。 |

### 按任务裁剪

- 动态、异步、多面板、滚动、完成收敛或恢复路径：执行相关完整旅程，按[动态关联证据](governance.md#动态信息流的关联证据)关联事件、阅读与录像；终态截图不足以关闭动态问题。
- `R-FLOW-021` 新页面：先用已有模式和Base组件做最小完整任务，再按同样条件取证；新增布局或状态需要明确问题与准入，不能把独立生成的新页面当成已批准设计系统。
- `R-FLOW-022` 视频模型不可用、未获当前素材的外发授权或采样覆盖不足：标记`unavailable`或待补证据，使用已授权的原图、实际交互及日志继续核查。素材选择、普通模型认证和参考实例保留遵从任务授权；工具名、模型版本或High强度均不是正确性证据。

核查模板初始为pending/needs-evidence；在既有报告中使用相同字段即可。证据引用填原manifest中的runId、frame/event ID和哈希定位，已有身份/版本/条件继续归原manifest。`comparison.state`用matched/mismatch/unknown描述状态是否可比，`basis.kind`用reference/rule/product-choice/unknown标明依据；最终裁决与实现验证状态分别维护。只有实际通过的规范变更才加入`normUpdates`并列规则ID、唯一文件、理由及验证引用；具体裁决语义见[差异准入](governance.md#差异筛选准入)。

`R-FLOW-024` 已有runner和报告可保留自己的字段；能覆盖上述完成条件时只补缺项，不另建一套账本。模型供应商封装的JSON/NDJSON保留原件，提取其中的结构化结果另存，不能覆盖原始答复。

## 截图取证方案

先把参考和实现分别登记为 run；引用原图及 SHA-256，记录应用版本/源码、dirty 状态、viewport/DPR、主题、字号/字体、内容与交互状态。每帧绑定合同 ID、状态 ID、进入动作和可见完成条件。

`R-FLOW-025` 优先采集公共控件的代表状态：设置组默认、二值选择、菜单打开、disabled、busy、失败与待确认；随后是对话过程/最终回答、长文本与决策卡片。不同主题、字号与宽窄用代表组合覆盖，不能凭一张总览声称全矩阵通过。Codex 参考只观察展示，不推断其执行协议。

`R-FLOW-028` 动态信息流按[动态关联证据](governance.md#动态信息流的关联证据)追加事件、阅读锚点及录像关联。任务合同同时写出运行条件和读者动作，例如“正文继续增长时向上回看”，不能只列一个busy截图。真实模型用于观察参考；实现复验可用固定输入事件序列控制外部到达顺序，但必须通过生产组件处理，不直接注入预期的展开或跟随结果。

## 交互分类输入

`R-FLOW-029` 先按[用户交互模式](interactions.md)写[设计时简报](templates/interaction-brief.json)：主要交互族、支持路径、must/default 规则、生产组件、例外及可观察结果。随后执行本文件既有 B 流程。视频用于提名变化；静态设置复用有效参考和同态图，不为分类齐全而录制无用视频。新分类的目录合法性、行为、视觉和平台覆盖分别报告。
