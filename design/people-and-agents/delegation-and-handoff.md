# 委派与交接

AReaL Harness 的委派让 Agent 承担可分离的工作。用户仍需看清谁负责结果，以及何时能继续操作共享资源。

## 委派是有职责的选择

`R-DELEGATION-002` 子 Agent 使用独立上下文和历史，权限继承或收窄。职责说明决定它负责什么，不能代替权限授权。父子身份的展示归 [身份与所有权](identity-and-ownership.md)。

## 报告、检查与交付

`R-DELEGATION-004` 阶段报告说明进展和剩余工作，不结束子任务。最终回复也不能单独证明检查通过或修改已交付。

## 停止后的交接条件

补充指令用于协作，不承担紧急取消的含义。停止请求表达停止意图，文件接管要等实际资源释放和持久结算。

`R-DELEGATION-007` 短暂等待超时、文件没有变化或一段旧交接文字，都不能单独证明子任务已经停止。结果未知时沿用 [控制与审批](control-and-approval.md) 的核对语义。

`R-DELEGATION-008` 普通子执行受父 Turn 管理，TaskRun worker 可以跨协调 Turn 存活。父会话一轮结束不能统一解释为全部后台工作已结束。

定时任务的暂停只阻止后续触发，停止当前 Run 是另一个操作。界面允许暂停计划与当前执行仍在收尾同时成立，最终结算依据 Run 和 worker 的状态。
