# 设计规格包

只拿这个目录，就能从零复现 AReaL 桌面工作台的界面与交互，并知道自己做对没有。为什么这样组织见 [D-005](../decisions/005-reproducible-spec.md)。

## 读法

1. 先看 `screens/`：有哪些界面，每个界面分哪些区域、放哪些组件。
2. 再看 `components/`：每个组件的结构、变体、状态、用到哪些用途变量。
3. 交互看 `flows/`：状态、事件、结果。

## 目录

| 路径 | 内容 | 格式 |
| --- | --- | --- |
| `components/*.yaml` | 组件：结构、变体、尺寸、状态、绑定的用途变量、键盘与读屏要求 | YAML |
| `screens/*.yaml` | 界面：区域、组件树、使用的示例数据、窄窗变化 | YAML |
| `flows/*.yaml` | 流程：状态 × 事件 → 新状态、应看到什么、动效角色 | YAML |
| `fixtures/*.json` | 示例数据：界面不连后台也能渲染各个状态 | JSON |
| `icons/*.svg` | 按名称引用的图标，按文件宽高渲染，取 currentColor | SVG |
| `references/` | 标准截图，按界面、状态、亮暗生成 | PNG，生成产物 |
| `conformance/` | 验收：只用角色、可读名称和文字操作与断言，任何实现都能运行；另含截图对比 | Playwright 脚本 |

实现提供入口页，接受 `?state=<流程状态>&theme=light|dark` 并用示例数据渲染（本仓库：设计系统页加 `?spec`）。运行 `conformance/run.mjs --url <入口>` 和 `conformance/references.mjs --url <入口>`。

Token 源：`clients/gui/packages/ui/tokens.json`。

## 四条规则

1. **数值只在 Token 源。** 规格文件只写用途变量名，不写 px、颜色值或毫秒。
2. **不写实现名词。** 不出现组件库、文件路径、编辑器、后台服务的名称。本仓库怎样接线写在代码旁边。
3. <!-- rule:R-SPEC-001 -->**本仓库实现也要通过验收。** 截图对比和行为验收任一不过，修代码或修规格，不能两边各说各的。
4. **参考有据可查。** 声称对齐外部产品的用途变量，在 Token 源记录对方变量名和值；规格正文不转述。

## Token 三层

| 层 | 作用 | 谁能引用 |
| --- | --- | --- |
| 原料 | 有限刻度，不带含义：圆角九档、阴影四档、模糊三档、文字灰阶 | 只有生成器 |
| 用途 | 说明用在哪，指向一档原料：`radius-composer`、`color-foreground-subtle`、`shadow-composer` | 组件 |
| 组件 | 组件内部变量，只引用用途层 | 组件自身 |

全局旋钮（主题底色、前景、强调色、对比度、内部圆角倍率）只改原料层。文字分四级：主要、次要、第三级、禁用；生成器按主题算出颜色后，把未达下限的推深直到达标（主要、次要、第三级 4.5:1，禁用不设下限）。

材质四种，每个表面选一种：

| 材质 | 用于 | 模糊 |
| --- | --- | --- |
| 平面 <!-- rule:R-SPEC-002 --> | 正文区、列表行、回合标题 | 不允许 |
| 抬起 <!-- rule:R-SPEC-003 --> | 输入框、卡片、代码块 | 不允许，用阴影表达高度 |
| 浮层 | 菜单、弹窗、提示 | 可选；减少透明度时改实色 |
| 窗口栏 | 顶栏 | 可选；减少透明度时改实色 |

## 检查

| 检查 | 失败条件 |
| --- | --- |
| 分层引用 | 组件或页面样式引用原料层变量；组件库中出现 `var(--x, 回退值)` |
| 材质 | `backdrop-filter` 出现在材质定义之外 |
| 外观走变体 | 页面样式选择器作用于组件类名并写外观属性 |
| 规格纯净 | 规格文件出现裸数值或禁用的实现名词 |
| 文字下限 | 标准主题与极端主题下任一文字级别低于下限 |
| 截图对比 | 标准截图与当前渲染不一致且 PR 未更新基线 |

存量写入基线，只减不增。

## 交接演练

只把本目录交给新 Agent 复现一个模块，跑 `conformance/` 并对比 `references/`；未过项追溯到规格缺口并修规格，记录首轮通过率（截图加 `--threshold 0.01`）。
