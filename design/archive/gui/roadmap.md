# Codex 参考到 Electron 真实旅程的推进计划

[English](roadmap.en.md)。本页拥有后续覆盖与验收顺序，不替代[结构化 B 流程](../../../clients/gui/design-system/structured-flow.md)或现有组件规则。以下按阶段维护：E1已完成选定旅程的真实Electron专项，E2已完成选定连续切片，E3已完成指定窗口/焦点/原生组合输入与新内容切片，独立候选窗口和其余宿主矩阵仍待验收；阶段通过不自动提升Base。

## 可达目标与当前证据

目标是让选定的 AReaL 桌面用户旅程，在信息层级、操作反馈、阅读连续性和桌面交互上符合已观察的 Codex 参考。逐条证明旅程，不承诺整个产品功能或所有平台与 Codex 等同。

B 流程已经提供视频候选 → 关键帧/事件核查 → 差异裁决 → 原所有者实现 → 重放 → 规范更新的方法。要达到 Electron 目标，必须把实际应用作为验收对象；继续扩大浏览器模拟题不能代替这一步。

| 范围 | 当前可确认的覆盖 | 尚不能推出的结论 |
| --- | --- | --- |
| 设置与决策 | 有公共组件、代表状态预览与探索题；Base 已准入 P-SETTINGS / P-DECISION | 所有设置页已迁移、任意新题都能复用、真实桌面全状态通过 |
| 对话信息流 | 共享生产组件承载逐步投影题；B 实验报告覆盖命令、父子独立状态、图片、阅读锚点与完成收敛 | 浏览器fixture不连接Core；另有E1真实命令/子代理、暂停UNKNOWN核查及GUI历史恢复，完整P-CONVERSATION仍未准入 |
| 动效 | 原 smoke 加 E2 真实 Electron 原帧/RAF 验证命令展开反向、资源进退、分片阅读、等待与暂停；指定缺陷已修复 | 全部动效与 Codex 一致、显示器无丢帧、全部内容/条件通过 |
| Electron 宿主 | 已有隔离 Electron/Core 验证入口，可复用 | E1/E3仅覆盖指定旅程及窗口/焦点/组合输入切片；E4另验同应用窗口往返与原生网页切片；独立候选浮窗、跨应用/显示器、原生文件视图及安装包仍未验收 |
| 防止 Agent 漂移 | 目录、规则引用、部分 CSS 与派生一致性检查已接入 | 全部 JSX 遵守组合、视觉正确，或每个 Agent 已自动执行 B 流程 |

设置页的主要变量是稳定控件的组合。对话还叠加异步到达、父子任务独立生命周期、流式内容增长、人工展开和阅读位置；Electron 又增加窗口、输入法、快捷键和原生视图。后续设计必须同时固定事件、读者动作与宿主状态，不能仅增加终态截图。

## 顺序与完成条件

### E1：真实 Electron 的完整对话切片

当前状态：选定macOS暗色旅程已通过，包含真实命令/子代理、图片缩放返回、阅读/收敛、暂停UNKNOWN核查及GUI重开。入口、证据字段和限制见[真实Electron专项](exercises/conversation-flow.md#真实-electron-专项-e1)。暂停中的工具UNKNOWN仍保留；该结果不表示所有停止都会得到已确认终态。

优先复用 [migration-smoke](../../../clients/gui/scripts/migration-smoke.mjs) 的隔离 home、workspace、真实 Core 与源码/二进制身份记录。它是现有验收入口，不表示当前设计 worktree 已通过本阶段；先核对该入口实际覆盖，再只补本旅程需要的断言与证据。

固定一条主旅程：发送 → 命令执行并连续输出 → 子代理并行 → 图片打开/缩放/关闭 → 输出增长中回看历史 → 回到最新并继续跟随 → 父子分别完成 → 过程收敛并可重访。另用短变体验证停止以及一条恢复/失败路径；不把互斥结果拼成同一条成功录像。

- 以 React → 窄 IPC → Core/Runtime 的现有权威链路运行。确定性本地模型控制事件顺序；命令和子任务如使用真实执行，需有执行身份与结果证据。模型、工具、文件选择器等任何 stub 分别标明，不能写成真实供应商或原生路径通过。
- 将运行事件、人工动作、阅读锚点和录像关联到同一 run。以可见条件到达状态；fixture 播放间隔不能作为真实执行耗时或 Codex 节奏。
- 完成证据须绑定最终源码、dirty diff、构建/Core 身份与隔离环境；覆盖父子身份稳定、历史阅读不被抢走、资源关闭回到原位置/焦点、最终回答与过程可独立阅读。失败和跳过不折算为通过。
- 只修复同状态核查成立的差异；沿 Messages、TurnProgress、CommandDetails、AgentConversationPane、MessageAttachment 与原阅读/执行所有者修改，避免再造展示系统或业务状态机。

### E2：围绕已通过旅程补连续动效

当前状态：macOS 暗色指定连续切片已验证，修复外层隐藏滚动、展开高度跳切和 reduced-motion 侧栏等待图标漏项；范围、参考差异和采样限制见[E2专项](exercises/conversation-flow.md#真实-electron-连续动效专项-e2)。完整动效一致性与E3不因此通过。

从 E1 中选取会影响理解的短片段：流式追加与等待、工具展开收起、子对话进入退出、图片查看返回、回到最新和完成收敛。保留现有动效 smoke；追加真实 Electron 的连续证据，不能只靠指定相位断言。

- 每个片段记录触发前、变化中、稳定后的画面，以及重复触发、反向操作/中断和 reduced-motion 的预期结果；读者焦点和阅读位置也属于验收。
- 采集时保留动画，从触发前录到稳定后。参考和实现分别记录帧时间、有效采样率、丢帧/采样空隙及时间对齐误差；必要时结合可用的动画/性能观测，区分录制掉帧、模型到达间隔与 UI 动效。
- 视频模型用于提名片段与事件。B 实验的分析自报约 1 fps，可能错过完整的 100–240 ms 过渡，不能作为时长、缓动或流畅度裁判；回到原视频、密集关键帧及可核对的时间证据。
- 当前 CSS 的 100/160/240 ms 是本产品值，尚不是测得的 Codex 规范。先说明动效目的与可见问题，再决定是否调整；不能照抄 fixture 的 1400/3200 ms 播放间隔。

### E3：桌面宿主、回归与准入

当前已完成本次 macOS 暗色有界切片：真实窗口三档尺寸与125%缩放、子代理/设置焦点返回、多行草稿、豆包拼音组合输入和编辑 Escape、新图书内容。修复与边界见[E3专项](exercises/conversation-flow.md#真实-electron-宿主与新内容专项-e3)。E4补充同应用窗口往返与原生网页交互/返回，并修复预览返回焦点；见[E4](exercises/conversation-flow.md#原生宿主补充-e4)。独立候选浮窗未触发，跨应用/显示器、原生文件视图、全条件组合及安装包仍未覆盖；不自动提升Base。

在同一会话中验证与旅程有关的窗口缩放、面板开关/焦点返回、中文输入法与快捷键边界、切换窗口后的阅读保持，以及实际涉及的原生文件/浏览器预览。原生视图独立取证；选择器注入和 renderer 截图不能证明原生路径。

对已通过切片固定代表条件：明暗、宽窄、字号、键盘与 reduced-motion。选择一条未用于调参的新内容旅程，检查同一 Base/组合是否仍适用；按[治理准入](../../../clients/gui/design-system/governance.md)更新规则、surface 与目录，再决定是否扩展 Base 或视觉基线。安装包与其他操作系统分别验收。

## 交付与停止条件

每阶段只关闭本阶段有证据的问题：给出参考/实现相同状态、采纳与拒绝理由、原所有者改动、最终运行证据和剩余缺口。已有 runner 与 manifest 能承载时只补缺项；不要新建通用采集平台。

先完成 E1，再据其已确认的缺口执行 E2，最后执行 E3。没有成立差异就记录无需修改；阶段验收通过后停止，不以“完全像 Codex”为无界任务。本计划不会自动恢复已暂停的心跳或启动参考实例；保留当前参考应用及其 CDP 会话。后续执行沿既有 Goal 的待办推进。
