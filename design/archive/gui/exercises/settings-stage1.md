# 设置页第一阶段：交互分类迁移

目标：验证按用户交互归纳的规范能否指导既有生产页面，减少临时样式和组合决策。不是逐像素复制 Codex，也不是整个设置中心、全平台或冻结 Base 的验收。English: [stage one](settings-stage1.en.md)。

## 设计输入

主要交互族为 I-MANAGE、I-DECIDE、I-READ；导航、输入、返回和恢复沿现有支持路径。具体简报见 [interaction-brief.json](../../../../clients/gui/design-system/templates/interaction-brief.json)。

- 必须：使用原偏好与 Core 保存所有者；读取真实当前值；保留输入、选中值和合理焦点；编辑非当前配色不切换应用主题。
- 默认：按目的分组，常用界面和减少动态效果直接可见；专门阅读和配色微调使用 SettingsDisclosure。
- 产品选择：界面、交互与动效、阅读与代码、配色微调四组；后两组默认折叠，保留全部原设置能力及两套配色编辑。该范围的分组效果已获用户认可，不宣称由参考截图直接推出。
- 允许变化：后续任务的字段、领域内容、必要组合；不得以此新增数值副本或页面 DSL。

## 生产所有者

外观内容归 DisplaySettings.tsx；布局和展开样式归 SettingsWorkspace.css、SettingsDisclosure；主题、字体和配色归现有 applicationPreferences / applicationSettings / code preferences；通知保存仍通过原 action → Electron → Core。原设置导航、未保存修改守卫及 App 返回机制保持所有权。

常规页作为共享控件和 Core 保存回归；本阶段实质重构集中在外观页。模型、插件、移动连接等其他设置内容没有因本次分类自动完成迁移。

## 验证合同

从仓库根构建后，使用已核对的固定 Core 产物：

```sh
make gui-build
AREAL_CORE_BIN=/absolute/verified/areal node clients/gui/scripts/migration-smoke.mjs --settings-stage1
```

脚本沿已有隔离 migration runner 启动源码 Electron 与真实 Core。项目选择器注入合成工作区；本地模型端点未被调用，不使用真实账号或日常配置。`AREAL_SETTINGS_BASELINE=1` 只用于采集保留的旧版生产构建，不能替代新版验收。

| 场景 | 可观察结果 |
| --- | --- |
| 外观默认 | 主题、界面字体/字号、动效偏好可发现；专门细节默认折叠 |
| 阅读展开 | 键盘 Enter 可展开，控件可操作；同一共享展开语义 |
| 配色微调 | 无效颜色草稿明确标记；切换两套配色不丢值、不切换应用主题 |
| 菜单选择 | 当前值更新，菜单关闭后焦点返回触发控件 |
| 窄窗大字号 | 实际 Electron contentSize 1000×720、字号18；无主区横向溢出，控件可滚动到达 |
| 常规通知 | 实际 Core 持久化通知值，Electron 关闭重开后仍保留 |
| 搜索与返回 | 无匹配状态可清除；返回保留先前通过编辑器输入的草稿，无模型请求 |
| 浅色与重开 | 浅色、字号和减少动态效果偏好按实际值恢复 |

每个独立运行保留 PNG、ARIA、事件、host 身份、视频、代码/产物哈希和清理结果。旧新版对照匹配窗口、主题、字号与语义任务；布局和展开默认值是干预本身，不能要求相同 scrollTop，也不把不同运行拼成连续录像。CSS 内容尺寸与 PNG 像素尺寸分别记录。

## 审查与边界

规则/目录检查、交互正确、视觉效果和平台行为分别评判。对照重点是常用项发现、分组可理解性、细节可达性和窄窗可读性，不用断言数量代替审美判断。本次不新增全局颜色、字体或动效参数。

首个试点由同一实现会话完成，不能称为独立泛化。保存失败/UNKNOWN 全矩阵、真实通知送达、原生候选浮窗、跨应用窗口切换、安装包和其他 OS 均不在本次通过范围。Base 0.1.3 准入不扩大。用户已批准以生产对话作为第二阶段，见[对话阶段二](conversation-stage2.md)；不自动扩展其他迁移。
