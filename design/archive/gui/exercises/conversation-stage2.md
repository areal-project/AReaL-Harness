# 对话第二阶段：交互分类迁移

English: [stage two](conversation-stage2.en.md)。设置第一阶段已获用户认可；本阶段把分类用于真实生产对话，而非重新制作模拟页面。主要交互族为 I-INPUT、I-OBSERVE、I-RETURN，I-READ 支持历史阅读和收敛；[页面合同](../../../../clients/gui/design-system/surfaces/conversation-stage2.json)引用既有 P-CONVERSATION 规则。

## 设计裁决与所有者

| 交互 | 本阶段默认表现 | 必须保持的事实与所有者 |
| --- | --- | --- |
| 输入与发送 | 原 Composer 的草稿、发送与执行反馈 | ConversationComposer / App 提交给 Core；受理和完成分开，不新增消息或执行 store |
| 执行与阅读 | 完成组明确显示“执行过程”和展开/收起；命令卡标题显示文字状态 | TurnProgress 保留人工展开选择；CommandDetails 读取原执行投影，同一 processId 的输出继续累加，工具返回成功不推断进程已退出 |
| 子代理 | 入口显示子代理、原始委派任务和查看动作；面板与标签使用同一任务名，缺少任务名时沿原身份回退 | ToolEvent / AgentConversationPane / App；父命令、子线程、父 final 独立，不用工具创建回执代替子任务完成 |
| 打开与返回 | 继续使用原图片查看器与子对话面板 | App 保留父 Messages 挂载，返回恢复合理焦点与未发送草稿；阅读和关闭不重新提交执行 |

命令状态前置、明确的展开文字是本产品的 I-OBSERVE/I-READ 默认选择。历史 Codex 26.1013.31256 的子任务标题、独立子对话和完成组提供参考；本次未重新采集当前 Codex，也不宣称上述位置和文字逐像素照搬。颜色、字体、密度、窗口比例及动效参数没有全面重新校准。

## 可重复验证

```sh
make gui-build
AREAL_CORE_BIN=/absolute/verified/areal node clients/gui/scripts/migration-smoke.mjs --conversation-stage2
```

旧版需先冻结原生产 renderer 构建；`AREAL_CONVERSATION_BASELINE=1` 只关闭新版特定呈现断言，不能替代新版验收。两侧采用同一 UI 操作、本地确定性 HTTP/SSE 模型、真实 Rust Core/Runtime 和隔离配置。模型内容为既有 E1 合成水果任务，不是新盲测或真实供应商验收；命令、输出读取和子线程确实执行，不向 renderer 注入期望状态。

1. 发送历史，再输入并发送复合消息；分别记录未发送和 Core 已受理、模型尚未返回状态。
2. 启动一个真实分批输出命令和一个 Core 子代理；打开同一命令详情、图片和子对话，记录命令先结束、子任务后结束、父 final 最后完成。
3. 在父 Composer 留未发送草稿，关闭子面板；核对父 DOM 身份、草稿和触发焦点，分别记录返回前后阅读位置。内容增长时不以绝对 y 相等代替上下文连续性。
4. 回看固定历史段落，正文继续两批增长；返回最新并观察实际到达及后续两批跟随。正常完成后检查过程收敛，再打开原过程和同一子线程并返回；不新增模型请求或重放命令。

每侧保留十八个语义检查点、PNG/ARIA、事件、完整状态、模型请求、原始录像、host/源码/二进制身份和清理结果。对照匹配任务、深色、默认字号14、CSS内容1509×949、DPR2；计时、生成ID和独立进程身份允许不同。两次运行不拼成一条录像，不把相同文件名当成相同状态的唯一证据。

## 执行结果与边界

旧新版均通过上述真实 Electron 场景；Core 二进制哈希前后不变，独立进程按 runner 正常清理。首次基线错误选中自动创建的项目，修正为按准确工作区绑定后通过；失败记录保留，未改生产逻辑掩盖它。原件与同状态对照仅保存在本地，不迁入公共源码。

这验证了分类对第二种生产交互组合的适用性，仍由同一会话实施，不能称独立泛化或完整 Codex 复刻。失败/UNKNOWN 全矩阵、新的连续动效测量、窄窗/浅色/字号18、真实供应商、原生输入法、安装包和其他 OS 不由本次运行证明。已有预览与先前桌面证据只按原范围使用。视觉取舍等待用户审查，Base 0.1.3 仍未冻结；不自动启动第三阶段。
