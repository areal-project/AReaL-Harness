# 完整工作台候选

本候选将提交任务、阅读过程、处理审批、查看资源和修改外观串成一条连续路径，供评价 AReaL Harness 的整体体验。它使用生产组件与本地演示数据，不连接服务、不执行命令，也不写入项目文件。

## 打开与体验

从仓库根运行 `pnpm --dir clients/gui design:dev`，打开 `/design-system.html?product-candidate`。现有设计预览也提供候选入口。

输入一项要求或采用示例要求，发送后观察过程。审批前没有新的交付物，可以展开“查看拟写内容”核对完整正文。允许一次后继续展示过程，再产生示例资源与最终回答；拒绝后保留已发生的过程并结束该次演示。

打开资源查看内容，再进入设置修改外观。返回时继续查看原资源，关闭资源后回到同一聊天。等待期间可以编辑下一条草稿，资源与设置的切换不提交或清空它。

“本地演示”入口集中提供异常场景与重新开始。明确失败和结果未知分别表达。未知状态保留原任务身份，不自动重发操作。演示结果的核对只改变本地示例，不代表已经查询真实 Core。

## 整体表达选择

| 范围 | 候选选择 | 设计理由 |
| --- | --- | --- |
| 工作归属 | 稳定导航与当前任务标题 | 用户在过程、资源和设置间移动时仍能识别原工作 |
| 主要内容 | 中央聊天与底部输入 | 提交、过程、决定和结果在同一阅读路径中连续出现 |
| 过程与决定 | 轻量过程入口与生产审批卡 | 需要用户决定的操作直接可见，细节按需展开 |
| 资源 | 宽窗并列查看，窄窗独立查看并明确返回 | 查看内容时保留任务身份，窄窗避免压缩正文与操作 |
| 设置 | 独立工作区域，偏好即时作用于当前候选 | 外观调整可直接比较，返回后继续原工作 |
| 视觉语言 | 既有中性表面、生产字体、图标及控件角色 | 通过信息层级与组合形成整体，不另建一套组件外观 |
| 异常 | 失败、拒绝、未知有各自文字与合法动作 | 不将点击、回执或未知结果改写为完成 |

精确色值、尺寸、形状和动效继续归[基础表达与 Token 所有者](../../foundations/tokens.md)。本候选不冻结新的全局视觉基线。

提交、过程、审批与结果使用生产调色板和组件样式。消息列与输入区共用阅读宽度，发送与审批共用主要动作颜色配对。候选审批仍位于阅读流，生产审批保留输入停靠区；这项位置差异不改变共同的卡片、文字与焦点规则。

## 实现与状态边界

候选入口与组合由 [ProductCandidate](../../../clients/gui/renderer/src/design-system/ProductCandidate.tsx) 维护，复用 Messages、ConversationComposer、ApprovalRequest、工作台布局和设置控件。草稿、路由、外观与模拟执行有明确的本地所有者，不建立 Core 协议模拟服务。

审批提交与执行完成是不同事件。后续结果到达前不生成交付物。重新开始使旧事件失效，资源与设置导航不启动另一轮执行。外观仅在当前候选内生效，不写入生产偏好。

## 评价重点

- 发送后能否判断目前在做什么、是否需要介入，以及已经完成什么。
- 审批的信息是否足够作决定，批准、拒绝与后续结果是否连贯。
- 资源打开与返回是否清楚，未发送内容和阅读位置是否保留。
- 明暗、字号与窄窗下，阅读层级和主要动作是否仍然清晰。
- 失败与结果未知是否容易区分，下一步动作是否符合当前事实。

## 真实 GUI 体验

构建 GUI 后，按 [GUI 体验入口](../../../clients/gui/README.md#composer)启动隔离窗口。输入普通要求，观察真实过程，选择批准或拒绝，再从文件结果打开正文。它使用既有提交、审批和结果控制器及真实 Core/Runtime，本地确定性模型只负责产生可复现的请求。所有文件限于临时项目。

该入口用于评价本次任务切片的颜色、宽度、间距和文字层级。资源与设置的整体组织仍在本地候选中评价，候选的模拟路由和状态没有迁入生产。

外观设置沿生产页面提供另一条真实路径。进入设置修改主题、界面字号或内容字号，直接查看正文样例，再返回原任务。它复用原偏好保存与导航，保留未发送草稿和同进程内的阅读段落。入口与专项命令见上述 GUI 指南；设计含义归[设置与管理](../../patterns/settings.md)。这一局部采用不表示完整候选中的设置组织或资源导航已迁入生产。

## 验证范围

`pnpm --dir clients/gui test:design --product-candidate` 从真实浏览器操作本地候选，检查连续路径、草稿、返回、状态、外观与响应式布局，保存截图和运行记录。构建使用 `pnpm --dir clients/gui design:build`。

这些证据只覆盖所挂载生产组件与本地演示交互。真实任务专项 `--task-slice` 另行检查提交、过程、批准与拒绝、文件副作用及原请求身份，覆盖 1440px 与生产最小宽度 980px、明暗和独立字号。恢复、原生视图、真实供应商与安装包继续沿对应生产路径分别验收。用户对整体视觉与体验的评价决定下一轮收敛，不因测试通过自动扩大 GUI Base 准入。
