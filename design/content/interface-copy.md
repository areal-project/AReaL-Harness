# 界面文案

本页给出 AReaL Harness 的文案建议和评审依据，不声明所有客户端已采用这些措辞。执行事实、审批范围和恢复保证分别以[控制与审批](../people-and-agents/control-and-approval.md)及原服务契约为准。

## 操作名称说明点击后的动作

`R-COPY-001` 按钮用动作命名。对象不明确时补上对象，如“打开文件”“暂停安排”“停止本次执行”。“保存”只用于需要提交的编辑，“返回”只用于导航，“关闭”不暗示后台工作已停止。

当前值留在字段或选中状态中。切换控件不写一次性动作。纯图标操作提供同义的可访问名称，提示文字补充必要范围，不承担唯一名称。

## 反馈先说已知事实

`R-COPY-002` 同一反馈先说明发生了什么，再说明用户可做什么。必要的技术原因与请求标识放在详情中。文案只承诺当前事实支持的结果。

| 事实 | 建议表达 | 使用条件 |
| --- | --- | --- |
| 正在读取 | 正在读取执行记录… | 表达读取，不暗示任务重新启动 |
| `R-COPY-003` 尚无记录 | 尚未运行 | 已确认列表为空，不能用于首次加载或读取失败 |
| 已受理，尚未开始 | 已受理，等待开始 | 已收到受理事实，不写“运行中” |
| `R-COPY-005` 正在执行 | 运行中 | 来自当前对象的执行状态，不从动画或最后回复推测 |
| 已完成 | 已完成 | 所属对象已确认完成。保存成功、轮次完成和 Run 完成各有范围 |
| 已确认失败 | 执行失败。可查看原因。 | 有失败事实，下一步只提供当前合法动作 |
| `R-COPY-007` 已知内容的刷新失败 | 更新失败，显示上次读取的内容。 | 已有可保留内容，不能把旧值说成当前值 |
| `R-COPY-008` 结果未知 | 结果待核对。已保留当前内容。 | 缺少确定回执，不能写成成功、失败或未执行 |
| 没有权限 | 当前身份无权执行此操作。 | 已确认权限原因，避免将所有连接问题归为权限不足 |

`R-COPY-009` 提交中、等待和失败的反馈跟随受影响对象。标题与正文不重复同一句错误。给出可行下一步时使用明确动作，如“重新读取”，不把所有失败都配成“重试”。反馈位置和可用动作继续见[反馈与恢复](../patterns/feedback-and-recovery.md)。

## 审批说明动作与授权范围

`R-COPY-010` 审批标题说明将执行的操作。正文展示目标与最终参数，动作区区分“拒绝”“允许一次”和实际支持的记忆范围。范围名称按后端权限表达，不用更宽泛的措辞承诺授权。

`R-COPY-012` 追问中保留已填写内容。回答结果未确认时可用“回答结果未确认，已填写内容保留。请先核对原问题状态。”。可选问题、必答问题与过期问题按真实能力表达，不由文案补造跳过动作。
