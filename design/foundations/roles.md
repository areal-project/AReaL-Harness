# 基础表达角色

本页维护 AReaL Harness 选择颜色、文字、空间和反馈的用途。数值在哪里改、写样式时用哪个变量，见 [Token 来源与使用](tokens.md)。

## 颜色与内容层级

`R-ROLE-001` 主文字承载当前任务与可操作内容。次文字承载补充说明和元信息，仍需可读。禁用表示当前不可操作，不能为了降低说明文字的强调而借用禁用角色。

`R-ROLE-002` 页面、内容、输入、浮层和边界用各自角色表达关系。一个分组表达一个功能关系，不给每段文字增加独立卡片、重阴影或装饰渐变。选中表示当前选择，强调表示操作优先级，危险表示操作后果。成功、警告、错误与待确认分别传达事实，不能仅凭颜色辨认。

## 文字与空间密度

`R-ROLE-003` 标题帮助定位，正文承载阅读，控件标签说明动作或值，说明文字补充范围。路径、代码和标识使用便于逐字核对的表达。UI 字号与内容字号分别承担操作和阅读职责，不能合并为一个偏好。

`R-ROLE-004` 默认排印采用用户指定的 Codex 参考方向：常规字重、清晰且克制的无衬线文字。任务列表与普通正文不默认加粗，选中态用已有表面反馈表达，字重强调留给标题和确需强调的内容。参考图中的 Codex 侧栏和正文字面较小；截图不能单独证明字体家族、精确 CSS 字号或缩放比例。

界面文字的字号只用 `--text-ui-*` 角色，这样用户调整界面字号时所有界面文字一起缩放；写死的像素字号会让该处不随偏好变化。没有合适角色时先在 tokens.json 增加角色，而不是写新的像素值。

`R-ROLE-006` 对话时间线是阅读密度最高的表面：正文、活动、子代理与过程状态用同一字号、同一行高和同一块间距，层级只由颜色与图标表达，不用更小的字号、卡片或分隔线区分。具体角色与运行中回合的规则见 [CONV-RHYTHM-01](../../clients/gui/design-system/patterns.md#对话信息流)。

同行控件采用一致密度，同组内容用间距说明关系。空间不足时重排，必要信息不靠缩字或裁切隐藏。控件形状与容器形状各有用途：圆角从 `--radius-*` 按表面选择，不逐页追加任意尺寸或圆角。

## 图标、动效与焦点

`R-ROLE-008` 动效解释状态变化和空间连续性。等待动画不证明执行仍在推进，停止动画也不证明后台已经结束。明确动效的起止状态与可中断方式。减少动态效果时保留同样的信息与动作。

`R-ROLE-009` 界面禁止使用左侧三角作为展开 / 折叠入口，包括原生 `details/summary` 的默认三角标记和手写的同类符号。优先使用“查看详情”按钮打开已有详情面板或对话框；确需原地展开时使用明确的“展开 / 收起”文字按钮并保留键盘与 `aria-expanded` / `aria-controls` 语义。不能只隐藏标记而留下无提示、不可访问的交互。下拉选择控件右侧的小箭头不属于此禁用项。

`R-ROLE-010` 评审时必须确认：功能分组合理、控件语义正确、反馈来自真实结果、没有冗长常驻说明或左侧三角、明暗与窄窗口均可用。新公共状态必须进入现有组件预览，不另外建立平行规范。
