# 任务推进与过程阅读

用户提出要求后，需要持续理解当前工作、找到需要介入的决定，并阅读结果。请求、执行与完成的含义见[控制与审批](../people-and-agents/control-and-approval.md)，父子任务关系见[委派与交接](../people-and-agents/delegation-and-handoff.md)。本页拥有信息组织与阅读的共同规则。

## 内容与阅读分开

用户输入、过程、工具证据与最终回答保持可辨认的层级。按所属会话、轮次和原始顺序组织内容，不用正文关键词猜测工具执行，也不为排序外观改写历史。没有对应事实时不补造进度百分比或完成信息。

常规过程可以渐进展开，结果和交付内容保持可读。需用户决定、失败、未知或仍在运行的内容必须可发现。具体状态文案与动作见[反馈与恢复](feedback-and-recovery.md)。

跟随最新与主动回看分别处理。新内容到达时保留读者对旧内容的阅读位置，返回最新使用明确动作。同一内容身份下的人工展开选择不因无关刷新丢失，新轮次不继承其他内容的展开状态。平台拥有实际滚动、焦点、测量和动画机制。

## 平台落实与验证

GUI 的分组、折叠、滚动和工具组合由[对话信息流合同](../../clients/gui/design-system/patterns.md#对话信息流)维护。后续 Web 复用时沿用相同的信息组织，按实际状态接线独立核对浏览器阅读与焦点。

用户标注图推动的[活动与上下文草案](../../clients/gui/design-system/conversation-flow.md)补充 GUI 的有限活动变体、默认折叠与溢出设计，保留规范候选和当前实现的区别。

复验应覆盖新增内容时回看、明确返回、过程结束、人工展开保留，以及所选失败或未决路径。观察结果必须绑定所属内容，不能仅凭最终截图或不变的滚动数值断言整个过程连续。
