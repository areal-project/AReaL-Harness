# 反馈与恢复

先决定用户需要理解的事实，再选择样式、文案和合法动作。本页维护通用状态的展示与动作约束。请求与审批的业务含义见[控制与审批](../people-and-agents/control-and-approval.md)，实际恢复保证由原执行契约决定。

## 状态必须先于样式决定

| 状态 | 展示与动作 |
| --- | --- |
| 首次加载 | 所属区域显示加载状态；无假数据，无可误触操作 |
| 刷新 | 保留已确认内容，局部标识刷新；请求失败时旧值不伪装为新结果 |
| 空 | 说明为何为空；只有存在可用下一步时提供动作 |
| 提交中 | 防重复提交，保留动作标签/草稿；只禁用受影响动作 |
| 成功 | 显示权威回执后的当前值；必要反馈就近出现 |
| 失败 | 明确原因及可行恢复，保留输入；无条件重试不作为默认 |
| 待确认 / UNKNOWN | 与失败、成功分开；核对原请求，不以新身份重放 |
| 不可用 / 无权限 | 显示真实原因与适用入口，不生成虚假开关或无效按钮 |

## 反馈的范围

反馈绑定受影响的任务、字段或资源。局部问题保留其他可用内容，不用全局失败遮住已经确认的结果。反馈同时使用可理解文字，技术详情按需展开。成功、结果刷新和计量结算分别表达，不因后续刷新失败推翻已知结果。

GUI 的实际组件、错误展示和恢复入口见[交互族](../../clients/gui/design-system/interactions.md#i-recover-异常与恢复)。后续 Web 复用相同状态含义，恢复入口按实际浏览器能力和执行契约提供。

## 短时通知

操作提示采用顶部居中的Toast：info、success、warning、error分别使用语义颜色和图标，默认5秒后消失，支持手动关闭；悬停或键盘聚焦暂停剩余计时。实际实现与无障碍合同见[NotificationToast](../../clients/gui/packages/ui/src/components/notification-toast/notification-toast.md)。通知消失只关闭提示，不删除草稿、原始结果、详情或恢复动作；任务状态与可核对事实由原所有者保留。

## 同窗口重载后的阅读连续性

恢复任务时保留未发送草稿，并从权威快照重新附着原执行，不重放提交。对正在阅读历史的用户，当前仍可用的正文段落也是恢复对象。新输出保持在原任务中，只有显式返回最新后才恢复跟随。等待历史补齐不能覆盖用户之后的导航。

同一主窗口的 Renderer 重载与崩溃后显式重载已有真实 GUI 证据，见 [E-RECOVERY](../../clients/gui/design-system/base-evidence.md#e-recovery)。阅读检查点的所有者、存储边界与排除范围见 [Messages 阅读合同](../../clients/gui/renderer/src/Messages.md#同窗口-renderer-恢复阅读)。完整应用重启、未加载历史与过程展开状态不在本次范围内。既有进程内外观切片证据不能替代此项验收。


## 统一短时反馈与待确认状态

操作反馈统一采用顶部短时NotificationToast，包括带核对或设置动作的通知。默认5秒消失，悬停/聚焦暂停；同一requestId在多个展示位置只出现一次。默认只给简短事实和必要动作，不展示请求ID、协议错误或多层“查看详情”卡片。

通知消失不清除UNKNOWN、持久请求或草稿，也不启用重复写入。真实待确认的Composer用小标识提供按需核对入口。恢复依据原请求回执和原Worktree就绪记录，不能因同项目另一条待确认请求阻塞已知成功的会话打开；也不能把无回执当成成功。定时任务新建沿同一原创建身份恢复，原Worktree已ready就打开原会话，不另建任务。
