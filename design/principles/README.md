# 共享设计原则

设计原则说明 AReaL 怎样取舍。它们为具体规则提供理由，规则及其变更由对应主题维护。编号保持稳定，其他文档、组件合同和 PR 说明按编号引用（例如“依据 P5”）。GUI 实现与后续 Web 复用入口见[客户端地图](../README.md#客户端地图)。

## P1 让工作事实可以理解

用户应能判断谁在工作、自己控制什么，以及当前结果凭什么成立。具体的身份、受理、权限与执行关系统一由[人与 Agent](../people-and-agents/README.md)维护，不能由控件外观或模型叙述重新定义。

## P2 保护人的决定与连续工作

设计应帮助用户在足够信息下决定，并在任务推进和深入查看时保留继续工作的路径。[控制与审批](../people-and-agents/control-and-approval.md)拥有承诺与授权语义，[交互模式](../patterns/README.md)拥有操作与阅读组织。

## P3 先定义任务，再选表达方式

先说明用户在 GUI 中要理解和完成的事情，再选择已有控件与组合。后续 Web 复用相同意图时按浏览器能力适配。意图归[模式地图](../patterns/intents.md)，控件选择归[组件目录](../components/README.md)。

## P4 用内容层级服务阅读与操作

重要内容、可行动信息与必要影响应容易发现，专业细节按任务展开。交互卡片采用“摘要优先、详情按需展开”：默认尺寸不随原始命令、长理由或目标文本持续增长，主要操作始终可达；完整原文必须可查，不能因视觉截断而改变执行参数。文字、图标、空间及动效共同表达关系。具体基础规则归[设计基础](../foundations/README.md)，长内容和资源阅读归[深入查看与返回](../patterns/inspect-and-return.md)。

## P5 共享规则只维护一次

一项判断只有一个可编辑的语义来源，平台在其上记录真实适配。接口归实现，数值归明确源，效果归实际验证。共享规则、平台差异和未完成项分别记录，目录整理不代替产品准入。

代码与规则不一致时，其中一个是错的：修改代码或修改规则，不让两者并存。Token 单源、字面量基线和成熟度检查是这条原则的自动化部分，见 [Token 来源与使用](../foundations/tokens.md#自动守卫)。
